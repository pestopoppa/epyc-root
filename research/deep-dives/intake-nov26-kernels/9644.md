# feat(cake_ssd_combined): read and write states in a caller state pool by slot

Merged 4a936721275d5e0d50ff4cc08805669556885a5b, head 0c7d6a553f8179b0cfa9dcb54e13b5d25f8a41fb. All three Cake Mamba2 packed-varlen program families have slot paths. Device-read strided int32 vectors allow captured graph mapping updates, with flag/null/out-of-range rules for zero-initial or skipped writes. Exact same pool view can support initial/final in-place state under caller-enforced unique writes and no cross-sequence read/write overlap. Unsupported overlapping checkpoint views are rejected. Author CUDA-graph microbenchmarks against gather/dense/scatter yield 2.10x B200, 2.10x GB300, 2.68x VR200 geomeans, with a 1.04x minimum on B200/GB300.

## Evidence checked

- The Cake Mamba2 packed-variable-length prefill path reads initial states from a caller-owned pool by per-sequence slot and writes final and checkpoint states back to that pool. (PR Description, first paragraph).
- The reported baseline gathers initial states, zeroes rows without an initial state, invokes the previous dense Cake implementation and scatters the output states back. (PR Description, baseline statement).
- The PR reports its speedup summary over 48 workload shapes modeled on vLLM Nemotron-H Nano and Super tensor-parallel configurations with FP32 state pools. (PR Description, throughput comparison).

## EPYC applicability

## Counterevidence and limits

The PR comparator already stages copies by construction, and long single-sequence cases save much less than 1024 one-token sequence shapes. EPYC already bypasses some snapshots under RS_REPLAY. The official GDN API documents duplicate-slot concurrent-write races, consistent with Cake requiring caller-enforced uniqueness. No external gfx90a or Zen5 measurement of this Cake change surfaced.
