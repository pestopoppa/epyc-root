### The 11 audited evaluation stacks (s12 Table 1, Table 6)
lm-evaluation-harness (template opt-in; logs prompt only with --log_samples), Open LLM Leaderboard v2 (opt-in; gated per-sample logs carry the template fallback 26 Jul 2024, not the run date), HELM (template default; prompt kept as request-cache key), lighteval (default; --save-details or default cache), OpenCompass (default; saves prompt before template), EvalPlus (default unless direct completion; completions only), BigCodeBench (same), AlpacaEval (opt-in; other configs carry no date), Arena-Hard-Auto (server-side by default), OpenAI simple-evals (server-side; writes a fixed stale 2024-04-01 into two of its own persona prompts), Qwen2.5-Math eval (opt-in; drops prompt before saving). None passes a date_string itself; none records the rendered date. Also: 0 of 16 accepted papers (ACL/EMNLP/NAACL/NeurIPS/ICML 2025, ICLR 2026) that run date-inserting models state the date, while 10 state temperature and 13 state the GPU.

### Which chat templates inject a date (s12 App. A, Table 4)
Llama-3.2 (`strftime_now`, "DD Mon YYYY", cutoff line Dec 2023), Llama-3.1 (date_string, fixed 26 Jul 2024 fallback), SmolLM3 ("DD Month YYYY", /system_override drops it), Granite-3.3 ("Month DD, YYYY", default system message only), Mistral-Small-24B-2501 (ISO date, default system message only), gpt-oss-20B (ISO date). Not injecting by default per x02: Qwen3 (but OpenRouter injects it server-side; x02 Fig 5). Server-side injection also seen for GPT-5.1 (x02 §5.2, identical scores across 42 repeat runs at a fixed date).

## In-house comparison

### Stopwatch: does our keep gate already require a mechanism witness and an A/A?
A/A: YES, already required. The keep path times "clean anchor build, guard build, A/A, headline, reprofile" (`handoffs/active/autokernel-loop.md:L4423-L4426`); controls are positive/neutral/negative/A/A, A/A failure voids the window (`autokernel-loop.md:L3068-L3078`, `L2193-L2195`); recent rows state "7 interleaved reps per cell with a same-row A/A" and KEEP_CANDIDATE only if a cell beats its A/A by >= 3% (AK-MMQ-SK2, `autokernel-loop.md:L4574`). Stopwatch's A/A (base vs base) adds nothing we lack.

Mechanism witness: PARTIAL, with a precise gap.
- Design layer has it: `mechanism_prediction.expected_counter_changes` in the hypothesis schema (`autokernel-loop.md:L1605-L1608`), "measure the exact predicted mechanism counters" (`L2204`), T1c selective mechanism receipt where "a failed mechanism prediction withholds the mechanism bonus and normally makes the result inconclusive" (`L2209-L2220`), banking needs "the predicted mechanism or a recorded explanation" (`L2242`), POST_RUN_CRITIC classifies mechanism confirmed/refuted/unavailable (`L2062`). Code layer: the champion banking verdict refuses unless mechanism resolution is confirmed or explained (`/workspace/repos/epyc-inference-research/scripts/kernel_rnd/autokernel/controller/champion.py:L482-L483`, read at repo HEAD c3c5c3f96, unpinned).
- Row layer (what recent GPU rows actually run) does NOT require it. `ak_row_lint.py` has one witness check, `NO-WITNESS` at WARN, and it only asks that a row which names a GGML_/LLAMA_ knob records a `*witness*` key to prove the knob took effect (`scripts/coordination/rowflow/ak_row_lint.py:L39`, `L680-L682`). That is a BUILD or path witness. AK-MMQ-SK2 filed exactly that: "knob-honoured witness ok all arms" and a same-row A/A, with no counter tied to the claimed cause (`autokernel-loop.md:L4577`). `FUTILITY_WITNESS` rules in `L4782-L4794` also mean "the knob never fired". AK-WIN-CNT-1 adds path counters (graph replay vs eager) as a non-gating sidecar, `authority: report_only, gating: false` (`autokernel-loop.md:L4721-L4724`). Only one hypothesis family pre-registered a mechanism counter: AK-QL S1 "SPI counter ratio testing the undocumented 64-VGPR rule" (`L3888`).
- Evidence the gap bites: Q8-W8-GEMV-1 design 4 (`handoffs/active/rocm-kernel-authoring.md:L1159`): int8 MFMA cut static instructions per byte 0.101 to 0.034 yet ran 2-3x slower (w8 0.478x MW2, 0.304x MW4); the coalescing diagnosis (~32-48 partial 64 B lines per wave instruction vs ~17) was reasoned after the fact from static analysis, with no row-level counter (L2/TA request counts) pre-registered. That is Stopwatch's "faster-or-slower but not for the claimed reason" and its "instruction count barely separates" lesson.
- Exact gap: row spec and `ak_row_lint` have no field "claimed mechanism -> named rocprof counter, direction, A/A band", and no lint that makes a KEEP_CANDIDATE rule depend on it. The schema and champion gate are further downstream than the rows that produce keeps.
- Gating subtlety to keep: Stopwatch itself says a held mechanism is consistent with, not proof; use it to void or downgrade (INCONCLUSIVE), per our own T1c wording, never to promote.

### Date: is our eval/judge path date-sensitive today?
Plain answer: NOT for the served roles, to the extent checked; the guard is accidental, not enforced, and results do not record a date.
- llama-server DOES inject the wall-clock date. C21 `common/chat.cpp:L2573-L2581 @ 98ff8a4` builds `datetime` ("%b %d %Y") and `date_string` ("%d %b %Y") from `system_clock::now()` with `localtime`, and `common/jinja/value.cpp:L399-L411` implements `strftime_now` from `std::time(nullptr)`. Same function exists in the frozen tree (`common/chat.cpp:L2543 @ ffc1bac82`). Per-request override: `chat_template_kwargs` are applied AFTER the default (`chat.cpp:L2747-L2750`) and the server reads `body.chat_template_kwargs` (`tools/server/server-common.cpp:L1277-L1280`), so a request or the server-level kwargs can pin `date_string`/`datetime`. `strftime_now` itself cannot be overridden per request (jinja context time), and it is timezone-dependent.
- Our served templates contain no date: pinned served template 1443ea9ab4bb (Qwen3.6-35B-A3B and Qwen3.8-27B roles; `/mnt/raid0/llm/models/chat-templates/sha256/1443ea9ab4bb...jinja`, grep for strftime_now, date_string, datetime, "Current date", "Today Date" = 0 hits); Qwen3.8-Flash-Next embedded GGUF template (parsed `tokenizer.chat_template`, 9,993 chars, 0 hits); `epyc-qwen3x-v1*.jinja` and deepseek-v41 template 0 hits; Gemma-4-31B-it and Gemma-3-1b GGUF templates 0 hits. Not checked: Qwen3-VL-30B and the GLM family templates (GLM log files exist; no GLM GGUF in the models listing I read).
- A Llama-3.2 template on disk DOES inject: `/mnt/raid0/llm/models/Llama-3.2-1B-Instruct-f16.gguf` embedded template has `date_string`, `strftime_now`, "Today Date". It is a draft/utility model, not an eval target as far as I found, but it shows the exposure is live for any Llama/SmolLM3/Mistral/Granite/gpt-oss model added later.
- Orchestrator and research code: no date placed into eval or judge system prompts. `epyc-orchestrator/src` hits are telemetry timestamps and a REPL tool `get_current_date` (`prompt_builders/constants.py:L282-L380`), a model-visible tool, not a prompt prefix. The only in-house `strftime_now` shim is the offline golden harness `epyc-inference-research/artifacts/f8-evidence-20261021/ct12/ct12_4_goldens_ab.sh:L122` (datetime.now), which would leak the date into goldens only for a template that uses it (the Qwen ones do not).
- Recording: result records pin `served_template_sha256` in the registry (`orchestration/model_registry.yaml:L1867, L2042, L2111-L2114`) and the template review gate, but no eval record, I found, stores the rendered date; with date-free templates there is nothing to record, but nothing would flag a regression.
- Judge: `eval-tower-program.md:L1377` says "Claude-as-Judge"; whether the judge API path injects a date server-side is UNKNOWN (x02 §5.2 saw it for GPT-5.1 and OpenRouter Qwen3); a zero-compute probe ("what is today's date?" with empty system) answers it.
- OFFICIAL-SAMPLING recipes (`autokernel-loop.md:L8702`, RATIFY-OFFICIAL-SAMPLING-20261124): sampling params are pinned and the garbage check covers five served models; none of the pinned recipes mention a date. The same paper-grade reasoning (x02: default temperature, fixed seed, no date drift) says pin template sha + date together.
