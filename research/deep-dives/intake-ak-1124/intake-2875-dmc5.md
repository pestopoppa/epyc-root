## 2. Key claims
0. **Agent input -38.5% to -57.0%, end-to-end cost -14.5% to -28.0%, compressor cache hit 78.0%-85.0% — CONFIRMED.** Table 1: agent input -46.55% / -38.46% / -57.02%; cost -24.80% / -14.48% / -27.97% (AppWorld / OfficeBench / 8-objective QA); cache hit 80.3 / 78.0 / 85.0. Means over three runs; cost is billed price on Alibaba Cloud Model Studio, not compute. Anchor 0.
1. **Task performance +1.0 to +5.8% — PARTIAL (units and noise).** These are ABSOLUTE points over No Compression (AppWorld +1.2, OfficeBench +1.0, 8-objective QA EM +5.8 / F1 +6.4), per the Table 1 caption. Run-to-run SDs (n=3, Table 14): AppWorld 77.0 +/-2.4 vs 78.2 +/-0.9; OfficeBench 87.0 +/-1.9 vs 88.0 +/-1.0; only QA is clearly separated (EM 39.1 +/-1.8 vs 44.9 +/-0.3). So AppWorld and OfficeBench "improvements" are inside one baseline SD; generation seeds are not fixed. Anchors 1, 12.
2. **Cost model and whether the saving survives local serving — OVERTURNED for local framing.** Cost = tokens x per-million price per Eq. (3)-(5). Agent (LoRA Qwen3.5-27B on a fine-tuned endpoint) is priced with NO cache discount (0.30 in / 0.30 cached / 2.40 out); compressor DeepSeek-V4-flash 0.50 uncached / 0.10 cached / 1.00 out; alt compressor Qwen3.7-flash 0.10 / 0.02 / 0.40. The saving exists because (a) the agent's repeated history is billed in full and (b) the compressor's history is billed at 20% price. With a cache-discounted agent endpoint (Qwen3.8-27B, 20% ratio), saving falls to -9.4% (35.72 -> 32.38) and break-even is a 9.1% cached/uncached ratio. Locally prefix-cache reuse is a compute saving, not a price one, and the uncompressed baseline already gets it for free on its append-only history, so the "agent input" saving is not a prefill saving locally; it is a decode-attention/KV-footprint and window-binding saving. Moreover the Decision View is NOT append-only: the summary block is regenerated every Delta=3 turns or every 6,000 new tokens (K=1 verbatim turn), so the agent prefix changes at every compression round (agent cache hit drops 70.5% -> 51.5% in the cached-endpoint run). Anchors 2, 3, 4, 5.
3. **Append-only canonical view keeps the compressor prefix stable — CONFIRMED.** The compressor input is H_t (previous prefix, byte-identical and in order) + U_t (new turns); compressor output is never written back to the canonical trajectory; cache-hit rate climbs from 0 to 96% by the last compression (Fig 4); vs ACON-style recursive summary (0 cached tokens) it reuses 15.6K-198.2K cached tokens per task. Anchor 6.
4. **YAMATO integrity — CONFIRMED, and it is where the gain is.** The compressor emits a structured summary plus pinned pointers; a deterministic restoration step copies the referenced raw records byte-for-byte, a persistent failure ledger carries failed actions across rounds, and turn provenance tags are attached. AppWorld: DMC-5 WITHOUT YAMATO 69.1% at cost 13.31 (worse than No Compression 77.0% / 13.71); WITH YAMATO 78.2% / 10.31. Corrupted execution-critical items 0.33% -> 0.01%, recall 77.7% -> 98.3%, max same-action repeats 29 -> 6. So the append-only+dual-model skeleton alone does not beat no-compression; the integrity layer is load-bearing. Anchors 7, 13.
5. **Which models play which role — CONFIRMED with an important narrowing.** Agent = fine-tuned Qwen3.5-27B (private-data LoRA, no benchmark leakage claimed); compressor = DeepSeek-V4-flash (parameter count NOT-FOUND-IN-SOURCE) or Qwen3.7-flash (size NOT-FOUND-IN-SOURCE). So the split is "cheap general API compressor / specialised mid-size agent", not "small compressor / large agent": the paper never states the compressor is smaller than the 27B. Role ablation (Table 4, AppWorld): specialised->specialised 77.4% at 21.49; DeepSeek->specialised 78.2% at 10.31; DeepSeek general-only 70.6% at 6.93 (cost/success 0.0591); Qwen3.7-flash->specialised 73.8% at 9.50. Cost per success of DMC-5 (0.0781) is WORSE than running the general model alone (0.0591), so the case for the split is quality (+7.6 points), not cost. Anchors 8, 9.

## 3. Reported results (as stated)
- Table 1 (three runs, Alibaba Cloud API endpoints, agent LoRA Qwen3.5-27B, compressor DeepSeek-V4-flash): see claim 0. Baselines on AppWorld: FIFO 36.3% (-34.5% cost), AgentDiet 64.8% (-12.98%), ACON 67.3% (-15.61%), DMC-5 78.2% (-24.80%). 8-objective QA: AgentDiet EM 35.5, ACON 34.2, DMC-5 44.9 (No Compression 39.1).
- Table 3 (OfficeBench): tasks compressed once cost +10.7% vs no compression; two or more compressions save 16.6-26.5%; break-even around step 16, 25% net saving by step 50 on AppWorld.
- Table 7 generalisation (compression-triggered subsets): PinchBench cost -8.2% (37/40 both); tau2-bench -8.5% (42/64 -> 43/64).
- Latency (Table 22, synchronous compression): AppWorld 69 s -> 94 s, OfficeBench 38 -> 44 s, QA 122 -> 186 s per task.
- Hyperparameters: K=1, Delta=3, T=6000; T=3000 drops AppWorld to 72.4% at cost 15.28; Delta=1 gives 70.6% at 19.82.
- Cost vs ACON: text says +5.7% (Office) to -9.19% (AppWorld); recomputing from Table 1 gives +7.2% (4.49 vs 4.19), -10.9% (10.31 vs 11.57), -1.7% (25.50 vs 25.94). The text and table do not reconcile; the dive uses the table values.

## 4. Performance-principles table
| Principle | MI210 gfx90a | Zen 5 EPYC 9655 | Reason |
|---|---|---|---|
| Append-only prefix for compressor (slot reuse, prefill only delta) | YES | YES | llama-server slot/prompt-cache reuse works if the compressor slot is pinned per trajectory. Cost: one resident KV slot per live trajectory (HBM2e 64 GB on MI210; DDR5 on CPU is plentiful). |
| Decision view regenerated every 3 turns | PARTIAL | PARTIAL | Agent re-prefills summary + recent turn each round; hybrid (GDN) models cannot shift KV (`src/llama-memory-recurrent.cpp:832` `can_shift` false, cited in KV-EVICT-COST-1 text at `kv-cache-program.md:L644 @ f74b175`), so the re-prefill is the whole suffix after the changed block. Cheap if the summary sits at the tail of a stable system+task prefix. |
| Pinned-pointer deterministic restoration (YAMATO) | YES | YES | Pure harness code; device independent; reduces compressor output tokens (decode, bandwidth-bound) as well as errors. |
| Heterogeneous compressor/agent on different devices | YES | YES | Compressor on a CPU quarter while the 27B agent runs on MI210 removes the paper's serial latency penalty (+36% AppWorld) if compression is asynchronous (the paper lists async as future work). Uncited, relies on host description. |
| Price-based saving via cached-input discount | NO | NO | Local has no per-token price; replace by seconds and KV bytes (see KV-EVICT-COST-1 break-even table). |

## 8. Contradiction / adversarial pass
- Cost per success of DMC-5 (0.0781) exceeds general-model-alone (0.0591; Qwen3.7-flash alone 0.0389 vs DMC-5 0.0766); the paper argues quality, but a cheaper general-only configuration is Pareto-cheaper.
- Without YAMATO the pipeline is below No Compression (69.1% vs 77.0%) and costs almost the same (13.31 vs 13.71); the headline is a YAMATO result more than an append-only or dual-model result.
- AppWorld/OfficeBench gains are within one run SD; n=3, no seeds.
- Latency is worse (+36% to +52%); the authors acknowledge synchronous compression as a limit.
- Tasks compressed only once cost +10.7% more than no compression; short trajectories lose.
- Pricing is a fixed snapshot of Alibaba Cloud Model Studio; the agent is a private LoRA on private data, not reproducible externally. The text's cost-vs-ACON range does not match Table 1 arithmetic (section 3). Authors are the vendor of both endpoints (commercial bias).
- Restatements: none found.
