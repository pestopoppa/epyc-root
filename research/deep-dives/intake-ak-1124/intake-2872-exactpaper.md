## 2. Key claims

1. **Exact features flip 1.47% (CI 1.13-1.85) to 1.78% (1.39-2.20), none above the 1.72% scheduling floor.** PARTIAL. Numbers CONFIRMED (Table 2: BS 1.47, NGRAM 1.78). But "none above" is inferential only: the point estimates of NGRAM (1.78) and EAGER (1.77) ARE above 1.72; the paper's claim is that no exact feature has a positive one-sided lower bound on its excess over the scheduling floor (largest estimates +0.06 and +0.05 points, upper bounds +0.33 and +0.32). Also against the RESTART floor (1.38) three features (EAGER, NGRAM, DRAFT) DO flip by the preregistered rule, and so do both reordered replicas, which changed nothing. Anchor 0, 1.
2. **FP8 KV flips 3.36% (2.80-3.96), as many as FP8 weights.** CONFIRMED. FP8W 3.38 (2.80-4.01); both about +1.65 above the scheduling floor (lower bounds +1.19 / +1.22); accuracy change +0.13 passes the 1-point equivalence test; 63 right vs 61 wrong (McNemar p 0.93). Anchor 2.
3. **With batch-invariant kernels all seven exact features, spec decode included, reproduce reference text on every request.** CONFIRMED for this setup (vLLM 0.33.0 `VLLM_BATCH_INVARIANT=1`, 3,380 items, upper bound 0.09% on text flip rate). Authors' own scope limit: holds for those kernels only (Limitation 6). FP8KV still flips 3.91% (3.28-4.53), FP8W 3.43%. Spec features were preregistered only for zero CORRECTNESS flips; zero TEXT flips went beyond the prediction. Anchor 3, 4.
4. **A single-replica-pair gate rejected an unchanged configuration.** CONFIRMED with detail: holding out R2 against floor from the other two restarts (one pair) gave excess +0.96, one-sided upper +1.34, FAIL at 0.5-point tolerance. Cause: the three restart pairs differ on 25 (R1,R3) to 62 (R1,R2) items (0.74% to 1.83%). Reordered S1/S2 against all three: INCONCLUSIVE. Preregistered C3 refuted in the default arm. Anchor 5, 6.
5. **Statistics as steered (floors, bootstrap, equivalence, margin, why >=3, what "flip" is).** CONFIRMED, definitions below. Anchor 7, 8, 9, 10.

### Statistics checked against the text
- **Flip definition:** item-level GRADED outcome (right/wrong) differs between candidate and a reference replica. Per-item flip probability = share of the k (candidate, replica) pairs that differ; flip rate = mean over items. Not answer, not text. Secondary metrics: answer flip rate (extracted answer differs; REF restart 3.01%) and text flip rate (any token differs; 24.56% restart, 29.00% reordered). Graded 1.38% << text 24.56%: text identity is a far stricter, mostly irrelevant criterion for graded accuracy, which is why our token-identity gate needs margin classes.
- **Restart floor:** same quantity over all pairs of restart replicas (R1,R2,R3 fresh processes, canonical order): 1.38% (upper 1.69%). **Scheduling floor:** over all (S, R) pairs, S1/S2 = same requests shuffled (seeds 1, 2): 1.72%. Both include preemption (about 1,947 per REF replica), batch composition, kernel selection.
- **Excess** = per-item candidate flip probability minus per-item floor, averaged over items (paired on the same items).
- **Cluster bootstrap:** 2000 resamples, seed 0, cluster = MMLU subject, otherwise item; 2297 clusters. 95% CIs for flip rates; one-sided 95% bounds for excess; 90% interval for accuracy change.
- **Equivalence test:** paired accuracy change (candidate minus mean reference accuracy), TOST-style 90% interval inside a 1-point margin. Note the margin is a chosen convention, not derived (reference accuracy 85.94%, CI 84.26-87.53, so the margin is smaller than the reference CI half-width of about 1.6). Accuracy passed for all 11 candidates, FP8 included, so accuracy alone has no power here.
- **Flip-gate rule:** PASS if one-sided 95% upper bound of excess <= 0.5 points; FAIL if lower bound > 0.5; else INCONCLUSIVE. Table 2: only CP and BS PASS at this n; 7 of 11 INCONCLUSIVE (sample too small to bound the excess below 0.5 pts). Gate FAILs both FP8 configs.
- **Why >=3 replicas:** one pair gives one noisy floor estimate; 3 replicas give 3 pairs. Authors give no variance formula or power calculation for 3; the justification is the single empirical failure (R2) plus Limitation 3 admitting 3 is still variable. "At least three" is an empirical minimum, not a derived one.
- **Statistical weaknesses I found:** (a) one candidate run per feature, so candidate own restart variability is not averaged (authors say it widens CIs); (b) the 3 restart pairs share replicas, so pair-level floors are not independent and the bootstrap over items does not capture replica-sampling variance (the clusters resample items, not replicas); this is the very variance the R2 failure exposed, so the interval around the floor understates it; (c) C3 was preregistered and refuted, which the authors report honestly; (d) margin AUC 0.89 is confounded with output length (AUC 0.88, corr -0.76).

## 8. Contradiction / adversarial pass

- The steering sentence "none above the scheduling floor of 1.72%" is wrong on point estimates (NGRAM 1.78, EAGER 1.77) and right on lower bounds; also against the restart floor three exact features DO "flip" by the preregistered rule and C1 holds at exactly threshold (3 of 7). Cite the lower-bound statement, not the point comparison.
- C3 (gate: no FAIL on null comparisons) was REFUTED in the default arm: the authors' own gate produces a false FAIL. The recommendation (>=3 replicas) is therefore a post-hoc fix to a failed preregistered claim, not a validated one; no run with >=3 replicas is shown to be false-FAIL-free (only 5 null comparisons, and S1/S2 are INCONCLUSIVE).
- EAGLE3's accuracy change +0.42 has a 90% CI excluding zero though inside margin; an accuracy gate would still pass.
- Generalisation: 4B model, one engine version, one consumer GPU (shared with other jobs), five exact-graded benchmarks, one candidate run per feature (all authors' limitations). No replication; code and per-item outputs "available on request until release" (unverifiable now).
- Batch-invariant result: the authors say another version or GPU could fall back to a batch-dependent kernel; for our stack it does not carry over at all (no such mode in llama.cpp C21).
- Independent corroboration: 2510.22876 v4 Table 4 (in our index) is the only one and only partly overlapping (batch size 1 spec vs non-spec, 80/80). The other related papers are cited by this paper, not corroboration.

### Settlement of the four questions

1. **Match, extend, or contradict our in-row reference-build band?** EXTEND, not contradict. The paper's core idea (candidate judged against a floor measured from replicas of the reference on the same items, paired, with the floor split into restart vs scheduling) is the same idea as the in-row reference-build band and the same-run A/A arm. Our protocol adds what the paper lacks: margin classes (cause-aware, distinguishing near-tie flips from defects) and an explicit exact-identity regime with floor 0. The paper adds what we lack: (i) a replica count >= 3 with all-pairs floor, (ii) a distinct scheduling-floor arm built from reordered requests (our A/A arm repeats the same config, not a different batch composition, so it can under-estimate the np>1 floor), (iii) an excess-over-floor with a one-sided bound vs a tolerance fixed in advance, (iv) a graded-outcome metric. A fixed 0.19/0.38 nat band is exactly the kind of single threshold the paper warns against; a per-build in-row band is consistent with the paper. (I could not read tonight's band design; this is a judgement on the protocol doc.)
2. **Minimum replica count / statistic:** at least 3 replicas of the reference (>=2 independent relaunches plus >=1 reordered or np-shuffled), all pairs, per-item floor, excess = candidate pair-flip rate minus floor on the same items, cluster bootstrap by prompt (or prompt group) with replicas treated as a second source of variance (the paper's bootstrap does not resample replicas, a gap), one-sided 95% bound vs a pre-set tolerance, INCONCLUSIVE otherwise. For our margin-class gate the analogue is: tau comes from all replica pairs' first-divergence margins, not one A/A. **Where we are single-pair:** one A/A repeat per block is single-pair at the item level (mitigated by averaging over blocks); sequential/one-shot gates (r9, c20-gpu27b-margin-capture) and BSV-2's paired accept gate are single-pair; the doc rule "single triples decide nothing" is correct but rows must be forced INCONCLUSIVE until blocks >= 8 and replicas >= 3.
3. **Batch-invariant / deterministic mode in llama.cpp at C21?** None as a flag (grep @ 98ff8a4). Closest: CPU `GGML_ROWEXACT_N` and `LLAMA_SPEC_EXACT=serial`; neither exists as a GPU zero-floor mode (serial does not restore width-1 identity on GPU). Does the paper imply our spec-decode A/A drift is scheduling noise rather than a defect? It supports that reading only conditionally: it shows that with default kernels exact features flip graded outcomes at the scheduling floor and that all flips vanish when arithmetic is batch-invariant, so drift between spec and non-spec at default kernels is batch-dependent arithmetic, not a logic defect, in vLLM. For us that supports "near-tie divergence is expected" but NOT "any divergence is noise": a `gt0.5` divergence, DEGEN_AFTER_TIE or any divergence inside the CPU exact regime remains a defect candidate, and we have no zero-floor arm on GPU to prove the remainder. The paper also does not test Gated-DeltaNet/recurrent targets (our server comment says quantized recurrent targets are not batch-invariant); extrapolation unproven.
4. **FP8 KV finding vs q8_0/q4_0 KV:** the transferable lesson is that KV precision flips graded outcomes at about 2x the scheduling floor even when accuracy is equivalent (+0.13 pts, 63 vs 61), and the flip survives a zero floor (3.91%), so accuracy and KLD gates do not bound it. FP8 itself does not transfer (MI210 has no FP8; paper used FP8 on RTX 5070 Ti; our formats are int8-block q8_0 and 4-bit q4_0). By general knowledge (uncited) q8_0 has more mantissa precision than FP8 e4m3 and q4_0 less, so a q4_0 KV flip rate at or above FP8's is plausible, but this is a hypothesis for A5 to measure, not a result. A KV-quant flip budget should be a paired graded-flip excess over the in-row scheduling floor, reported next to accuracy and KLD.
