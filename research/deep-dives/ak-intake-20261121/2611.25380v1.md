## Verified numbers
- Table 3 matches the Stage-1 entry. Gains vs base: SAO +0.21/+0.21/+0.20; GEPA +0.17/+0.23/+0.11; combined +0.30/+0.35/+0.29. Harness-only share of SAO gain: SWE 81%, Office 110%, Terminal 55% - the text's "55-110%" is correct. Table 4: A_SWE 0.48/0.29/0.36, A_Office 0.30/0.51/0.34, A_CLI 0.32/0.27/0.46, base 0.31/0.28/0.35.
- Seeds / variance: none reported ("point estimates from a single training run per configuration"); no confidence intervals; two-decimal scores on n=100-200 tasks imply +-5-10 pp sampling error, larger than several claimed deltas (e.g. OfficeBench GEPA 0.51 vs SAO 0.49).
- Overfitting controls: the loop evaluates each candidate "on the task sample" of the target benchmark, uses the same sample for all candidates in a generation, three rollouts + majority vote; the final adapter is argmax of mean success over the archive. No held-out tasks are reported. The paper's limitations section concedes the evolved harness 'may overfit to the evaluation distribution'.
- Reflection model and cost: "GEPA runs on CPU and uses a reflection API"; the model is unnamed and its tokens are excluded from the 0.8M tokens/task. "~4 h" wall time for 32 x 20 candidates x 3 rollouts x 300 benchmark tasks is not reconcilable without parallelism details.
- Policy identity: the base Codev model is not stated; SAO starts from Qwen3-30B-A3B; the SFT diagnostics (Figs 5-6) use Qwen3.5-4B.

## Adversarial pass
Single-author independent researcher with own agent (Codev) and own harness; no independent replication found. Reviewer-style objections: (1) base-harness weakness - the 'base' harness has 8 skills and 12 tools, so any tuned prompt may beat it; (2) SAO baseline run with another group's hyperparameters, one run; (3) weight-only was trained on a different base (30B-A3B) than diagnostics (4B); (4) Table 3 mean scores without CI cannot support 'harness-only exceeds SAO on OfficeBench' (0.51 vs 0.49).
