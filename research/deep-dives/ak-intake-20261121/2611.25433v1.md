## Mechanism (Sections 2.4 and C)
- **Phase A.** A streaming kernel computes RocketKV approximate logits from page min/max key summaries over the top-r query dims, as an FP32 non-WMMA matmul. Section 2.4 says "scores for every single token" while C.1 says "per-(page, GQA-rep)"; the text is ambiguous here. The same kernel computes the redundancy cosine against the centroid (one extra matmul plus one global write per tile). The block table is loaded into shared memory once per kernel. KT layout makes the top-r-dim sparse loads coalesce; NHD is better for Phase C and short sequences. A reduce kernel does the softmax, the GQA aggregation and the (1 − λr) multiply.
- **Phase B.** Approximate top-k: one block per (request, kv head); each thread keeps its best 4 candidates (P = 4) through a branchless bubble; one `cub::BlockRadixSort` sorts descending. A token from the exact top-k is missed only if more than 4 of them fall in one thread's slice. Under KT, indices are re-sorted by position.
- **Phase C.** Exact sparse attention over the sorted index list: 16 positions per tile, 4 threads per position, online softmax, 128-bit loads, cp.async double buffering, a peeled boundary tile masked to −∞. Each request reads its own budget k_t from `topk_per_req[B]`, using the prefix of the sorted list.
- **Split-KV.** The host plans splits per request greedily, outside the graph, in proportion to cached length, and writes them into device tables. A fixed grid lets one captured graph replay every step.

## Mapping to EPYC KV-eviction state
- **Expected Attention on hybrid 27B: no safe ratio.** AM-PORT-2B ladder: EA keep 0.8 scores 1/32 and EA at 5x scores 0/60, against FULL 60/60. The failure is scattered per-token eviction dropping single-digit needle tokens (`handoffs/active/long-context-program.md:901-907` @ ac1347f). EA-HYBRID-FOLD-GUARD stays open (`handoffs/active/kernel-champion-and-promotion.md:433` @ ac1347f). Expected Attention is the deployed default compactor (long-context-program.md:794, 1802). RoCoKV's speed result comes from the opposite regime: **query-aware per-step selection without eviction** (the cache stays intact, so a miss is recoverable at the next step). The paper's own number for permanent eviction is RocketKV at budget 128, which scores 0% on AIME25 until exact top-k is substituted (16.67%). That is consistent with our EA failure, and it says the lever is selection quality at uncertain steps, not a better eviction score.
- **The redundancy idea vs our EA.** The deployed EA scores keys against the mean pre-RoPE key (AM-PORT-2 diagnosis, long-context-program.md:902). RoCoKV's redundancy term uses the same key-centroid geometry but only as a ≤10% penalty, and on its own it collapses on AIME25. It does not address the digit-dropping failure. Decline it as an EA fix.
- **Hybrid 27B, 16 global-attention layers (about 1/4).** KV scales only on those layers (`handoffs/active/kv-cache-program.md:2202` @ ac1347f). The in-house byte roofline (LSA-CPU-SPARSE, long-context-program.md:1919): for 27B Q8_0 decode, KV is 3.8% (q8_0 KV) / 6.9% (f16) of per-token bytes at 32k and 13.6% / 22.8% at 128k. A sparse selector caps e2e decode gain at about +3.1% (q8_0, 32k) and about +14% (q8_0, 128k). That ceiling is roughly 4× lower than for a dense-attention 8B like the paper's (all layers carry KV, plus a smaller weight footprint). Production :8083 shows 42.62 → 37.25 tok/s from about 2k to about 50k context (quantization-and-low-bit.md:96), which puts the KV-dependent share of a step near 13%. **Memory relief is near zero** for selection without eviction, and small for eviction, because only 1/4 of the layers carry KV.
- **Existing in-house sparse-attention path.** D-LSA H12 fused sparse FA (top_k/mask in FA src[5]/src[6]) on the 27B's 16 global layers was **FUTILE on GPU at 32k: 0.368×**, because "scoring + top-k over all keys plus re-projecting f16 K per ubatch costs more than the 4,612-of-32k sparse attention saves" (long-context-program.md:1911). The CPU op gate LSA-CPU-SPARSE gave KEEP_OP 3.97× at T24 (long-context-program.md:1913). That is exactly RoCoKV's Phase-A problem, which it attacks with the KT layout and top-r dims. Ours is the missing persistent low-dimensional index-key cache (long-context-program.md:1919, finding 1).
- **Speculative serving.** Production verify is multi-row (DFlash2 n_max 7). RoCoKV is single-token decode, sampled at T = 0.6. Per-row selection in verify needs either a per-query index list or a union. Per-step entropy is available from the target's verify logits.

## Adversarial pass (3 queries)
- No independent replication of RoCoKV exists; it was published 2 days ago and the code is "released upon acceptance". This is a restatement-free fact.
- RocketKV (arXiv 2502.14051, ICML 2025, same senior author Tumanov) is the backbone. Its own claims (comparable accuracy up to 400× compression, 3.7× speedup on A100) are on long-context inputs, not reasoning traces.
- SkipKV (arXiv 2512.07993, MLSys 2026 oral, Kundu is a co-author of both papers) reports up to 26.7% higher accuracy than baselines. RoCoKV's re-implementation has SkipKV at 15.20% vs 67.20% on MATH500, which suggests a baseline re-implementation gap. SkipKV's thesis is that token-level eviction breaks semantic units; that matches our EA digit-dropping failure.
- R-KV (arXiv 2505.24133, already ingested) reports 105% of full accuracy with 16% of the cache in its own setting. In RoCoKV's Table 1 it is only 0.94× latency. Its speed path is a different port (the R-KV vLLM v0.25.1 env-var port).
