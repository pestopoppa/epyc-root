### Claims (as verified)

0. Mechanism (v1, the version NeMo-Speech.cpp ports): phrases are tokenised with the model's own BPE tokenizer into an Aho-Corasick prefix tree with failure links; arc score is c0 at depth 1 and c0*beta + ln(depth) deeper (beta=2, c0=1 by default), a root self-loop scores off-trie tokens at c_unk (0 by default), failure-link backoffs subtract the accumulated partial score and are zero at phrase-final nodes (the boost is 'banked'). At each decoding step hypothesis score = acoustic + lambda * tree score. No retraining, no second model. The logarithmic depth bonus is the paper's novelty over the Icefall uniform-weight tree (GPU-PB uw), whose reward arrives only at the final node and so lags in greedy decoding. The GPU part (sorted-arc table, index-select, Triton kernel for CUDA graphs) is PyTorch-specific; the tree itself is plain host data (NeMo-Speech.cpp rebuilds it on the host).
   - *unaffected*: Mechanism read in II-A/II-B and Algorithm 1; it matches the NeMo-Speech.cpp header comment (token_score formula, backoff_w, unk_score 0) read at 2bdfb03b.

1. Greedy rule that bounds insertions: decoding is two-stage. First a plain greedy pick without boosting; if it is blank, the frame is skipped untouched (for CTC a repeated token is likewise kept unboosted); only otherwise are the remaining non-blank tokens reweighted by the tree and the best of those emitted. Boosting therefore cannot make a lexicon term appear on a frame the model wanted to leave blank; it can only swap which non-blank token wins. NeMo-Speech.cpp implements exactly this (blank excluded from the second argmax; comment cites NeMo/riva rnnt_label_looping semantics). It does not make substitution-type false accepts impossible: any acoustically plausible non-blank frame can flip to a lexicon token, and the per-depth ln() growth makes a phrase hard to abandon once its first subword is taken. The paper never measures insertions on audio that lacks the terms.
   - *narrowed*: The abstract says GPU-PB works 'without noticeable speed degradation' and the intro implies robust behaviour; the two-stage rule bounds insertions at blank frames only. Substitution-type false accepts and non-list word degradation are real (see claims 3,4).
   - anchor `paper.txt: II-C two-stage selection` @ arXiv:2508.07014v1 (html saved as paper.html -> paper.txt; v2 of 2025-08-12 saved as paper_v2.html, body identical by normalized diff): "First, greedy selection is applied without boosting. If the result is a blank token, we proceed to the next decoding step."

2. Case handling: v1 is case-sensitive. The tree matches the tokenisation of the string given, so 'hello' does not match a cased 'Hello'. The v1 paper's remedy is to add the variants (plural forms and capitalisation) as separate list entries, at the price of a larger tree; TurboBias 2.0 later replaced that with a case-insensitive graph. NeMo-Speech.cpp feeds each phrase through encode_phrase verbatim (no case folding, no length floor, a single fusion alpha from the largest request boost clamped to boosting_max_boost 5.0, class hints starting with '$' skipped), so a Nemotron-3.5 lexicon trial must supply the surface forms the model emits.

### Verdict

TurboBias v1 is a small, well-specified shallow-fusion tree whose exact semantics (greedy two-stage pick, case-sensitive match, depth-scaled scores, off-trie score 0) are what NeMo-Speech.cpp ships, so the first CS lexicon trial tests this mechanism. The paper proves recall gains on English with authors' own models and sets; it proves nothing about insertions on lexicon-free speech, non-English languages, Parakeet/Nemotron models, or CPU cost. Do not cite its 2-5 percent overhead or WER gains as expectations for our stack.
