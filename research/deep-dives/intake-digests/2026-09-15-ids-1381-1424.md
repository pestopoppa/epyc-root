### Verdict

On the only LLM serving-engine surface in this benchmark, default SMAC/HEBO/BOHB/Hyperband did not beat random search at a budget of roughly a hundred-plus evaluations, even though config effects were several times larger than repeat noise. That is negative input for putting a classical sampler in front of autokernel U3, where effects sit below the session floor. It does not test TPE, CMA-ES or LLM proposers, does not study crash handling (though its SGLang table is a good offline fixture for it), and its paper tables and failure-cleaning text disagree with its own released data.
worth_investigating, not adopt_component: nothing here should enter a loop, but the released SGLang table is a ready zero-inference fixture for AP-NUM-FAIL (a deterministic infeasible region covering 88% of rows) and the vLLM r1/r2 pairs quantify noise-vs-effect for a sampler-vs-random replay. ### Claims (as verified)

0. Upstream ts is a per-user server on a unix socket that runs queued commands under a global slot count; a job may request -N slots, which the man page suggests using to represent CPU cores - slots are a number, never an identity of which cores (ts.1, ts-1.0.4).
   - anchor `ts.1:106-110` @ task-spooler ts-1.0.4.tar.gz from viric.name/soft/ts (upstream release 2025-06-30, tarball sha256 b1ab3db52dca36af3699178b8d0e936a30107f8d5c86a974163c580823b01790): ".B "\-N <num>" Run the command only if there are \fbnum\fB slots free in the queue. Without it, the job will run if there is one slot free. For example, if you use the queue to feed cpu cores, and you know that a job will take two cores, with \fB\-N\fB you can let ts know that."
1. The scheduler walks the job list in order and starts the first queued job whose slot request fits the free slots, so a job needing more slots than are free is skipped and later smaller jobs start ahead of it (backfill with no reservation) (jobs.c next_run_job).
   - anchor `jobs.c:542-548` @ task-spooler ts-1.0.4.tar.gz from viric.name/soft/ts (upstream release 2025-06-30, tarball sha256 b1ab3db52dca36af3699178b8d0e936a30107f8d5c86a974163c580823b01790): "if (free_slots >= p->num_slots) { busy_slots = busy_slots + p->num_slots; return p->jobid; } } p = p->next;"
2. There is no halt-all admission lever via slots: the client refuses -S values below 1 (main.c); stopping admission means killing the server (-K) or sending signals to jobs.
   - *narrowed*: Anchored on the -S parse guard; that no other admission-halt lever exists is read from the action list in main.c/ts.1 (-K kill server, -k/-T signals, -r remove), not a positive statement in source.
   - anchor `main.c:177-179` @ task-spooler ts-1.0.4.tar.gz from viric.name/soft/ts (upstream release 2025-06-30, tarball sha256 b1ab3db52dca36af3699178b8d0e936a30107f8d5c86a974163c580823b01790): "if (command_line.max_slots < 1) { fprintf(stderr, "You should set at minimum 1 slot.\n");"
3. Waiting is event-driven: -w registers the client on the job's notify list and the server answers when the job finishes, and on enqueue the client blocks on a server message before it forks and runs the command itself in its own environment (jobs.c s_wait_job; upstream web page "How it works").
