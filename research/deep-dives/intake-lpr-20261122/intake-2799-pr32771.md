## 4. Mechanism (read from diff.raw.patch, `tools/server/server-context.cpp`, function `server_context_impl::...` speculative verify-and-accept lambda in `post_decode`)
Before: after accept, `slot.prompt.tokens` gets ids[0..n-2] appended and one `seq_rm(pos_next, -1)` trims the memory; then the emit loop calls `process_token` for each accepted id. If `process_token` returns false (stop string, EOG, length) at index i < n-1, tokens ids[i..n-2] stay in both `prompt.tokens` and the memory, whereas the non-speculative run never caches the stopping token or anything after it.
After: (a) `use_ckpt_tgt` is hoisted above the accept loop; (b) the early `seq_rm` is removed; (c) on stop at index i with i+1 < ids.size() and a trimmable target/draft, `keep_first(n_tokens - (ids.size()-1-i))` drops ids[i..n-2] from the token list and `seq_rm(pos_next,-1)` is issued once; otherwise one `seq_rm` after the loop.
Recurrent/hybrid interaction: the trim is a plain position `seq_rm` — no checkpoint restore, no reprocess. For RS memory it relies on the per-sequence snapshots that exist for batches up to `n_rs_seq + 1` tokens (the code comment), which is why it is gated on `!use_ckpt_tgt` and is done once. When the target must use its checkpoint (FULL type, or RS with a longer draft) the PR leaves the stale tokens in place; those cases still force the next request to trim or reprocess (see #28049 in the PR text).

Consequence for us: stop inside an accepted draft (stop string, EOG, `n_predict` hit mid-draft — the length limit is also a `process_token` stop) leaves up to n_draft-1 stale tokens in `prompt.tokens` and in the target memory. Next request on that slot:
- attention-only/PART targets: LCP against the new prompt, `keep_first(n_past)` (`:4945`) and `seq_rm(p0,-1)` (`:4986`) trim the surplus; cost is nil, only `tokens_cached`/`cache_n` differ.
- recurrent/hybrid (Qwen3.8 GDN, A3B): the recurrent state contains the stale tokens; a position trim back to p0 is refused unless a snapshot/checkpoint covers it, and the code then does the full-prompt reprocess (`:4986-4990`, warning "memory refused the rollback ... re-processing the full prompt"). So the champion failure mode is lost prefix reuse (large reprocess) — NOT silent state corruption: stale tokens are always checked by token identity against the next prompt, and the refusal paths fall back to reprocessing.
