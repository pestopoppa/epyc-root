## 3a. Hardware lens (derived from config + this diff)
CPU decode, per token (24 physical / 48 visits): experts 8 x 7,962,624 x 48 = 3.06B weights = 1.72 GB at IQ4_NL (4.5 bpw) or 3.25 GB at Q8_0 (8.5 bpw); attention 18.9M x 48 = 0.91B; unembed 463M; so ~4.4-4.9B weights per token (card says 5.4B effective incl. embedding). Mixed IQ4_NL experts + Q8_0 rest = ~1.72 + (0.91+0.46) x 1.0625 = ~3.2 GB/token; all-IQ4_NL ~2.8 GB; all-Q8_0 ~5.2 GB. This CORRECTS the first dive's "1.7 GB/token": that was experts only, and attention + unembed add ~1.5 GB. Expert reuse across passes is not guaranteed (different hidden state routes differently), and per pass ~430 MB of experts at 4.5 bpw is far above a CCD's 32 MB L3, so no cache saving. tok/s ceiling = effective bandwidth / ~3.2 GB (bandwidth is not in source; compute with the measured host figure, not a guess).
MI210: total weights 26.4B => ~28 GB at Q8_0 (the Unsloth UD-Q8_K_XL file is 22,867,451,616 B per the PR comment), ~15 GB at IQ4_NL; both fit 64 GB HBM with ~35 GB left for KV: at f16 1.16 GiB/seq @32k (+ conv state), that is ~30 concurrent 32k sequences or ~8 at 128k; q8_0 KV roughly doubles that. Per-token HBM bytes at Q8_0 ~5.2 GB; at high concurrency expert reads amortise across sequences per pass.

## 4. Performance principles table
| Principle | MI210 | Zen 5 |
|---|---|---|
| Unrolled loop, shared weights per physical layer (`layers[il]=layers[ip]`) | YES: pure graph structure; weights resident once | YES: same; no bandwidth gain (see 3a) |
| Per-visit KV/recurrent cells (48 slots) | YES: slot count 48 vs 24 doubles per-seq overhead; fine at 64 GB | YES |
| Graph node budget x pass count | YES | YES |
| Attention-residual bank + `mix` (ggml_mul_mat on transposed stacked blocks) per core layer per pass | PARTIAL: small GEMMs (n_embd x ~blocks) per layer; launch-bound at n=1 on HIP (graph capture helps) | YES: negligible vs experts |
| Loop controllers: 3 low-rank mul_mats x 4 modules per core layer, rank 64 | PARTIAL: tiny GEMV; launch overhead on HIP | YES: 2304x64 / 64x2304 trivial; quantizer excludes `.loop_` tensors (keep F32/F16) |
| Short-conv (SSM_CONV) state for sconv + K/V dynamic conv | YES: CUDA/HIP SSM_CONV exists (ggml-cuda.cu:2518 @ eee3da8) | YES: CPU SSM_CONV exists (ggml-cpu.c:2549 @ eee3da8) |
| Dense bias kq_b + sinks, no FA | PARTIAL: materialised [n_head, n_kv, n_tokens] F32 — fine n=1-16, huge for prefill | PARTIAL: same; at decode n_tokens=1 and 32k ctx a full-visit kq_b is 24 x 32768 x 4 B = 3 MiB, fine |
| NVFP4 expert blocks (native option) | NO (no FP4 on gfx90a; must dequant) | PARTIAL: type exists in tree, but no AVX-512 native FP4 kernel; IQ4_NL requant is the practical route |
