## 4. Performance principles
| Principle | MI210 gfx90a | Zen 5 |
|---|---|---|
| Unrolled loop, shared weights, per-visit KV/conv slots (no new op) | YES: graph-level, backend-agnostic; weights read 3x per token for core | YES: same; core weights (~1.0B params per extra pass) are re-read from DRAM each pass, 3-pass decode ~5.4B effective active (card) |
| Dense per-head F16 mask [n_kv,n_tok,24] + FA | PARTIAL: our CUDA/HIP FA returns NONE when mask->ne[2] != 1 (ggml/src/ggml-cuda/fattn.cu:591 @ eee3da8) so the biased FA is unsupported on gfx90a until a #32740-style port; falls to non-FA softmax path | PARTIAL: generic ggml CPU FA handles per-head masks (iq2%mask->ne[2], ops.cpp:9556/10067 @ eee3da8) but the iqk FA fast path refuses them (mask->ne[2] != 1, ops.cpp:10390) and refuses sinks unless GGML_IQK_FA_SINKS=1 -> Inkling would run the slower generic kernel |
| Bias table projected once, gathered by distance (get_rows) | YES (gather is memory-bound, any GPU) | PARTIAL: get_rows + cont(permute) + add + cast = ~7.5 F32-sized passes over n_kv*n_tok*24 elements (own count from the ops); DRAM-bound at prefill, cache-resident at n=1 |
| Short-conv recurrent state alongside KV | YES (small state, 3 history cols) | YES |
| SWA 1024 on 40 of 48 visits | YES (mask only n_kv_swa wide; bias mask small) | YES |

Derived numbers (my arithmetic; elements = n_kv x n_tokens x 24 heads; F32 4 B, F16 2 B):
- ub=512: 32k ctx F32 bias 1.50 GiB, F16 mask 0.75 GiB; 128k ctx F32 6.00 GiB, F16 3.00 GiB. ub=2048 at 32k F32 6.0 GiB; at 128k F32 24 GiB.
- Decode n=1: 32k F32 3.0 MiB (F16 1.5 MiB); 128k F32 12 MiB (F16 6 MiB) per full visit; x8 full visits. Verify batch n=8 at 128k: 96 MiB F32 per full visit.
- Per-token mask-build traffic (~7.5 F32 passes x 8 full visits): 32k ~190 MB/token, 128k ~750 MB/token, independent of ub. Compare per-token KV read at f16: 1.0 GiB (32k) / 4.0 GiB (128k) (inkling2card dive) plus weights (~3.4B-5.4B active). So at n=1 the mask build adds about 3% (32k) to 10% (128k) of bytes, and the 12 MiB buffers fit L3 so real cost is lower; at an 8-row verify batch the mask traffic is per-row and approaches the KV+weight bytes (~6 GB mask vs ~4 GiB KV + weights at 128k). Prefill at 128k ub512: ~360 GiB of mask traffic per ubatch, DRAM-bound. Time = traffic / effective bandwidth; no bandwidth measured here, so no tok/s claimed.
