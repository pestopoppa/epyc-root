"Inkling 2 DSpark is a different drafting path: an RNN head with recursive state, not a Markov head." — CONFIRMED by the author. anchor: claim_index 1, file page.txt, locator "reply to ggerganov on llama_decode_dspark_head", quote: `Because it's a recursive head, not a Markov head like the other DSpark drafters.` Code: `dspark_recurrent_step` (gate = sigmoid, cand = tanh, state = cand + gate*(state-cand), output tanh) is now shared with the existing Markov head, and `inkling2_head_step` adds lm_head applied to hidden plus lm_head applied to the correction latent, F32 precision, final-logit tanh softcap. anchor: claim_index 1b, file diff.txt, locator "src/models/dspark.cpp", quote: `static ggml_tensor * dspark_recurrent_step(ggml_context * ctx, const llama_model & model,`.
2. Hidden-state taps — CONFIRMED and now source-exact. The target graph records `res->t_layer_inp[visit++] = cur;` at the input of every layer VISIT (looped arch increments `visit` through all 48), and `t_layer_inp[n_layer]` is the final normed state. The drafter loads `dspark_fuse` of shape {n_targets, n_layer+1} and, per drafter layer row, takes a softmax over the target features and sums them (`mix_target_features`), then RMS-norms. With config target_layer_ids [5,23,41,48] those are inputs to visits 5, 23, 41 and the final normed state at 48 (config from the model card dive). anchor: claim_index 2, file diff.txt, locator "src/models/inkling2-loop.cpp hunk @@ -80", quote: `res->t_layer_inp[visit++] = cur;`.
3. Drafter block layout — CONFIRMED. Block of 8 positions: anchor token embedded with the TARGET's tok_embd + tok_norm, the other 7 rows are a learned mask embedding; requires a matching Inkling2 target (n_embd, tok_norm, output rows). anchor: claim_index 3, file diff.txt, locator "build_inkling2_embd", quote: `Inkling2 DSpark requires a matching Inkling2 target`. Per-position head runs INSIDE the graph (unrolled over n_outputs, single sequence): greedy = lowest-id argmax emulated via step/rank trick; temp>0 = in-graph draw using F32 cumsum ticket arithmetic and emitting the dense proposal row q. anchor: claim_index 3b, file diff.txt, locator "build_inkling2_block", quote: `GGML_ASSERT(ubatch.n_seqs_unq == 1 && n_tokens == hparams.dflash_block_size && n_outputs < n_tokens);`. So the per-position recurrent steps are serial inside one graph (7 head steps), not a parallel one-shot like the DFlash backbone.
