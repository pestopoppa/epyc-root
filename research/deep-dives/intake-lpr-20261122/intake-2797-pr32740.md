## 4. Performance principles

| Principle | gfx90a (MI210) | Zen 5 |
|---|---|---|
| Feature bit as template parameter (`if constexpr`), separate instantiation | YES, and more important on gfx90a. Our served decode kernel is `flash_attn_ext_vec` (`rocm-kernel-authoring.md:2618 @ 860023c`), and VGPR count sets occupancy in wave64 steps (cap 256, plus AGPRs). A +21 VGPR step can cross an occupancy boundary. | PARTIAL. On CPU the equivalent is hoisting the branch out of the inner loop or compiling separate variants. AVX-512 register pressure (32 zmm) is analogous but there is no occupancy cliff. |
| Compact indexed bias (table [bins, head, token] + int32 bin index per key/query) instead of a dense per-head F16 mask | PARTIAL. Same kernel code compiles for HIP. realugbun puts the byte break-even with the dense mask at about 2K context. The gather is one `uint32` index load plus one table load per KQ element, the same on HIP. | NO port. The CPU backend refuses the op (`supports_op` returns false) and the graph falls back to the dense bias mask. |
| Bins-fastest layout (native mul_mat output, no permute) | YES. A contiguous bin gather and one fewer `cont(permute)` pass are layout-independent wins. | YES for the fallback path in principle, but it is upstream graph code, not ours. |
| ncols2 = 1 for per-Q-head bias (no GQA packing) | YES, it is required for correctness. The cost is that K/V tiles are reloaded per Q head, so for GQA models this gives up the packing our H10 verify kernel relies on. | N/A |
| Biased FA never takes the MMA path | PARTIAL. On gfx90a the MMA path is the MFMA build of `fattn-mma-f16.cuh` (`amd_mfma_available`). With a bias, prefill and verify batches (nq 2-16) run on the non-MFMA tile kernel. Throughput relative to MFMA is unmeasured. | N/A |
| Disable mask scan (`scan_mask`) when bias present | YES; it is just control flow. | N/A |

## 5. In-house state (champion eee3da8)

- **Model**: `src/models/` has no `inkling*` file, so we have neither Inkling nor Inkling 2 graph code, and no `attn_rel_bias`.
- **Bias support in FA**: none. Our FA has sinks (`src[4]`). Our `src[5]` and `src[6]` are taken by AK-ASM-H12 (top_k, base mask; `qsa-sparse.cu`, commit `ba5a0c6cd`). Upstream puts kv_rows in `src[5]` and this PR adds table/indices in `src[6]`/`src[7]`. A port would collide on `src[6]`, and H12 rejects any extra source from index 7 up. Op_param slot 5 is free in our tree (slot 4 is `n_seq`).
- **Kernels**: our `fattn-tile.cuh` and `fattn-vec.cuh` are the same generic kernels and do compile for HIP. Selection order on gfx90a is in `fattn.cu:595-700 @ eee3da8`: H10 GQA_VERIFY (hd256, nq 2..16), then rows-are-seqs vec, then the CDNA D=256 MFMA tune, then MFMA MMA crossovers, then tile/vec.
- **Register tooling**: research `scripts/kernel_rnd/gfx90a_isa_audit.py` recognises the families `fattn_vec` and `fattn_tile` (lines 497-500). But `DEFAULT_FAMILIES = ("mmq", "mmf", "fattn_mma", "fattn_wmma")` (line 72), and the hard pre-timing gate INF03-REGAUDIT-2 calls `--families mmq,fattn_mma,fattn_wmma,mmf` (`rocm-kernel-authoring.md:2240-2241 @ 860023c`). So the served decode kernel (`flash_attn_ext_vec`) is outside the default register gate. That is exactly the class of regression this PR's comment measured.
- **Inkling relation**: intake-941's measurement (graphs reused = 0, banded rel-bias/shortconv path) concerns first-generation Inkling (`intake_index.yaml:58487 @ 860023c`).
  - This PR touches the Inkling 2 reuse check: it removes `self_rel_pos->ne[0] == get_n_kv()` from `can_reuse` and switches to `can_reuse_attn_mask`.
  - That plausibly lets an Inkling 2 graph be reused across n_kv changes.
  - No commenter measured graph reuse, so the intake-941 reuse defect is NOT shown fixed: NOT-FOUND-IN-SOURCE.
  - anchor: claim_index 6, file diff, locator "src/llama-graph.cpp llm_graph_input_mem_hybrid_iswa_rel::can_reuse", quote: `- res &= self_rel_pos->ne[0] == attn_ctx->get_base()->get_n_kv();`
