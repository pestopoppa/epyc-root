## 2. Key claims
1. Loss per follow-up = previous answer length + 4 tokens. CONFIRMED (as reported). Anchor: file page.txt, locator "Problem description", quote: "In live traffic the loss was consistently the answer length plus four tokens"; also "16,791 lost where the answer was 16,787".
2. Cause: accepted draft tokens are inserted in one block, the stop-token walk returns early, the 1-2 accepted tokens after EOG stay; hybrid memory cannot trim, falls back to a checkpoint; checkpoints only made during prompt processing so newest is 4 tokens before end of previous prompt. PARTIAL (mechanism is self-diagnosed from code reading; log excerpt shows f_keep 0.993 and "restored context checkpoint (pos_min = 46 ...)"). Anchor: "checkpoints are only created during prompt processing".
3. draft-mtp specific, ngram-mod does not produce the tail. CONFIRMED on that rig (tiny n: 2 of 4 rounds vs 4 of 4). Anchor: "So it is draft-mtp specifically. ngram-mod does not produce the tail."
4. Second seq_rm after the walk aborts (recurrent snapshot index single-use, "partial rollback REFUSED: rollback=3, n_rs_seq=12"); cutting `accepted` at first EOG before n_rollback works. CONFIRMED as reported. Anchor: "Cutting accepted at the first EOG before n_rollback is computed works instead".
5. Fix result: tokens kept past turn 2 (9 of 9) -> 0 (19 of 19); previous answer reused 0 of 8 -> 12 of 13; decode 20.89/8.52 -> 21.17/8.48 t/s; acceptance 0.3347 (n=34) -> 0.3334 (n=27). CONFIRMED as reported, tiny n, no noise bars. Anchor: "before after tokens kept past the turn 2 (9 of 9) 0 (19 of 19) previous answer reused 0 of 8 12 of 13".
