## 4. Performance principles

| Principle | gfx90a (MI210) | Zen 5 |
|---|---|---|
| 16-byte vector mask loads (8 halves per thread, `int4`) | YES. gfx90a has 128-bit global loads (`global_load_dwordx4`). Only matters if we ever build a mask-to-index pass, and H12 does not need one. | PARTIAL. A 512-bit AVX-512 load already covers 32 halves. No CPU code path exists for this. |
| More loads in flight (`nload` loads × ncols1 queries per thread before use) | YES as a principle on HBM2e latency. Register cost rises with ncols1×nload (the PR cuts cpt to 16 at ncols1=8 for this reason). Needs a VGPR check under the 256 cap. | N/A, since hardware prefetch covers sequential mask scans. |
| row_count kept in a register instead of LDS | YES, a trivial saving. | N/A |
| Compaction staged through LDS (selection bytes, then warp prefix sum, then cross-warp offsets) | PARTIAL. wave64 means one `__popcll` per 64-bit word suits gfx90a. LDS use is `nthreads*nload` bytes, far below the 64 KB limit. The reviewer flagged a type-punned LDS read (uint8 array read as uint64). | NO. A CPU compaction would use VPCOMPRESSD, not LDS. |
| combine_results 8-way unroll over parallel_blocks (HIP only) | YES technically, on any HIP target. See ledger: our served decode combine tail was already measured as a near-zero lever. | N/A |
| Gather-cost break-even (CDNA: when `n_kv_max > n_kv/4`, require `2*nq*n_kv_max <= n_kv`; otherwise `nq*n_kv_max <= 4n_kv` or `8n_kv`) | PARTIAL. Tuned on gfx908 (wave64, no packed-FP32, different L2) and carried unchanged to gfx90a. Usable as a prior, not as a threshold. | NO. CPU sparse is a separate DROP_QUALITY track (LSA-CPU-SPARSE-E2E). |
| Sparse tile pins ncols1=1 and uses ncols2 = all Q columns (GQA heads) | PARTIAL. The tile kernel is the non-MFMA path. On gfx90a it competes with MFMA MMA and our H10/H12 kernels. | N/A |

## 5. In-house state (champion eee3da8)

- **Upstream sparse-FA infrastructure: ABSENT.** Nothing in `ggml/src/ggml-cuda/` contains `n_kv_max`, `compact_mask` or `shall_use_sparse`.
- **Op-param collision.** Our FA op_params slot 4 holds `n_seq` (`ggml.c` `ggml_flash_attn_ext_set_n_seq`: "scale, max_bias, logit_softcap, prec are on positions 0..3"). Upstream uses slot 4 for `n_kv_max`.
- **Source-slot collision.** Our QSA path puts top_k in `src[5]` and the base mask in `src[6]` (commit `ba5a0c6cd`). Upstream uses `src[5]` for kv_rows, and the sparse gate rejects any `src[5]`.
- **Superseding in-house kernel: AK-ASM-H12** (`ggml/src/ggml-cuda/qsa-sparse.cu:454-600 @ eee3da8`, hooked at `ggml-cuda.cu:2531-2532 @ eee3da8`).
  - It recognises the Qwen4exp (Q38FN) QSA mask chain `fill(-inf) -> set_rows(top_k) -> add(kq_mask) -> FA`.
  - It gathers K/V rows directly from the top-k indices with GQA packing, so there is no mask scan and no compaction kernel. The workload this PR speeds up is skipped entirely.
  - Scope: hd256, f16 or q8_0 KV, G ∈ {1,2,4,8,12,16}.
  - Dispatch: fuse only when `n_kv >= 8*width` (`GGML_CUDA_QSA_SPARSE_MIN_KV_RATIO`, default 8). The commit `ba5a0c6cd` message records 0.78-0.94x at n_kv/width 4 and 2.2-4.6x at 16. The band between 4 and 8 was never measured, and `kernel-champion-and-promotion.md:399 @ 860023c` flags MIN_KV_RATIO=8 as chosen post hoc.
- **combine_results**: our version (`fattn-common.cuh:1299-1350 @ eee3da8`) has the plain `for (int l = 0; l < parallel_blocks; ++l)` loop, without the HIP unroll.
- **Arch macros**: as in C0. `GGML_CUDA_CC_IS_GCN` is `cc > OFFSET_AMD && cc < CDNA1` (`common.cuh:91`), which excludes all CDNA.
- **Served-path reachability.** On gfx90a, Q38FN QSA layers reach H12 before FA kernel selection runs. Dense layers go through H10 GQA_VERIFY or the vec kernel (`fattn.cu:595-599 @ eee3da8`). A port of #32741 would therefore never be reached by the QSA shape while H12 is enabled.

## 8. Contradiction / adversarial pass

1. `ggml_cuda_flash_attn_ext_tile_shall_use_sparse` does not check `logit_softcap`, but `..._may_use_sparse` refuses softcap.
