## 4. Performance principles
| Principle | MI210 | Zen 5 |
|---|---|---|
| Chunk the mask build to bound transient F32 buffers | YES: bounds HBM use (64 GB; 200k ub512 master 19.13 GiB) | PARTIAL: RAM (1.1 TB) is not the constraint; a 32-row chunk at 128k is 131072x32x24x4 B = 384 MiB F32, larger than L2/L3, so no cache benefit; DRAM traffic about unchanged |
| Single per-head F16 mask, broadcast-copied once per layer | YES | YES (F16 mask feeds generic CPU FA; iqk path refuses per-head mask and sinks) |
| Sequence chunks with ggml_build_forward_expand to force order | YES | PARTIAL: CPU graph runs ops serially with threads per op; ~5 ops x <=32 chunks x 8 full visits = up to ~1,280 extra small ops per ubatch to schedule (own count) |
| set_rows into a view of the mask | YES | YES: CPU set_rows F32->F16 supported (champion has ggml_set_rows) |

## 5. In-house state: none of the Inkling graph exists in eee3da8. Relevance to CPU-only serving where FA-with-bias is refused: the CPU runs FA with a materialised per-head F16 mask, so #32752 is the memory/traffic shape the CPU would actually run. It doesn't change CPU bytes much (edwardyoon), and RAM is not scarce (1.1 TB), so its value to us is small; the in-kernel gather (CPU analog) is the real lever and does not exist on CPU. Note also that the mask is rebuilt every ubatch and every full visit (8x) with identical content for passes using the same physical layer? NO: rel_bias differs per physical layer (table depends on each layer's R and weights), so no cross-visit sharing; the 3 passes of layers 11 and 17 each have own Rcur through different message-mixed inputs, so bias is per visit. (Derived from build_layer in #32694: Rcur = attn_rel(inputs[0]) and inputs differ per pass.)
