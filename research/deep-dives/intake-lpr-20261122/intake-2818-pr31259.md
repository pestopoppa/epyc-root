## 2. Key claims

**C0. What runs on gfx90a: only the DKQ=576/DV=512, ncols1=1, ncols2=16 sparse MFMA variant (DeepSeek MLA). Head size 256 is never selected.**
Verdict: CONFIRMED, and this verifies the #27970-dive statement.
- The host gate `shall_use_sparse` returns false on `amd_mfma_available(cc)` unless `may_use_sparse(Q->ne[0], V->ne[0], 1, 16)` holds. That is true only for (576,512,1,16).
- `ggml_cuda_get_best_fattn_kernel` forces MMA_F16 for that case, and `switch_ncols2` routes it to `switch_ncols1<576,512,16>`.
- Device side, the MFMA guard now lets `DKQ > 256` through when `use_sparse` is set, even though ncols < 32.
- One finer point for gfx90a. At the merge, `may_use_sparse` also lists (256,256,1,8) and (256,256,8,8), which come from #28770.
  - Under MFMA, (1,8) is `NO_DEVICE_CODE`, because `ncols1*ncols2 = 8 < 16`.
  - (8,8), with ncols = 64, does compile into the gfx90a binary, but the host gate never selects it.
  - A downstream fork confirms the kernel gets built on HIP. Its build budgets a "sparse-gather D256 8x8 kernel", and on gfx1151 it had 26 SGPR spills.
- This is unchanged on upstream master `e300919cc` (2026-11-22): `fattn.cu:145-146` still has the "only DKQ=576" gate.

**C1. Wave64 port of the mask-to-index compaction kernel.**
Verdict: CONFIRMED.
- `warp_size` comes from `ggml_cuda_get_physical_warp_size()`, which is 64 on gfx90a.
- The lane mask type is `uint64_t` on wave64. The ballot uses a full-width mask, and the count uses `__popcll`.
- With 256 threads there are 4 warps, so `warp_offsets` is 4 ints.
- For HIP before 7.0, `hip.h` maps `__ballot_sync(mask, var)` to `__ballot(var)`. Our MI210 runs ROCm 6.x.
- Anchors:
  - claim_index 1, diff, `fattn.cu @@ flash_attn_mask_to_sparse_indices`: `using lane_mask_t = std::conditional_t<warp_size == 64, uint64_t, uint32_t>;`

  - claim_index 1, diff, `vendors/hip.h @@ -254`: `#define __ballot_sync(mask, var) __ballot(var)`

**C2. Threshold: on AMD the activation floor is `K >= max(4096, 2*n_kv_max)`, independent of batch. NVIDIA keeps the batch-aware `2*n_gather`.**

## 4. Performance principles

| Principle | MI210 gfx90a | Zen 5 |
|---|---|---|
| Wave64 ballot plus `__popcll` prefix compaction | YES. Correct for wave64. Only useful if we ever need a mask-to-index pass, and H12 does not: it consumes top-k indices directly. | NO. A CPU equivalent would be VPCOMPRESSD. |
| `__ballot_sync` → `__ballot` shim before ROCm 7 | YES, but there is a hazard. It drops the mask argument, which is unsafe where partial-warp masks matter (the author's ROCm 6.3/6.4 note). Our H12 uses no `__ballot_sync` (git grep in eee3da8 ggml-cuda finds none). | N/A |
| Sparse MFMA 576/512 at ncols1=1, ncols2=16 (16 heads × 1 query per tile) | PARTIAL. It applies only to DeepSeek-MLA-shaped models. We serve none on GPU. | N/A |
| Batch-blind floor `K >= 2*n_kv_max` on AMD | NO as a rule for verify batches. The ncols1=1 sparse path gathers one list per query, so 16 verify rows read 16×n_kv_max rows, while dense reads K once per tile. NVIDIA uses `2*n_gather` for exactly this reason. Our H12 r4 data (loses at n_kv/width=4 for nb=16) shows that a batch-blind 2x floor would be far too permissive on gfx90a. | N/A |
| Large-head MFMA allowed at small ncols when sparse | YES technically: gfx90a has 64 KB LDS and MFMA. The VGPR exception list was extended for the 576/512/1/16 sparse kernel, which signals register pressure near the cap. | N/A |

## 5. In-house state (champion eee3da8)

- **Absent.** The champion lacks #27970 and every follow-up (no `n_kv_max`, `compact_mask` or `shall_use_sparse` in `ggml/src/ggml-cuda`). #31259 cannot be applied on its own, because it edits code that #27970/#28770/#29298 introduced.
- **The served path does not reach it.** Q38FN QSA layers (hd256, GQA 12) are captured by AK-ASM-H12 (`ggml/src/ggml-cuda/qsa-sparse.cu:454-600 @ eee3da8`) before FA kernel selection. Even after a full upstream fold, the #31259 gate would refuse hd256 on gfx90a and fall back to dense FA.
- **The `__ballot_sync` shim is absent.** Our hip.h has no mapping, and no ggml-cuda file in eee3da8 calls `__ballot_sync`. A fold of #31259 imports it. Upstream #31617 later refactored it.
- **Fold cost, if folded as part of the #27970 → #28770 → #29298 → #31259 chain:**
  - Small in `fattn.cu`, `fattn-mma-f16.cuh` and `hip.h`.
  - It adds a compiled (576,512,1,16) sparse kernel and a compiled but unused (256,256,8,8) sparse kernel to the gfx90a fatbin, which increases code size.
  - There is a VGPR-check script entry for the new symbol.
  - The real cost is the slot-4 and `src[5]` collisions described in the #27970 dive, not this PR.
