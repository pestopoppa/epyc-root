## 2. Key claims

1. **"VGPR 6 -> 4, ISA 29 -> 26, rank calculation 5 -> 2 instructions"** — CONFIRMED as author-reported (anchors 0, 1, 2). The kernel is not named, no GPU is named, and no compiler version is given; the table does say "Wavefront size 64" (anchor 3), so the target is a wave64 AMD GPU, plausibly gfx9 but not stated. The legacy listing is 5 VALU ops (`v_lshlrev_b64`, two `v_bfi_b32`, two `v_bcnt_u32_b32`); the new listing is `v_mbcnt_lo_u32_b32` + `v_mbcnt_hi_u32_b32` (anchor 4).
2. **mbcnt semantics on wave64** — CONFIRMED correct. `ballot_rank(mask, lane)` on HIP is `mbcnt_hi((u32)(mask >> 32), mbcnt_lo((u32)mask, 0))` (anchors 5, 6). `v_mbcnt_lo(m, c)` counts set bits of `m` strictly below the lane within lanes 0..31 (all 32 bits for lanes >= 32); `v_mbcnt_hi` continues for lanes >= 32. Together they equal `popc(mask & ((1 << lane) - 1))` for lane = physical lane id 0..63. The 64-bit mask returned by HIP ballot is split correctly. The helper ignores its `lane` argument on HIP and the code comment states the precondition: the caller's `lane` must be the physical lane in the wave (anchors 7, 8). The three call sites pass `threadIdx.x` (mmid.cu) or `lane`; whether `lane == threadIdx.x % 64` holds in each kernel was NOT verifiable from the diff (fattn.cu and top-k.cu derive `lane` elsewhere), so correctness at those sites rests on the author.
3. **Scope / predicate** — CONFIRMED: `#if defined(GGML_USE_HIP)` with a `static_assert(sizeof(ggml_cuda_thread_mask_t) == 8)`; non-HIP keeps `popc(mask & (((mask_t)1 << lane) - 1))` (anchor 9).
