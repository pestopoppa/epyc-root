## Vision (ratified 2026-09-24)

> **A permanently resident speech-native interlocutor hears, interprets and speaks. It has one external tool, the
> orchestrator, which supplies the cognition. Preserve speech-native state locally; export only the cognitive problem.**

```
                 ┌──────────────────────── SPEECH PLANE ─────────────────────────┐
 audio in ──────▶│ VOICE CONTROLLER (model-agnostic; lives in epyc-orchestrator) │
                 │  VAD · turn detection · barge-in · session · routing policy   │
                 │  context budget · degraded mode · event log                   │
                 │        │ Interlocutor backend interface (pluggable)           │
                 │        ├─ candidate: Step-Audio 2 mini   (bake-off lead)      │
                 │        ├─ candidate: Qwen3-Omni-30B-A3B  (bake-off challenger)│
                 │        └─ cascade: whisper :9000 → (text) → qwentts :9002     │
 audio out ◀─────│           (baseline + permanent fallback)                     │
                 └───────────────┬───────────────────────────────────────────────┘
                                 │ ONE tool: the voice-turn contract (streaming)
                 ┌───────────────▼──────── COGNITION PLANE ───────────────────────┐
                 │ ORCHESTRATOR: reasoning · retrieval · web · code · memory ·    │
                 │ tools · model routing. Replaceable without touching speech.    │
                 └────────────────────────────────────────────────────────────────┘
```

The interlocutor and the orchestrator split the work like this.
- **The interlocutor** hears, reads the paralinguistic signal, handles timing and turn-taking, gives social and backchannel responses, and decides the delivery.
- **The orchestrator** remembers, reasons, retrieves, calculates, writes code, searches and acts.
- **The orchestrator never takes over the conversation.** It returns the substance, and the speech plane decides how that substance is spoken.

## Accumulated insights — 2026-10-20 (for Phase 2 / D1 when the second MI210 is installed)

Added 2026-10-20 at the operator's request ("bake tonight's work into the handoff/vision so that we can pick it up when the time comes with our accumulated insights"). This section adds to the ratified Vision and D1–D8; it changes none of them and no task text. Every bullet points to the note, artifact or commit it came from.

**Turn detection (CS-22, CS-47)**
- CS-22's text calls semantic end-of-turn "optional" and names a silence threshold as the policy. The evidence below points toward a semantic-gated design (a probability or acoustic model decides complete vs incomplete, silence only gates it) as the candidate default. This is a design insight, not an edit to CS-22. Pointers: CS-47 findings (Smart Turn behind the Silero gate is the only arm that moved the false-cut rate); the Unmute reference, whose end-of-turn is a model pause head thresholded 0.6 / 0.4 rather than a silence timer (intake-2054#record); M10 (further end-of-turn models) in the durable triggers below.
- CS-47 synthetic results (CS-47 accuracy-legs note, research `artifacts/cs47_turn_end_bakeoff_20261020/`): the incomplete clips carry 2.0 s of trailing silence, so every silence-gated or acoustic arm fires on nearly all of them (silence 1.000; Parakeet-EOU 0.972 to 1.000, including the no-fallback rows). Smart Turn discriminates a little (gate 0.6 theta 0.9: false-cut difference -0.333 vs the nearest-latency silence row, paired CI [-0.515, -0.181]) but selection-only extension to FPR <= 0.10 costs recall <= 0.017. Parakeet-EOU ties its matched silence row at 0.000 difference. No arm meets the 0.10 FPR budget on selection; no arm advances.
- Adaptive-arm results (CS-47 addendum A, research `0d495b8fc`, offline re-score, synthetic stratum only; ranks and rejects, cannot advance): no semantic-gated adaptive variant yields a usable operating point. The only FPR-feasible Smart Turn + Silero point (theta 0.99, gate 0.4, T_short 0.5, T_long 2.5) has confirmation recall 0.296, EOT FPR 0.000, INT FPR 1.000 and reaches FPR 0 by never answering (100% of incomplete clips censored never-fired, 0% of complete clips answered within T_short); Parakeet-EOU adaptive equals its no-fallback rows (EOT FPR 1.000). The 2.0 s digital tail means any T_long >= 2.5 s arm cannot fire in-clip, so this stratum cannot test those arms (follow-up CS-45.1).
- Only the `human_recorded` stratum can advance an arm, and it is EMPTY (CS-4 sets 2 and 5 are not recorded): `corpus.json` keeps `advance_eligible_strata = [human_recorded]` (CS-45 note; `docs/reference/speech/turn-taking-measurands.md` §0 rule 3). Recording it is the gating input for every turn-end decision.
- Latency leg: the per-decision CPU cost half ran 2026-10-20 on a LOADED host (CS-47 addendum B, research `0d495b8fc` `latency_now/`; contended, one pass, no A/A pair): criterion (c) CPU p95 <= 100 ms PASSES for every arm at 1 core (worst 43.4 ms) and at 4 cores Parakeet fp32_fp32 160 ms (86.1 ms) is BORDERLINE and Smart Turn (79.1 ms) is at the edge; those two 4-core rows are queued for a quiet-host re-run with the staged script (`artifacts/cs47_turn_end_bakeoff_20261020/scripts/latency.sh`, CS-47 note). Signed latency in the accuracy legs is stream time of the first fire minus gold EOT with no compute lag added; model-only latency is separated from any wrapper gate (measurands §2.2).

**Speech kernels**
- Thread study (CS-45 qwen-tts thread-scaling follow-up, `artifacts/qwentts_threads_20261020/`): `ggml_barrier` (`ggml-cpu.c:575`) is a pure `_mm_pause` spin and qwen-tts builds a disposable pool per graph compute, so one descheduled thread stalls all N. On a quiet region 8 threads is about 4x faster than 1 (38.3 vs 94.4 ms/frame); with 8 spinners on 8 pinned cpus it reaches 9754 ms/frame. The trigger is core sharing, not thread count. Recommendation recorded there: N threads only on cores nothing else runs on, otherwise one thread per process.

  - Partitioning the LLMs to `-t 56` on cores 40-95 restores STT, leaves TTS marginal, and costs the LLM 22–26%. **The frontdoor under that partition was never measured.**
- **No free physical core.** Even correctly pinned GPU host threads degraded the CPU A/A floor from 0.80% to 7.22%.
