## 2. Why do no full/half endpoints exist in the live lineup?

**Short answer: the launch drop was deliberate and explicitly wired; the surviving full-port references are acknowledged debris under active cleanup; and the "2 halves per role" shape the operator recalls was never a production configuration at all.**

### (a) Deliberate decisions (with citations)

1. **The v7 cutover relaunch was an explicit quarter-mode choice, not an accident.** Orchestrator commit `ff4b3766` "Wire v7 quarter stack runtime" (2026-07-20 14:43) set and propagated `ORCHESTRATOR_STACK_NUMA_MODE=quarter` through the runtime-facts manifest; the 13:55 relaunch started quarter mode (8072's log ends with a clean shutdown at ~13:50). The promotion gate was run *in* quarter mode (183 passed) and tests were deliberately updated so quarter-mode validation "no longer fails on hard-coded full-mode ports" (`progress/2026-07/2026-07-20.md:1794-1820`; `v7-promotion.md:37`, "21/21 smoke").
2. **The rationale was ratified the next day as a standing contract.** The operator-authored DESIGN CONTRACT (2026-07-21, `within-role-placement-state-machine.md:382-393`): the big instance exists for single-request max throughput only; **full/half and quarters are mutually exclusive operating modes** — burst ABANDONS the big instance; frontdoor's old 3-way mix was "a geometric accident, NOT the contract."
3. **worker_general's full was placement-hard-disabled by operator grant.** DISPATCH-A `99dd6c92` (2026-07-21): `placement_policy: "full_disabled"` with in-code rationale "quarters-only is the correct static mode until an operator redeploys a real full instance" (`stack_numa.py:173-184`).
4. **The absence was then hardened into the control plane.** ESC-8 (2026-07-22, `1de3cef9`/`5aa29f35`): cold-start default flipped full→quarter, priors compile refuses to default full, lineups referencing dead 8070/8072/8085 rejected. WP-13 (`d8b7e0bd`/`6dc2e2b4`): live role priors records recompiled quarters-only. Independent confirmation: `wp9-wp10-lineup-event-prep.md:33` — "The half/full instances 8070 / 8085 / 8072 are NOT launched (consistent with full_disabled / mode-exclusivity)."
5. **The throughput basis predates the cutover.** J5 (2026-05-26): frontdoor quarter pairs scale 1.37-1.67×; worker_general 1.54-1.89× aggregate; certified re-bench worker ALLOW 1.34-2.04×. The dual-half experiment measured *negative* (co-run ratios 0.455/0.524/0.541 — "each half HALVES under concurrency → aggregate ≈ serial"; `progress/2026-05/2026-05-26.md:844-847`).

**Honest caveat (per handoffs reader):** no single dated document says "we hereby stop launching 8070/8072/8085." The decision is assembled from (1)+(2)+(3); the formal ratification postdates the launch change by one day. It is nonetheless clearly intent, not drift — the launch, gates, tests, defaults, and priors were all aligned to it within 48 hours.
