  - No commit ever defined those functions, so they were never moved or renamed. They never existed.
  - They were the only 4 unresolvable handlers among the 45 python entries.

  - The YAML now carries a comment recording this reasoning.
- **Test.** `tests/unit/test_tool_registry_handlers_resolve.py` checks three things:
  - every python handler imports and is callable;

## 3. Decision package — install kuzu into the production venv? (NIB2-78b)

**Context.**

- Graph scoring has never run in production.
- The failure and hypothesis graphs are empty, so turning scoring on adds no learned signal on day one. It only
  starts accumulating.
- Upstream `kuzudb/kuzu` was **archived 2025-10-10**. 0.11.3 is the final release, MIT-licensed, with manylinux
  cp311 wheels.
- **Kuzu takes an exclusive per-file lock, even for `read_only=True`** (verified). With 6 uvicorn workers, the
  first worker to start owns the graphs and the other 5 fall back.
  - Graph-enhanced scoring would therefore depend on which worker serves a request.
  - While the API runs, `seed_graphs.py` and canvas export could not open the files.

**Exact install command** (next stack window, API stopped):

```
uv pip install --python /mnt/raid0/llm/epyc-orchestrator/.venv/bin/python 'kuzu==0.11.3'
```

or, equivalently, from the repo: `uv pip install --python .venv/bin/python -e '.[graph]'`. The editable form
re-resolves the whole project, so prefer the pinned single-package form.

**Options.**

| Option | Gain | Cost / risk |
|---|---|---|
| A. Leave dormant (recommended now) | No change. The log is already a single WARNING line per worker. | Graph tools stay inert, as they have always been. |
| B. Install as-is | 1 of 6 workers gets graph scoring and begins filling the graphs. | Routing varies by worker; new code paths go live at once; depends on an archived package; Kuzu file locks block tooling while the API runs. |
| C. Install after NIB2-78c (single-owner graph process) | Consistent scoring across all workers. | Design and implementation work first; still an archived dependency, unless a maintained fork is adopted. |

**Recommendation.** Take **A** now. Choose **C** if the graph layer is wanted.

- **B** adds routing behaviour that differs between workers, which confounds autopilot and eval measurements.
- The install itself is low-risk: one self-contained wheel, no transitive dependencies, and a verified-compatible
  storage format.
- The risk lies in what the install enables.
