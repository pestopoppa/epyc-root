## Verdict: GPU-only is feasible

The reader is **Qwen3-VL-30B-A3B-Instruct Q4_K_M + `mmproj-…-F16`**. It is the production
`worker_vision` model, which makes it "a reader we actually serve".
- **Champion support**: `ef81196d5` (`/mnt/raid0/llm/tmp/fold-ef81196d5-src`, build 10301,
  `GGML_HIP=ON`) has `PROJECTOR_TYPE_QWEN3VL` and `tools/mtmd/models/qwen3vl.cpp`.
  `libmtmd.so.0.0.10301` contains qwen3vl symbols. The binary was built 09:25, after the 08:53
  commit, so it is not stale.
- **Backend**: `clip.cpp` has no backend-specific gate. It picks the GPU device (or
  `MTMD_BACKEND_DEVICE`), and unsupported ops fall back through the scheduler. The HIP lib
  registers the device name `ROCm`, so the flag is `--device ROCm0`.
- **Prior GPU evidence**: the same model already runs on the MI210. It won MMMU-250, and the KV
  A/B of 2026-08-02 measured VRAM at 21,049 MB at 65k ctx, with a prediction of 23.9 GB after the
  first request.
- **Token cost**: Qwen3-VL uses a 32 px cell (patch 16 × merge 2) with token bounds (8, 4096).
  Production passes `--image-min-tokens 1024`, so a 1568×1568 frame is 2,401 tokens.

  exact McNemar test on EM, and a pre-registered verdict: ratio ≤ 0.50 AND CI lower bound > −0.05.
- **Token accounting**: `usage.prompt_tokens` with `cache_prompt:false` and `--cache-ram 0`. The

## Review fixes (Fable MERGE-AFTER-FIX) — research `e2c48c13`

The branch is now `070db22a` → `2f053f61` (main session: port 18431 + SC85 sidecar) → `e2c48c13`.
1. **Pre-registration drift.** `report` now grades with `plan.json`'s `prereg`. If it differs from
   the code's `PREREG`, the run is VOID, `summary.json` carries the plan's `prereg` plus
   `prereg_code`, and no belief row is written. `run` refuses to start on drift.
2. **Malformed 200 bodies.** A body without `choices`, content or `usage.prompt_tokens` is an
   error. It is retried once, then stored as an error; resume retries it, and an unrepaired one
   VOIDs the run.
3. **Pillow.** `pillow==12.3.0` is pinned in the recipe, `plan.json.pillow_version` records it, and
   `run` refuses a mismatch.
4. **GPU residency.** `run` samples sysfs VRAM and `/sys/class/kfd/kfd/proc` in flight: at start,
   after each request, and every 2 s. The samples go to `residency_samples.jsonl` and
   `residency.json`. Proof needs at least 2 samples ≥ 16 GiB above a pre-launch baseline file plus
   a KFD context for `--server-pid`. Otherwise `report` VOIDs the run.
