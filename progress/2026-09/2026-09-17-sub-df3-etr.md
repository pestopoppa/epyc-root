## D-f3 — graph snapshot writers that never landed (repl-session-memory-maturity.md)

- **Defect**: two callers used a `save_checkpoint` signature the store never had:
  - `SQLiteStatePersistence._write` called `save_checkpoint(session_id=, data=, checkpoint_type=)`.
  - `helpers._log_state_snapshot` called `save_checkpoint(task_id, json, "state_snapshot")`.

  The real method is `save_checkpoint(checkpoint, *, fencing_token)`. The resulting `TypeError` was
  swallowed at DEBUG, so every graph and turn snapshot was lost. The turn snapshot runs whenever
  `STATE_HISTORY_SNAPSHOTS` is on and the API supplies a session store.
- **Commit**: `epyc-orchestrator` `f853764f`.
- **Why not `checkpoints`**: `get_latest_checkpoint()` is the REPL restore source, so a snapshot row
  would shadow the real globals checkpoint. The turn snapshot is also keyed on `task_id`, not a session
  id.
- **Fix**:
  - A new append-only `graph_snapshots` table, written by `save_graph_snapshot(run_id, data,
    snapshot_type, *, session_id, fencing_token)` and read by `get_graph_snapshots(run_id)`.
  - A session-scoped write runs D-f's `check_fence` inside the insert transaction.
  - `TaskDeps.session_id` / `session_fencing_token` are set by `_execute_repl` only while the turn holds
    the lease. Otherwise, including when the session is owned elsewhere, snapshots are run-scoped and
    unfenced.
  - `SQLiteStatePersistence` takes an optional `fencing_token`.
  - Both swallowed-error paths now log at WARNING.
- **Other callers**: a repo-wide grep found no other mismatch. `PersistenceManager.save_checkpoint(repl_env)`
  is a different API.
- **Tests**:
  - `tests/unit/test_df3_graph_snapshot_writes.py` has 9 cases, and 8 fail on the old code. They
    include an AST guard over every `save_checkpoint` call in `src/`.
  - The two adapter mock tests that asserted the broken call now assert the real writer.
  - The two D-f executor cases now pin the deps wiring (leased turn → `(session_id, 1)`; turn owned
    elsewhere → `(None, None)`).
  - Focused run: 170 passed after the rebase.
- **Follow-up filed**: D-f3a. The table has no reader or retention bound yet.
