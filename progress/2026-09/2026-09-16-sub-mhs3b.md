## What landed

One checker (`PromptForge._leakage_reason` → `eval_leakage_reason`) serves prompt, GEPA and code
mutations. It looks only at the ADDED text, and the reason string records the matched source.

- **`eval_content_ngram_overlap`**: a verbatim ≥8-token overlap with an eval row, or with the
  trace bank rendered into the proposer context.
  - The rows are the whole question pool (a superset of every draw), the core files and the
    sentinel YAMLs.
  - The trace bank is parsed from `failure_context`: MH-7 contrastive, MH-11 IR JSON and recent
    traces.
  - Index: hashed 8-token shingles, with the row id packed in the low bits (row_bits = 17 on the
    real pool), which leaves a 47-bit hash.
    - **Documented FP rate: ≈ N/2^47 = 1.3e-7 per looked-up shingle, about 7e-5 per 500-shingle
      mutation.**
    - Shingles present in ≥32 rows count as template and are dropped.
    - A hit must contain a rare anchor token (≥4 bytes, not numeric, pool tf ≤200) or sit inside a
      ≥15-token verbatim run.
    - Rows larger than 32 KiB (1,417 rows) keep their first and last 512 shingles exactly, with a
      width-16 winnow in between. Detection there is guaranteed for runs of ≥23 tokens.
- **`eval_expected_answer_leakage`**: a whole expected answer of 1–7 tokens.
  - The answer must be name-shaped (upper case, digit, underscore or non-ASCII) or, for a
    multi-word answer, unique (tf ≤2).
  - Answers shared by ≥32 rows are dropped. Numbers and placeholders are never indexed.
- **`eval_source_identity_leakage`**: each trace block resolves to question or sentinel ids,
  through explicit `qid`/`question_id`/`sentinel_id` fields, exact vocabulary ids, or ≥2 pool
  shingle hits. The mutation is refused when it shares ≥3 rare, non-harness tokens with that block,
  which also catches paraphrases.
  - The current trace-bank records carry no qid, so the pool-shingle route does the resolving
    today. Records that gain an id field are picked up with no further change.
- **`eval_suite_special_casing`** (the spec's "also refuses in-suite special-casing"): keyed,
  phrase and mention forms. It runs after the AP-33 checks, so their reasons keep precedence.
  Suite names the harness uses in ≥4 files count only in the keyed form.
- **Harness exclusion.** Shingles and tokens already present in the current prompts, in
  `src/**/*.py` or in the original file are never blamed. This corpus is cached by file identity.
- **Reuse, caching and fail-closed behaviour.**
  - The content index is built in the same row pass as `EvalIdVocabulary` and lives in the same
    cache (file identity), with the same 60 s negative cache.
  - `available` now requires the index. A missing index, a failed build or a crashed check yields
    `eval_leakage_vocabulary_unavailable:*`, so the preflight, the alarm and the observer all
    apply unchanged.
- **Runbook** § 7: new cost figures, a table of the four new reasons with their known
  false-positive classes, and the measured rates.

## Measurements (real pool, read-only)

**Cost**
- Build: 16.2 s cold, against 3.6 s before.
- Memory: RSS +590 MB for the process lifetime, against +253 MB before. The content arrays are
  173 MB (18.55M shingles) and the transient peak is 1.37 GB.
- Warm lookups: 0.2 ms. A small prompt edit costs 8.6 ms and a whole `chat.py` 280 ms.
- Harness corpus: 0.17 s cold, 3.4 ms warm.

**False positives.** For the whole-file measurements below, the harness was leave-one-out, so a
file never excuses itself.
- The 33 live targets:
  - A benign edit to each target: 0/33 refused. A regression test pins this.
  - Each target as a whole file: 0/33 content refusals. There are 5 special-casing mentions, all
    benchmark names already written into the files.
- 91 historical autopilot mutation commits, read from git:
  - Content refusals: **0/91**.
  - Special-casing refusals: 10/91. 8 of them are special-casing under the spec (suite-keyed
    `tool_policy`, "LeetCode/HumanEval/MBPP" prose, AIME routing, corrupted `frontdoor.md`
    commentary). 2 are borderline comment mentions (**2.2%**).
- 467 `src/` and `docs/` whole files: content-refusal false positives **11/467 (2.4%)**; the 8 in
  `src/` are exempt under the production harness. There were also 3 true hits and 20 suite
  mentions, of which about 6 are harness identifiers.
- Coverage: 1,998 of 2,000 verbatim pool prompts are refused, as are 172 of 174 qualifying
  verbatim answers.

**Tuning decisions, each backed by a measurement**
- Template df 8 → 32 raised coverage from 1,976 to 1,999 of 2,000 (duplicated debugbench
  descriptions), with the same false positives.
- The unanchored-run threshold went from 12 to 15 tokens, which removed a generic Java-loop
  false positive in `rules.md` at a cost of 1 in 2,000 coverage.
- Single-token answers must be name-shaped; this removed `contention`, `multiprocessing` and
  `canary`.
