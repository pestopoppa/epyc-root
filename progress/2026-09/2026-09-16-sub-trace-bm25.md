# 2026-09-16 — sub-trace-bm25

- **Bug**: in `epyc-orchestrator` `src/trace/query.py`, `query(text=...)` claimed bm25 ranking but always ran `ORDER BY ts_utc DESC`, so a limited FTS search returned the newest matches instead of the most relevant. The CME-4 memeval agent found it (research `ccc41d4b`). A failing test confirmed it: with `limit=1` the query returned the newest match, not the most relevant (older) one.
- **Fix**: orchestrator branch `sub/trace-bm25-20260916`, commit `6302b381`, worktree `/mnt/raid0/llm/worktrees/sub-trace-bm25`. This is pending integration.
  - Adds `order=None|"relevance"|"recency"`. The default is bm25 (via an `event_fts` JOIN, ranked before LIMIT) when `text` is given, and recency otherwise.
  - Asking for relevance without `text` raises `ValueError`.
  - `search_records(order=)` passes the option through. The CLI `query` and `search-records` commands gain `--order`.
  - `trial_context`, `decision_chain` and `get_conversation` now pass recency explicitly, with no behaviour change.
- **Callers**:
  - Callers that pass `text`: `navigation.search_records` / `search_conversation` (they wanted relevance, and RRF uses their rank order), and the CLI `query --text` / `search-records`.
  - Callers without `text`, which keep recency: `trial_context`, `decision_chain`, `get_conversation`, `scripts/analysis/tm8_coverage.py`, `scripts/analysis/reviewer_events_to_ledger.py`. Both scripts fetch every row and re-sort, so the order does not matter to them.
- **Tests**: new `tests/unit/test_trace_query_order.py` (10 tests). The trace, navigation, CLI, review-plane, tm8, ledger and parity suites pass: 94 passed, 1 skipped.
- **Affected results**: none.
  - The CME-4 retriever takes every match and re-ranks by `bm25()` itself, so its output is correct and does not need a re-run. It could be simplified once this fix lands.
  - UTM-B2/B4 and the CME-4 retrieved arm have not produced numbers.
  - No belief-kernel rows depend on trace search, so the vidya note was not needed.
- **Handoff note**: added to `handoffs/active/unified-trace-memory-service.md` (UTM navigation section).
