  - checks path arguments and recursive roots;
  - refuses `python`/`python3`;

- `run_python_code` is refused when its source literally names a fenced place.
- `doc_search` is refused.

## Kernel enforcement (operator directive; Fable re-review of 80fa99aa)

Merged `origin/main` (`a6796a6f`), committed enforcement as `0d3b6e26`.

The residual gaps (ctypes/libc, `sh -c` variable indirection) cannot be closed by pattern matching,
so an ARMED `run_python_code`/`run_shell` child now runs under a kernel restriction that every
descendant inherits. The hook and shell checks stay as the recording layer, and enforce under
`hook-only`.

**Enforcement, probed once per process:**
- **landlock** (unprivileged; the level active here, ABI 6). Allow-list: `READ_DIR` on `/` so names
  stay listable, `READ_FILE` on everything except the fenced dirs. Fenced file contents are
  unreadable by any route; names stay listable.
- **mountns**: unprivileged user+mount namespace, empty read-only tmpfs over each fenced dir and
  `/dev/null` over each fenced file.
- **hook-only**: no kernel layer; the row records it.

The child execs through a shim (`_fence_kernel_shim.py`) that applies `PR_SET_NO_NEW_PRIVS` +
`landlock_restrict_self` (or `unshare`+mount) before `execvp` and never falls through to an
unrestricted exec. The allow-set and roots config are cached per discovery TTL and passed as files.
Mount aliases (`/workspace` is a bind of `<llm>/epyc-root`) come from `/proc/self/mountinfo`. Each
checkout's `.git` is fenced, closing `git show HEAD:wiki/x`. Discovery: ~327 checkouts / ~1145
fenced dirs.

**Hook hardening (`_fence_audit_hook.py`):** closure-held state, private rules namespace with a
private posixpath, bootstrap names deleted after install. Armed, it refuses
`gc.get_objects`/referrers/referents, `sys._current_frames`, `sys.settrace`/`setprofile`, and any
watched event that re-enters the hook (monkeypatch tampering). It watches `os.link`/`rename`/
`symlink`/`chdir`, `shutil` copies, `os.fwalk` and fd-based `scandir`/`listdir` (fds via
`/proc/self/fd`). Under `hook-only` it also refuses `$`/backtick/glob/`cd`/`eval` in `sh -c`,
`-C`/`--chdir`, and ctypes file/exec/syscall symbol lookups. Denials are always recorded.

**`run_shell` tightenings:** awk `ARGV`/`ARGC`/`ENVIRON`; sed `r`/`R`/`w`/`W`/`e` without trailing
space, `s///w`, `s///e`; `ls --recursive`; tar/cp/rsync/zip/git/perl in the recursive-or-refuse set.

**Recording:** `fence_enforcement` per row, `enforcement_counts` in the trial summary,
`eval_fence_enforcement` in the journal tuple and the vidya adapter.

**Production:** an unarmed request installs no carrier, no wrapper and no config env; the python
launch is output-identical (golden test). One deliberate production change, restated from the
earlier commit: the tool ThreadPoolExecutor hops run under `copy_context()`, so a timed-out tool
thread now sees the request deadline, cancel flag and inference-tap context.

**Tests:** `test_ap54_eval_knowledge_fence.py` now 112. Under Landlock every reviewed leak (ctypes
libc open, `os.system $VAR`, `bash -c`/`-lc` eval, `env -C`, grep -r, tar/cp parent, git show, perl,
copied interpreter, dir_fd+listdir, hardlink, rename, `/proc/self/cwd`) is denied; stdlib/numpy/
`/tmp`/cwd keep working; the probe falls back when the syscall is mocked. Full `tests/unit`: 13,249
passed, 2 failed — `test_dashboard_helpers` and `test_config_consolidation`, both failing on clean
`origin/main` (they read live host config).

**Enforcement level on this host: landlock.**

**Residuals, only under `hook-only`:** `os.open(rel, dir_fd=)` and raw ctypes function pointers.

## Landlock write/execute widening (third review MERGE follow-up)

Committed as `3c2295f4`. The Landlock ruleset handled only `READ_FILE`/`READ_DIR`, so armed code
could still write, truncate, unlink or execute a fenced file through raw ctypes. The ruleset now
handles the full content set for the running ABI: read, write, execute, `MAKE_*`, `REMOVE_*`, plus
`REFER` (ABI>=2) and `TRUNCATE` (ABI>=3).

- Allowed directories (run dir, `/tmp`, site-packages, every non-fenced subtree) get all handled
  rights; allowed files get the file subset. Fenced dirs get nothing.
- Masks come from the live ABI (`landlock_access_masks`) and ride in the spec; the shim uses them
  and stays fail-closed. `--probe` and a maskless spec fall back to read-only ABI-1 masks.

**Verified denied under Landlock (no leak):** ctypes write, append, truncate, `os.truncate`,
unlink, and creating a new file inside a fenced dir. **Still working:** run-dir write, `/tmp` write,
a default `NamedTemporaryFile`, and numpy.

**Accepted residuals (documented in the fence docstring and handoff):** names stay listable
(`READ_DIR` on `/`); a fenced file in a volatile dir is hook-covered only; the allow-set TTL is
300 s; new-file creation directly in a container dir that also holds fenced data is denied.

**Tests:** fence suite 121; re-ran tool-registry / REPL / eval_tower_concurrency: 368 passed.
**Enforcement level here: landlock (ABI 6).**

## Inherited TMPDIR check (pre-merge)

Committed as `257731ba`.

**Finding:** the API process is launched with `TMPDIR=<llm>/tmp` (`orchestrator_stack.py` sets
`env["TMPDIR"] = _PATHS["tmp_dir"]`; `src/config/models.py` defaults `tmp_dir` to `$TMPDIR` or
`<llm>/tmp`). `/etc/environment` and the container env set none. `<llm>/tmp` also holds fenced
subtrees, so armed children inherited a TMPDIR they cannot create files in, and `tempfile` would
have failed. The cached spec/roots files, which used `tempfile.gettempdir()`, had the same
exposure.

**Fix (rights on `<llm>/tmp` not widened):**
- Armed `run_python_code`: TMPDIR/TEMP/TMP → `<run dir>/tmp`.
- Armed `run_shell` under kernel enforcement: TMPDIR/TEMP/TMP → a per-call
  `/tmp/epyc-fence-tmp-*`, removed after the call. Production, control arm and hook-only launches
  are unchanged.
- Spec and hook-roots files pinned to `/tmp/epyc-eval-fence-<uid>`.

**Verified:** with `TMPDIR=/mnt/raid0/llm/tmp`, an armed `NamedTemporaryFile` and `mkdtemp` work;
a direct create in `<llm>/tmp` is denied (negative control).

**Tests:** fence suite 126; tool-registry / REPL / eval_tower_concurrency / task_root: 381 passed.
