## RESOLVED once and for all: the anchor guard was digesting the non-deterministic layer (2026-09-06)

The recurring keep abort (2/2 in-loop promotions) was NOT a one-off — I was wrong on that. Root cause,
proven across every mismatch: the **compiler is byte-reproducible (0/379 objects ever differed); the
LINKER is not** (libggml-hip.so's host .text/.rodata layout varied across links of identical objects —
four distinct .so digests for one commit). The guard hashed the linked .so, so it aborted every keep on
link noise that changes nothing about the kernel.

**Fix** (root-cause, not guard-relaxing; research lane): `anchor_integrity.object_digest` hashes every
LIBRARY object (executables excluded — target-set dependent); the guard is wired to it. Deterministic,
and still catches run 18's stale-anchor class more precisely (a stale anchor's mutated-file object
differs, and the diff names the file). Proven on the exact aborted builds: .so digests differ, object
digests identical (cba7b046 == cba7b046). The operator's "why rebuild everything?" is answered the same
way: the guard's scratch build is now INCREMENTAL (CMake recompiles only the changed sources; heal stays
a clean rebuild), cutting its 20-min clean rebuild per keep to minutes. 415 loop tests pass.

**Relaunched** from `8a3049beb` (both keeps kept: +1.508% and +0.818% tg128) with `anchor-gen-017` as
the anchor — its objects are proven correct, so no rebuild. Remaining rebuild cost is promote_anchor's
one full build per keep; making THAT incremental is the follow-on throughput win.
