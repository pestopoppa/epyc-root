## What landed

### Explicit declared-only fallback (review caveat)
The fingerprint now carries a `kernel_evidence` field, set to `live` or `declared_only`. Rows written earlier today do not have the field, so it is derived from the kernel component they stored. Nothing is back-filled.

A declared-only kernel compares on the digest of the on-disk binary:
- **Digests differ:** NON_COMPARABLE, with `kernel` named as the differing component.
- **Digests match:** only UNVERIFIED, never COMPARABLE.
- **One side live, the other declared-only:** also compared on the on-disk digest, so it is UNVERIFIED rather than a false NON_COMPARABLE.
- **No kernel detail at all:** the evidence is `unknown`, which is never COMPARABLE.

**Consequence inside this container:** the stack's server PIDs are invisible, so every live verdict will be UNVERIFIED until the kernel component can read live PIDs. That is the honest reading.

### (b) Seed re-run in the same regime
- **Reference state:** `_seq_baseline_reference_state(current_fingerprint=…)` now sets `regime_due` in two cases: the latest baseline-reference draw is NON_COMPARABLE, or it has no fingerprint (a legacy row). The flag only fires once at least `AUTOPILOT_AP55_REGIME_REFRESH_MIN_TRIALS` trials have run since that draw (default 3). This guard stops a churning fingerprint from forcing a re-run on every other trial.
- **UNVERIFIED does not trigger a re-run:** a new draw could not verify the regime either.
- **Forcing the re-run:** after the Fable review fix (`0e6e2288`), a regime change schedules a re-run only when `AUTOPILOT_AP55_SEED_RERUN=1` is set, with seq on or off. The flag is unset by default. With it unset, nothing is fingerprinted on the force path and the seq cadence is unchanged from before AP-55.
  - With seq on, a regime change is one more "due" reason.
  - With seq off (the production value), only the regime-triggered re-runs are forced.
  - **Bootstrap:** a tier with no reference draw schedules one (`NO_REFERENCE`). Without this, `enforce` would hold forever on `seed_rerun:MISSING`.
  - **Bounded attempts:** a forced re-run whose eval comes back invalid or skipped would otherwise re-force forever. Attempts are counted per reference in `state["ap55_seed_rerun_attempts"]` (daemon-owned), spaced by `AP55_REGIME_REFRESH_MIN_TRIALS` trial ids, and capped by `AUTOPILOT_AP55_SEED_RERUN_MAX_ATTEMPTS` (default 3). Both the deferral and the cap are logged. A reference draw that lands resets the count.
- **Paired diagnostic:** the paired-baseline diagnostic skips reference draws from another regime and records `baseline_reference_regime`. **This changes the observe-only `seq_paired_baseline` payload even in shadow mode**, because it may pair against an older same-regime draw or report no reference. It remains `used_for_gating=False`.
- **Gate leg** (`seed_rerun_verdict`), which looks for the newest seed re-run inside the candidate's regime:
  - MISSING: there is no fingerprinted re-run.
  - NON_COMPARABLE: every fingerprinted re-run belongs to another regime.
  - Otherwise, that re-run's verdict: COMPARABLE or UNVERIFIED.

### (c) Batch homogeneity before a winner is named
New module: `src/autopilot_core/ap55_promotion_gate.py`.
- **The test:** a chi-square homogeneity test in pure Python (scipy is not installed). It matches reference values to 1e-9.
- **The batch:** every trusted row of the tier that was judged against the same baseline revision (the EV-14e pin) and falls inside the candidate's regime. Rows are pooled by config fingerprint. Seed re-runs are members, and the candidate is added.
- **Exclusions:** rows with no pin or no fingerprint are excluded and counted, never back-filled.
- **Verdicts:**
  - HOMOGENEOUS: p ≥ α, where α comes from `AUTOPILOT_AP55_HOMOGENEITY_ALPHA` (default 0.05).
  - HETEROGENEOUS: p < α.
  - INSUFFICIENT: the batch has fewer than 2 members.
  - UNVERIFIED: the candidate has no fingerprint.
  - The result also records `low_expected_counts` (Cochran's rule).
- **Where it runs:** before both `gate.update_baseline` call sites.
- **Where it is recorded:**
  - The full gate goes to the journal's `comparability.promotion_gate`.
  - A summary goes to `eval_details.ap55_promotion_gate`.
  - `measurement.ap55_gate` holds `{mode, seed_rerun, batch_homogeneity, hold}`.
  - The vidya adapter carries that block into the support frame. The fields are carried only; the grade is unchanged.
- **Modes** (`AUTOPILOT_AP55_PROMOTION_GATE`):

  | Mode | Behaviour |
  |---|---|
  | `shadow` (default) | Computes and records the gate. Never holds. |
  | `enforce` | Holds on seed re-run MISSING or NON_COMPARABLE, a HOMOGENEOUS batch, a candidate with no fingerprint, or a gate error. |
  | `strict` | Also holds on any UNVERIFIED. |

## Decision package: make the AP-55 gate binding? (operator)
**Decision:** what should `AUTOPILOT_AP55_PROMOTION_GATE` be set to, and should `AUTOPILOT_AP55_SEED_RERUN` be set? Making the gate binding changes what counts as a promotion. MEASUREMENT.md makes that human-amendment-only; the launcher's note on the `AUTOPILOT_SEQ_VERDICT` re-arm says the same.

| Option | Effect | Tradeoff |
|---|---|---|
| A. `shadow` (current default) | Gate legs are recorded on every trial and promotions are unchanged. | Zero risk. The winner-naming defect AP-55 targets stays possible. |
| B. `enforce` + `AUTOPILOT_AP55_SEED_RERUN=1` | Holds a promotion that has no same-regime seed re-run or comes from a HOMOGENEOUS batch. Forces at most one 14-question seed draw per regime change. | Extra compute is small. Chi-square power is low at batch sizes around 14–50, so HOMOGENEOUS will be common, and with `AUTOPILOT_SEQ_VERDICT=0` promotions may drop sharply. UNVERIFIED still passes, so the container blind spot does not block promotions. |
| C. `strict` | Only a verified regime passes. | Blocks **every** promotion inside the container until the kernel component can see live server PIDs (mount the host `/proc` or record namespace PIDs). |

**Recommendation: A now, B once the shadow record shows its effect.**
1. Run in shadow mode through the next autopilot run.
2. Measure how many actual promotions `enforce` would have held, using `eval_details.ap55_promotion_gate.hold` counterfactually. The field is recorded in shadow mode too, with `mode` shown.
3. Arm B if the hold rate is acceptable. If HOMOGENEOUS dominates, raise α or pair the decision with AP-65 (binding strength) and the seq re-arm.

Separately, fixing PID visibility is what makes COMPARABLE reachable at all.

Note on shadow mode: in `shadow` without `AUTOPILOT_AP55_SEED_RERUN`, promotions and forced draws are unchanged. The only behaviour that differs is the observe-only paired diagnostic: it no longer pairs against a reference draw from another regime.
