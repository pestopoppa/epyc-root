## Defect

`tools/server/server-context.cpp` `sample_and_accept_dspark_serial()` is the serial verify path
(`LLAMA_SPEC_EXACT=serial`, and the DSpark default for recurrent targets at temp 0). Each step
re-decodes `ctx_tgt` with one token, so the logits of the previous step are overwritten. The
TD-1d.2 fix covered only the batched path and left a `TODO(TD-1d.2)` here. As a result, every token
this path accepted came back with `prob = 1.0` and no top-n. Job 60's T4.1 run had 491/512 rows
without probabilities, so the serial-vs-plain comparison could only check token ids.

## Change

Branch `experimental/ds41-t412-serial-verify-nprobs-20261021` @ `02c139f11`, from champion
`dd3d9721c`. Worktree: `/mnt/raid0/llm/worktrees/ds41-t412-serial-verify-nprobs-20261021`. The
commit holds the feature and its test (OP-58).

- `sample_and_accept_dspark_serial(slot, off, out_probs = nullptr)`: after each sample+accept,
  `populate_token_probs(slot, cap, post_sampling_probs, special, tok_idx)` runs on the row just
  sampled, before the next `llama_decode`. This is the same call plain decoding makes after
  sampling.
- The accept loop in `post_decode` takes `serial_probs[i]` for serial rounds and asserts one
  capture per accepted token. The batched `verify_idxs` / `verify_dists` branches are unchanged.
- Test `tools/server/tests/unit/test_speculative.py::test_n_probs_serial_verify_matches_plain[False|True]`
  runs the stories15M MoE F16 target twice, once with no draft and once with the q4_0 draft under
  `LLAMA_SPEC_EXACT=serial`, at temp 0. It requires draft tokens to be accepted, and per row it
  requires the same id, the same logprob/prob (abs 1e-6) and the same top-n ids and probs as the
  no-draft run. Every serial row is a single-token decode, so the two runs should be bit-identical.
