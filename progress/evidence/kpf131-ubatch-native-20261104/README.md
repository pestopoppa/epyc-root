# KPF-13.1 source-header ubatch fixture

A model-free C++ child built against the `a1f0c8cf9bd7102415a72577474f307b8ba94db9` source headers produced a `llama_ubatch` with three unique sequence IDs. The parent used `/proc/<own-child>/mem` and the two offsets inferred from the pinned historical `find_slot` image: `n_seqs_unq` at `0x10` and `seq_id_unq` pointer at `0x40`. The fixture's own C++ `offsetof` values matched both. It read `[11, 22, 33]`, observed a planted in-place ID change to `[11, 99, 33]`, then observed the count change to 2 with `[11, 99]`; the child exited zero. Four independent capture tests pass for exact reading, count bounds, pointer mismatch and short reads. The detached source worktree was removed after the run.

This establishes those two fields in an independently compiled source-header object under this host toolchain, alongside the existing machine-code access signatures. It does **not** exercise the historical library, establish its compiler ABI, identify an individual token row, validate cache cells, task/slot/request association or memory consistency in a concurrently changing server, or prove custody. The pointer check is intentionally restricted to the fixture's known own-child array; this is not a general-purpose process-memory reader or deployed observer. Source commit and clean tracked source state are checked before compiling; no model, server, GPU or historical run was used.
