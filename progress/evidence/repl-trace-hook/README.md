# REPL v2 coverage bridge candidate

This is a **review candidate**, not an applied APP change, deployment, real trace, or a wired planning loop. `app-hook.patch` applies to `src/repl_environment/trace_capture.py` at APP commit `488b31c96c6c148768508b3dcaefcb6c4c297664`; `trace_belief.py` is the proposed new `src/repl_environment/trace_belief.py`. The hook passes only native successfully written v2 events, at the event boundary, to the existing prospective coverage producer; it never imports old records. The original native trace remains independent if the new bridge fails. The extra setting `EPYC_REPL_TRACE_BELIEF_CAPTURE=1` is required in addition to `EPYC_REPL_TRACE_CAPTURE=1`.

On first event in each process, the bridge checks a configured SHA-256 against the APP trace source currently on disk, checks an absolute output directory, creates an exclusive writer with an unpredictable run ID and registers normal-exit finalization. It serializes capture and resets inherited state after fork. Failed initialization or record writes fail closed for that process; abrupt termination or capture failure leaves an incomplete stream and no successful sidecar. Only accepted events count; coverage is not retrieval quality or opened-span follow rate.

**Outstanding gates:** The source file digest is a *declaration and on-disk check*, not proof of loaded bytecode or full deployment/runtime identity; the existing writer's row also carries no process/build manifest identity. The bridge imports the root producer (`scripts.vidya...`) and therefore needs an owner-reviewed, pinned distribution/import strategy, dependency and permission review, protected output directory, process-lifecycle integration, and fault/production-load tests. The root and APP repositories must not be mixed implicitly via an unreviewed `PYTHONPATH`. `atexit` does not cover SIGKILL, crashes, all termination paths or process worker lifecycle; incomplete streams must remain ungraded. A source-applicability scope and passing planning-context canary remain required. Actual session capture requires the separate operator activation and exact-original custody package. No source was installed or runtime flags changed here.

Controls: `PYTHONPATH=. python3 -m pytest -q progress/evidence/repl-trace-hook/test_candidate.py` passed 3 tests against the pinned native source, using a temporary patched file and synthetic spill search/open: valid finalized sidecar, independent flag-off behavior, and source-pin refusal while native writing continues. These are correctness controls only. GitNexus did not locate `_spill_record`; blast radius of the proposed hook is the native v2 spill write path, with additional I/O only when both flags are enabled. More testing is required before deployment.
