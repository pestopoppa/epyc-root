## AutoPilot local planner JSON extraction hardening

- **Problem**: the first fully local post-restart planner canary stayed off
  cloud providers, but `local_ingest` emitted a valid fenced
  `json:autopilot_actions` block with a duplicate closing brace after the JSON
  object. The old parser discarded the whole draft, forcing a degraded fallback
  planner path even though the proposed action was recoverable and still could
  have gone through normal validation and critique.
- **Change**: `epyc-orchestrator` `a151d319` adds a narrow shared parser helper
  for planner action/critique JSON. It first tries strict `json.loads`; on
  failure it accepts only a valid leading JSON object followed by trivial
  trailing bracket noise, then lets the existing schema and critic gates decide
  whether the recovered action is usable. Arbitrary trailing prose remains a
  parse failure.
