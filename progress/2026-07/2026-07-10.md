# Progress — 2026-07-10

## Dashboard: false "off-tap CPU-region holder" warnings eliminated

**Operator report:** The autopilot dashboard kept showing "`worker_general.full` is holding
CPU regions from /proc, but no matching structured /chat tap request is open" (action source
`autopilot:numeric_trial`), and it felt like it had gotten worse recently. Investigate + fix.

### Root cause — monitoring false positive, NOT a resource leak

The warning is generated client-side in `dashboard.html` by cross-referencing two feeds:

| Feed | Endpoint | Source | Property |
|------|----------|--------|----------|
| region-lock holders | `/dashboard/api/region_locks` | `/proc/locks` (`cpu_region_lock._current_lock_owner_pids`) | live, always current |
| structured tap requests | `/dashboard/api/inference_tap` | fixed **~1 MB tail** of `inference_tap_events.jsonl` | ages out under load |

Any lock holder with no matching tap request is flagged "off-tap." Two facts make that a false alarm:

1. **The lock cannot be orphaned.** Region locks are `fcntl.flock(LOCK_EX)` detected via `/proc/locks`.
   The kernel releases them the instant the owning process dies (even SIGKILL — the fd closes), so a
   `/proc` holder is **always a live process currently inside `cpu_region_lock`**, i.e. genuinely
   dispatching inference right now. Release is a `finally`-block fd close; no leak path exists.
2. **The 1 MB window is too small.** `inference_tap_events.jsonl` rotates at 512 MB — **three
   rotations in the last 5 days** (Jul 5/6/8). The last 1 MB holds ~1900 `worker_general` refs, i.e.
   only *seconds* of history. A genuinely-running holder briefly between visible tap events — most
   commonly a **long prompt-prefill emitting no chunks yet, while concurrent frontdoor/vision chunk
   traffic pushes its `start` event past the tail** — is invisible to the parser and mis-rendered as
   off-tap.

**Why worse recently:** eval-batch volume has climbed (orch `7cb71a4e` added eval-batch metadata
stamping), so the fixed window covers proportionally less time → more prefill-gap false positives.
Autopilot `numeric_trial` → eval → `call_orchestrator_forced` → `/chat` **is** tapped, so the
warning's own copy ("off-tap-route traffic such as seed_batch, probe, eval") was misleading.
