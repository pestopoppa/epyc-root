### R1 result + a scoring artifact that had inverted the conclusion

**GPQA-Diamond letter-only (no-CoT), n=198 paired, all 3 GPU arms complete:** A1 122B-IQ2 **55.1%**, A3 27B-dense **55.6%**, A4 35B-A3B **53.0%**. All pairwise McNemar p ≥ 0.63 — **no arm separates from any other**. Under a letter-only prompt these models emit ~2 tokens and cannot reason, so the suite reads knowledge/priors, not reasoning depth. **H3 is not supported here**: the 3B-active shallow reasoner ties the 122B when neither may reason.

**The first scoring pass said the opposite, and it was wrong.** It reported A1 55.1 / A3 51.0 / A4 43.4 — **A1−A4 = +11.6pp at p=0.0059, "significant"**. Cause: `extract_letter_answer` only accepted a bare letter when it was the entire response, so "…reasoning…\n\nB" failed to parse and scored **wrong**. Parse failures ran **0 / 13 / 29** across A1 / A3 / A4 — the bug penalised precisely the arms that show their work, fabricating an 11.6pp gap that pointed at the wrong architect model. Diagnosed by splitting no-parse into `finish_reason=stop` vs `length`: **37 of 42 were stop-with-a-bare-letter-final-line** (real answers, missed) and only 5 were genuine mid-derivation truncations.

Fix: bare-letter-final-line rule + last-match-wins + delimiter-required `ANSWER` tag (the old pattern matched the "i" of "answer **is** A"). It also removed *false positives* — "Option D matches this structure.\n\nD" had been scored `C`. **Re-scored offline from stored responses at zero GPU cost** (`architect_bench_rescore.py`); `architect_bench_analyze.py` now always prefers `per_question.rescored.jsonl` so arms are never compared under different scorer versions. Standing rule adopted: **report per-arm parse-failure rate beside every accuracy; a cross-arm difference is a scoring bug until proven otherwise.**

**Two process lessons persisted to memory:**
- `feedback_never_edit_running_shell_script` — editing `run_arm.sh` while a shell was executing it made bash resume mid-command at a shifted byte offset (`line 43: --binary: command not found`, exit 127). The eval itself had completed correctly (verified: `result.json` meta carried every flag; per-question ids matched the pinned manifest exactly) — so verify before discarding. Also: `pkill -f <pattern>` self-matches when the pattern is in your own command line (exit 144); kill by PID and `ps -p` to confirm.
- `feedback_parse_failure_rate_is_a_scoring_artifact` — the R1 story above, generalized.

**CoT budget raised 4096 → 8192** after A1's CoT run showed 1-in-5 truncating at the cap; partial run discarded and restarted, since truncation is the same budget-artifact class just corrected.
