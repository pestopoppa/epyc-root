## Toolrunner backend _MISSING_TYPE crash fixed + strategy store scrubbed

**Operator report:** `real_mode=true` requests to the toolrunner role returned 503 with `'_MISSING_TYPE' object has no attribute 'split'` in `_init_caching_backends`. The toolrunner field was added to the `ServerURLsConfig` dataclass but not to the `ServerURLsSettings` pydantic class, so the pydantic→dataclass constructor path produced a `_MISSING_TYPE` sentinel for `toolrunner` that crashed during `url_str.split(",")`. Additionally, the strategy store contained a stale belief (`7e33ead1...`) claiming tool_use suites "likely fail at an infrastructure level" — that was the *symptom* of this bug, now fixed.

### Root cause

`get_config()` builds `ServerURLsConfig` by iterating its dataclass fields and looking up matching attributes on the pydantic `ServerURLsSettings` object. For `toolrunner`, the pydantic object had no such attribute, so it fell back to `f.default` — which is `dataclasses.MISSING` for a `default_factory` field. That `_MISSING_TYPE` sentinel propagated into `as_dict()` → `_init_caching_backends()` → `url_str.split(",")` crash.
