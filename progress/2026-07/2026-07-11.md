## Toolrunner backend _MISSING_TYPE crash fixed + strategy store scrubbed

**Operator report:** `real_mode=true` requests to the toolrunner role returned 503 with `'_MISSING_TYPE' object has no attribute 'split'` in `_init_caching_backends`. The toolrunner field was added to the `ServerURLsConfig` dataclass but not to the `ServerURLsSettings` pydantic class, so the pydantic→dataclass constructor path produced a `_MISSING_TYPE` sentinel for `toolrunner` that crashed during `url_str.split(",")`. Additionally, the strategy store contained a stale belief (`7e33ead1...`) claiming tool_use suites "likely fail at an infrastructure level" — that was the *symptom* of this bug, now fixed.

### Root cause

`get_config()` builds `ServerURLsConfig` by iterating its dataclass fields and looking up matching attributes on the pydantic `ServerURLsSettings` object. For `toolrunner`, the pydantic object had no such attribute, so it fell back to `f.default` — which is `dataclasses.MISSING` for a `default_factory` field. That `_MISSING_TYPE` sentinel propagated into `as_dict()` → `_init_caching_backends()` → `url_str.split(",")` crash.

## Region-locks dashboard panel: shows all configured NUMA instances (full + quarters)

**Operator report:** the "regions lock" grid showed only one shape per role (frontdoor=Half0, worker_general=Full, ingest=Half0, vision=Half1, worker_vision=q1) — hiding the 4 running NUMA-quarter servers of the multi-instance roles. Recurring regression; operator noted it began around the same Jul 5–7 region-locks/tap rework as the off-tap live-tap warning (yesterday's fix).

### Root cause — two independent gates

1. **NUMA mode read as `full`.** `active_stack_numa_mode()` (dashboard_topology.py) defaults to `full` when `ORCHESTRATOR_STACK_NUMA_MODE` is unset — and **nothing in the codebase exports it** (the docstring's "launcher exports it" was false). But the stack genuinely runs `both`: every quarter server is up + healthy (verified via `orchestrator_stack.py status` — worker_general 8082/8182/8282/8382, frontdoor 8080/8180/8280/8380, ingest 8185/8285/8385/8485, vision 8187/8287/8387/8487). The `full`-mode filter collapsed each role to its primary instance.
2. **Visibility gated on co-placement.** The grid derived visible shapes from the contention matrix's `same_role.instance_pairs` (a **co-placement** property). `ingest_long_context` (heavy 80B) correctly has no co-placement pairs, so its quarters stayed hidden even in `both` mode — even though its 4 quarter servers are live, dispatchable-one-at-a-time targets.
