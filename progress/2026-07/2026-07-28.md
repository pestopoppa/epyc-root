### The embedder-outage path (found while closing M-17e)

Chasing "what if BGE is down when the gate runs" turned up an unfixed corruption path.
`use_fallback` defaults to **True** in `EmbeddingConfig` and `EmbedderPoolConfig`, and every live
site builds a bare `TaskEmbedder()`. So an embedder outage does not fail a write — it silently
stores a SHA-256 pseudo-vector. Measured over 5,000 real task texts:

| outcome | share | consequence |
|---|---|---|
| all-zero | **89.0%** | float32 `norm` overflows to `inf`; `norm > 0` is True for inf; `v/inf == 0` |
| contains NaN | 2.8% | permanently unretrievable — FAISS scores the row `-inf` |
| unit-normalised | 8.1% | well-formed, meaningless, passes every cheap check |

The blind spot was exact: the well-formed 8.1% pass sync and round-trip, so the only detector was
semantic self-match — which needs the very embedders whose absence produced them. **The condition
that causes the corruption is the condition that disables its detector.**

Audited all 58,322 live rows: **0 hash-fallback vectors**. The store is clean, because the reseed ran
with `use_fallback=False` and BGE has been up.

| Change | Repo | Effect |
|---|---|---|
| `is_degenerate_embedding` / `is_hash_fallback_embedding` | orchestrator | exact detection; the fallback is a pure function of the text |
| `EpisodicStore.store()` guard | orchestrator | raises `DegenerateEmbeddingError`; one chokepoint, not ~8 constructor sites |
| `degenerate_vectors` check | orchestrator | **needs no embedder** — detects 91.8% of fallback corruption in the exact condition that causes it |
| AutoPilot gate retry | orchestrator | 180 s embedder boot window, then fail closed |

Healthy startup costs 0.9 s; a structural failure blocks in 0.3 s without burning the window.

**Two defects in my own detector, caught by measuring instead of asserting.** A cosine test at 0.99
had a **45% false-positive rate** against random unit vectors — the overflowed reference is
unnormalised and dots high with anything — replaced with exact comparison, now **0 false positives
over 3,000 live BGE vectors**. And I first wrote that hash vectors are "maximally diverse and defeat
`vector_diversity`"; wrong, at 89% all-zero they collapse and that check would fire.

Store state: `ntotal=58322 id_map=58322 desync=0`, round-trip 500/500, diversity 57/57 (ratio 1.000),
degenerate 0/500, **semantic self-match 0.9943**. 23 new tests; episodic suite 173 passed.

## GPU shadow lane — P2-3d (loader-level ceiling gate) + P2-5 (D1 admission provision)

**P2-3d.** Moved the serving-shape/ceiling consistency check off Stage-0 and onto the resolution
path. A gate you can skip by not running Stage-0 is not a gate on the launch path;
`load_serving_shape()` is what stack-priors calls to produce the builder's real `-np`/`-c`, so an
out-of-ceiling shape is now unresolvable rather than merely reported. Both conditions were chosen to
be universally necessary, because the loader cannot know which tenant will be resident: `np_slots`
may not exceed any tenant's saturation point (past saturation a launch is slower *and* hungrier, so
it is wrong for every tenant), and the cell must be admissible for at least one tenant/mode/budget
row (a shape admitted nowhere is unusable by construction). The stricter program-specific check —
works for every Phase-3 arm — stays in Stage-0, which knows the tenancy table. Policy parsing was
split so both loaders share it, with the feature gate deliberately left on the consumer entry point
rather than on parsing: `load_serving_shape` must resolve during the Step-2 pipeline gates before the
flag is flipped, and handing the ungated caller its own second parser is exactly how the two blocks
in that file drifted apart to begin with.

**P2-5.** The lane spec listed D1's four admission classes but left the provision incomplete where it
gets expensive later. §3 now pins the class-3/4 flag names (reserved, deliberately *not* registered
in `src/features.py` — a flag for an unbuilt feature reads as an invitation), defines what priority
may and may not mean (it orders **admission, never eviction**: no class may interrupt a request
already decoding, at any priority — stated explicitly because "priority queue" ordinarily implies
preemption and here it must not), and records that the reservation is enforced at load rather than by
reviewer memory.

The substantive finding is §3.4: **shed-batch is partially self-defeating**. Class 3 exists to move
batched work to the GPU when CPU is stressed, but the lane is not a pure GPU resource — its host
threads sit on q3's physical cores, so shedding consumes CPU in the region most likely to be
contended precisely when CPU is stressed. Bounded (8 host threads, not a 48-thread quarter) but
concentrated, and shared with frontdoor 8380, worker_general 8382 and 8072, ingest 8485,
vision_escalation 8087 and architect_general 8083. The net is (GPU gained − q3 CPU lost) and has
never been measured; the Step-4 recert already produces the pairwise inputs. Filed as P2-5a so that
"don't build class 3" can be a measurement outcome rather than the reversal of a shipped feature.
