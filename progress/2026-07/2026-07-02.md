## Dashboard topology + CPU region-lock panels stale after reboot (front-end lifecycle fix)

- **Problem**: After the host reboot, the AutoPilot dashboard showed live inference in the tap/snapshot panels, but the **topology strip** and the **CPU region-locks** holder dots appeared frozen/stale. Other panels updated normally.
- **Ruled out**: not a stale process — the orchestrator API (`pid 258221`) started `20:22`, after the last commit; not stale data — `/dashboard/api/topology`, `/dashboard/api/region_locks`, and `/dashboard/api/topology_activity` all returned fresh, correct payloads (region_locks showed `frontdoor` holding `q2` / instance 3 and `worker_general` holding `q3` / instance 4; topology_activity age `0.06s`); not stale serving — `dashboard.html` is re-read from disk per request with `no-store`.
- **Root cause**: `renderTopologyStrip()` (builds the strip DOM: roles, ports, backing models) is called **only** by `loadTopology()`, which ran **exactly once**, at page init (`dashboard.html:5647`). There was no interval and no other caller, and the global `topology.nodes` array was frozen from that single fetch. Every live overlay — `updateTopology` slot-dots (iterates `topology.nodes`), `#activity_<base>` stats, in-flight badges, and the **region-lock holder slot-dots** — attaches to that frozen strip DOM keyed by role. After a reboot the stack re-launches (possibly different ports/models, or the tab predates the stack coming up), so the strip and its region-lock dots stayed pinned to pre-reboot structure until a manual hard-reload. The inference-tap/snapshot panels kept updating because they do not depend on the frozen strip.
- **Fix** (`epyc-orchestrator/src/api/routes/dashboard.html`): added `_computeTopologySig()` (a signature over strip *structure only* — id/label/port/kind/model, excluding live activity); `loadTopology()` now re-renders **only when the signature changes**, preserving per-row expand/collapse state and avoiding steady-state flicker, and on a real rebuild immediately repaints the live overlays via `scheduleRegionLocksRefresh(true)` so the strip is never momentarily blank; registered `setInterval(loadTopology, 5000)` so the strip self-heals after any reboot/stack reload (a no-op when unchanged).
- **Validation**: extracted the script block and ran `node --check` → OK; confirmed the running server already serves the patched HTML (`curl /dashboard | grep _computeTopologySig|topology-refresh|_topologySig` → 6 hits). HTML is served fresh per request, so **no orchestrator reload needed** — one browser hard-reload of an already-open tab picks up the new JS; future reboots self-heal.
- **Deferred/next**: none for this fix. Operator action: hard-reload any dashboard tab open from before this commit (the build-rev badge will be yellow).
