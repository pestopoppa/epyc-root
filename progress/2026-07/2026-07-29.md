## C36 — liveness now comes from the runtime, not the agent's self-report (auditor)

Operator-approved Option B, dispatched at 16:30Z and landed in two commits (`33eb7306` signal +
backend identification, `dd9e61d2` probe wiring). **The heartbeat is written BY the agent, so an
agent that has stopped cannot say so** — that is the deadlock, and C35's pane-quiescence override
only treated the symptom with a heuristic. The runtime's answer has no such dependency: it is state,
not a timestamp.

Both directions act, and both report. Runtime ACTIVE blocks whatever the heartbeat says — **a
protection the previous guard did not have at all**, because a main whose heartbeat wrongly read
`idle` while mid-generation was nudged without hesitation. Runtime IDLE clears the `working`
heartbeat *and* its staleness, since once the runtime has spoken the self-report is not evidence
about anything. UNAVAILABLE changes nothing and never becomes `idle`.

Verifying the design doc rather than trusting it changed the implementation four times, and one of
those was live: a parent Codex process **keeps finished subagent fds open**, so on pid 257808 one fd
read `task_complete` while its own user rollout read `custom_tool_call`. Reading the wrong fd
reports idle for an agent mid-tool-call. The `thread_source` filter is the guard, not hygiene — and
absent `thread_source` fails closed for the same reason.

**I repeated C25 inside the C36 fix, an hour after landing C25.** The first draft resolved windows as
`window_name == agent` and silently lost `coordinator-agent`, whose endpoint is
`tmux:agent:coordinator`. Smoke-testing against the live fleet caught it; my tests did not. That rule
now lives in one function so no future caller re-derives it. A second fixture defect followed the
same shape: the probe helper fed a pane "quiet since 1973", which silently made C35 override the
heartbeat in every case, so the fallback tests were not exercising the fallback.
