## Governance: Operator Decision Requests contract (options + tradeoffs, never open-ended)

**Problem**: agents across harnesses (claude/codex/opencode) repeatedly escalate decisions to the
operator as generic open-ended questions ("How should I proceed?"), forcing the operator to ask
for options and tradeoffs on every round-trip before an informed decision is possible.

**Change**: formalized a mandatory **decision package** for all operator input requests —
(1) 1–2-sentence context on the fork and why it can't be resolved autonomously; (2) 2–4 concrete
options, each with tradeoffs (cost/risk/time/quality/reversibility) and supporting data
(perf/quality numbers follow the MEASUREMENT.md claim grammar); (3) a recommendation with
reasoning (or the tie-breaking measurement if torn); (4) the default outcome if no choice is
made. Claude Code sessions deliver via AskUserQuestion (recommended option first, labeled
"(Recommended)"); other harnesses render a compact markdown list. Exemption: pure factual gaps
(missing credential, ambiguous reference) may be asked directly.

Canonical policy lives once in `agents/shared/OPERATING_CONSTRAINTS.md` (thin-map architecture);
all other surfaces are short pointers. Coverage is complete for every harness because each
repo's `AGENTS.md` (read by codex/opencode) symlinks to its `CLAUDE.md`.
