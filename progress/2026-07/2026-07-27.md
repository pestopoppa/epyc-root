### D-a landed same session — hardened pickle boundary (operator decision)

Operator was presented a 4-option decision package (harden-AST-and-measure-first / typed
non-executable codec / pickle behind a hardened boundary / close D-a) and chose **pickle behind a
hardened boundary**. Implemented with four independent layers:

1. **`find_class` allowlist** (load-bearing) — `src/repl_environment/safe_pickle.py`. Only explicit
   `(module, name)` pairs resolve; the list is inert data types only. Model-defined classes live in
   `__main__`, deliberately absent, so they cannot be reconstructed at all.
2. **HMAC** over the blob — tampering at rest only. Explicitly documented as NOT establishing content
   safety, since we are the ones pickling model-authored objects.
3. **Size cap** — 5,000,000 bytes, checked from encoded length before decode.
4. **AST rule** — `ASTSecurityVisitor` now refuses REPL code that binds a serialization hook.

**Motivating measurement**: `pickle` was already in `FORBIDDEN_MODULES`, and `FORBIDDEN_ATTRS` lists
`__reduce__` — but `visit_Attribute` only fires on attribute *access*. A class that *defines*
`__reduce__` is an `ast.FunctionDef`, and our visitor returned **zero violations** for it. Latent
(no pickle path existed); D-a is what would have armed it.

**`/security-review` on the implemented diff found 4 issues, all fixed before landing:**

| Sev | Issue | Fix |
|---|---|---|
| P1 | numpy `multiarray.scalar` deserializes an object-dtype scalar's data buffer with plain `pickle.loads` — a nested unguarded unpickle inside our guarded one. numpy 2.4.4 refuses it, but that is a version-dependent invariant we must not rely on. `scalar` cannot be dropped (needed for `np.int64`, not for arrays). | `_guarded_numpy_scalar` rejects object dtypes itself |
| P2 | HMAC key race: `O_CREAT\|O_EXCL` published a zero-length file before writing; a concurrent worker reading in that window got an **empty, guessable** key | write to private temp + `os.replace` (atomic) |
| P3 | `.strip()` applied to raw random key bytes could silently alter the key | hex-encode on disk; reject short/unparseable reads |
| P3 | Two layer-4 AST bypasses — class-body assignment (`__reduce__ = lambda …`) and `type('C',(),{...})`. Both measured as passing. Layer 1 held in both. | `visit_Assign` + a `type(...)` check in `visit_Call` |

**Verified holding**: hostile `__reduce__` → `__import__`/`eval` rejected at save; hostile object
nested in an object-dtype array rejected; a *correctly HMAC-signed* hostile blob still rejected at
load; no callable gadgets on the allowlist (`operator.attrgetter`, `functools.partial`,
`copyreg._reconstructor` absent, with a regression test asserting it).

**Scoping calls inside the operator's decision**: pandas NOT allowlisted in v1 (block managers +
index constructors are too wide to audit tightly) → filed as D-a2; allowlist drift guard → D-a3.

### 🔴 The pickle boundary I landed and pushed this morning was BROKEN

An adversarial agent was asked to break `safe_pickle.py` (orchestrator `d4f84288`). **It succeeded.**
Model-authored REPL code passing `ASTSecurityVisitor` could produce a checkpoint variable that, once
signed and restored, dereferences an attacker-controlled pointer in the orchestrator process —
verified end-to-end as **SIGSEGV (exit 139)** on a fresh restore. Fixed in `9d30bb60`.

- **Primary defect — "allowlisted" ≠ "inert".** `numpy.ndarray` was on the allowlist as a nominal
  data type, but `np.ndarray((1,), dtype('O'), buffer=...)` reinterprets the buffer bytes as raw
  `PyObject*` pointers with **no validation**. The morning's review guarded `multiarray.scalar` for
  exactly this shape and left `ndarray` unguarded — it guarded the *instance* of the defect, not its
  *class*.
  Fix: `numpy.ndarray` now resolves to a **non-callable type token** (legitimate pickles only ever
  pass it as `_reconstruct`'s subtype — verified against the real opcode stream), plus
  `_assert_array_safe`, a metadata-only check (reads `dtype`/`nbytes`, never an element) rejecting
  object-dtype and oversize-logical arrays.
- **Size-cap evasion, same gadget**: a **104-byte** signed pickle describing a 4 GB stride-0 view.
  The byte cap bounds the encoded payload, never the logical object → `MAX_ARRAY_BYTES`.
- **Secondary — layer 4 bypassable six ways**, all installing a hook with no `FunctionDef`: metaclass
  `__new__` mutating the namespace under a **computed key**, `dict(__reduce__=fn)`,
  `ns.update(dict(...))`, subscript assignment. Fix: reject custom metaclasses and `dict(<hook>=...)`,
  extend the subscript check. **The insight: a computed key can never be caught statically, but it is
  inert unless the dict is installed as a class namespace — and that has exactly two routes, both now
  closed.** Docstring corrected: this layer is depth, never the guarantee.
- **What held up** (reported as clean): `defaultdict`/`Counter`/`deque` factory abuse, numpy
  object-*array* contents (inlined in the outer stream, so `find_class` catches them), classic pickle
  bombs, HMAC usage (`compare_digest`, verified before any unpickling), no parse differential.
