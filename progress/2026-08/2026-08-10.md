## R1b: the 2026-08-09 null was vacuous, and the real result is a refutation

`route_a_incremental` and `route_b_ground_truth` reduce to the same expression — specializing the base by
zeroing a token and then dropping ⊥ entries *is* deleting the fact — so 5,670 agreements measured nothing.
The mutation test recorded alongside it was sound but only showed the harness detects disagreement.

Three genuinely incremental routes implemented and swept over the same instances:

| Route | Counterexamples / 5,670 |
|---|---:|
| Re-evaluate each stratum (the old "route A") | 0 — *by construction; vacuous* |
| Circuit specialization | **2,241 (39.5%)** |
| + dual tokens | **270 (4.8%)** |
| + intra-stratum dependency closure | **0** |

Minimal counterexample: `p :- a`, `r :- not p`, retract `a` — `r` never fired, so the circuit has no node
for it. Caveat recorded: the exact route retains **91.7%** of stratum-2 rules, saving 8.3% over full
re-evaluation, so it is not yet worth building. `R1b-closure-size` is blocked on a genuine prerequisite —
spec §12 requires the pilot rule set to be positive, so there is no negation stratum to measure. Filed
`R1b-usecase` for the rule that would create one.

## Corroboration is no longer degenerate

The operator reviewed all 45 alias candidates: **10 same, 35 different**. Emitting those aliases would have
manufactured corroboration on its own — `_disjoint_supports` counted evidence *labels*, which are minted per
claim, so two records of one paper produced two labels and read as independent support. Support is now
counted by **source locator**, and alias groups their author marked non-independent collapse to one witness.

Distribution over 4,181 beliefs: 0 supports → 112, 1 → 4,066, **2 → 3**. First non-zero
`disjoint_supports ≥ 2` in the program's history; 7 of the 10 groups (same-source or linked) correctly
produce none, and exactly the 3 genuinely independent ones do.

## PR2d: a 20-edge sample said one thing, 60 edges said the opposite

A uniform 20-edge sample suggested "a citation from a dived entry is a candidate dependency" at 4/6
precision. A **60-edge sample stratified over the 672 dived-source edges refutes it: 18% evidential, 75%
topical, 7% companion artifact.** The n=20 figure was a small-sample artifact of the semiring-provenance
intake. Promoting all 672 would create ~550 false dependencies, and a false dependency propagates
invalidation into work that never depended on anything. Two mechanical rules also failed (names-the-target
0.50/0.09; verification-language 0.50/0.27).

Recommendation reversed: **do not infer dependency from citation at any confidence.** `depends_on` adopted
end to end — schema field (`entry` / optional `claim_index` / required `why`), validator shape-check, a
`claim_depends_on/v1` frame from the adapter, and a Stage-2 obligation carrying the counterfactual test:
*if that entry's claim were retracted tomorrow, would a claim in this entry have to change?*

## Merge gaps: assessed, declined, and made recoverable

Renumbering to close the four gaps would change 728 entry ids, rewrite 5,565 references across 479 files,
and change 731 of the 1,067 intake ids embedded in ledger claim identifiers — which an append-only,
checkpointed log cannot absorb. The decisive argument is independent of the ledger: a reused id makes an old
reference resolve to the *wrong* paper, silently, whereas a gap is a visible absence.

That argument only holds if the absence is recoverable, and it was not — 44 references to absorbed ids sat
in 20 files with no forward pointer. Now published as a generated redirect map
(`research/intake_merge_map.md`) plus `resolve_intake_id.py`; the validator fails if an absorbed id is
missing from it. Deliberately **not** a bulk repointer: inspection found the MI210 handoff cites intake-797
inside a correction saying intake-797 was a mis-stamp, and `recommendations.md` uses it as a range endpoint.
