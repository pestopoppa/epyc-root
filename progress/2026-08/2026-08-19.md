### 2. `entry_verdict.py` confidence gate rejected the only real confidence source we produce

`_confidence_nondegeneracy` accepted `confidence_source` by **equality** against
`{logprob, logprobs, probabilities, completion_probabilities}`. The eval tower's real value is
`completion_probabilities_geomean` (`handoffs/active/eval-tower-verification.md:149`), which matches
none of them and none of the degenerate markers either — so it fell through to
`None, "no non-degenerate signal was supplied"`. Net effect: the one genuinely non-degenerate
confidence source in the stack could never satisfy the rule written to accept it, while the
`float(correct)` phantom the rule exists to catch was correctly rejected. The gate was
unsatisfiable, not merely strict.

Fix (`scripts/coordination/entry_verdict.py`):
- accepted-source test is now substring-based over `logprob` / `logit` / `probabilit{y,ies}`, so
  qualified producer names pass;
- degenerate markers (`proxy` / `float(correct)` / `binary`) are checked **first**, so a name carrying
  both (`binary_probabilities`) still fails closed;
- `confidence_is_real` — the boolean the eval tower already stamps in aggregate details — joins the
  explicit non-degeneracy signal names.

Four regression tests added, each mutation-tested (revert the fix → the test fails; reorder the two
branches → the ordering test fails). `scripts/coordination/tests/` + `tests/vidya/`: **709 passed,
38 skipped**.
