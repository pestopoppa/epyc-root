### A live security defect, found and fixed

While auditing whether a staged amendment could rely on `human_only_paths.yaml` for enforcement, a
review agent found that `scripts/hooks/check_trust_boundary_edit.sh` compared the target path against
each gate-list entry with a **quoted** right-hand side — literal string equality, not bash pattern
matching. Literal entries matched, so the guard looked healthy. The one wildcard entry matched
nothing: `measurement/protocols/*.md` was compared against that literal path, which no real file
equals.

**Effect: Annexes B, Q and G — which `MEASUREMENT.md:17-19` states carry the same trust boundary and
amendment rules as the constitution itself — were writable by any agent, with layer 1 reporting
success.** Layers 2 and 3 protect `human_only_paths.yaml` itself, not the annexes, so nothing was
catching an annex edit.

Verified by replicating the matcher against the live gate list rather than by trial write. Fixed in
`6f1c4a8b` (two quote characters). Then a second finding: my assertions went into a new sibling
script when `scripts/hooks/tests/test_trust_boundary_edit.py` already existed and already drove the
hook end-to-end. Its `CASES` list covered **every literal entry and no wildcard entry** — non-vacuous,
and it still missed this purely by omission. Sibling deleted; wildcard cases plus their
compliant-path counterparts folded into the canonical suite (`51613c9e`, 22/22 pass).

### Two more guard defects, found by the guards failing on my own commits

**The epyc-root pre-commit wrapper discarded the PII hook's failure.**
`.git/hooks/pre-commit` called its two hooks bare:

```bash
"…/pii_precommit.sh" "$@"
"…/hermes_drift_precommit.sh" "$@"
```

A bash script exits with the status of its **last** command, so a failing
`pii_precommit.sh` printed every `BLOCKED` line and was then discarded by a passing
`hermes_drift_precommit.sh`. Verified empirically: **with a real AWS-access-key-shaped blob staged,
the wrapper exited 0.** Every secret pattern — AWS keys, GitHub tokens, Anthropic keys, PEM private
keys, JWTs — has been advisory-only in the governance repo.

Found because the hook printed `BLOCKED` on my own progress file and the commit landed anyway. The
hook itself was correct and had its own tests; **the composition around it was never tested, and the
composition was the defect.**

Fixed: the wrapper now runs all hooks (so one failure cannot hide another's findings), accumulates,
and exits non-zero if any failed. Deliberately not `|| exit $?`, which stops at the first failure.

**epyc-orchestrator has the identical defect** — same bare-call pattern, with a trailing conditional
block whose zero exit becomes the wrapper's. **Not fixed here:** that repo was held by another session
all day and is explicitly out of scope. The irony is on the record in that file's own comment, which
reasons at length about `--no-verify` skipping "the PII and hermes-drift checks above" while the
composition was silently skipping them anyway.

`scripts/hooks/tests/test_precommit_wrapper.sh` drives each installed wrapper end-to-end against a
throwaway repo with a known-bad blob staged, and asserts both directions so a wrapper cannot pass by
always failing. It reports epyc-root and epyc-inference-research green and **epyc-orchestrator
failing** — that failure is a live finding, not a test bug, and should stay red until that repo's
wrapper is repaired by whoever owns it.

**Also worth recording:** `.git/hooks/pre-commit` is untracked in every repo and no installer exists in
tracked code, despite each wrapper claiming to be "auto-installed by epyc-root". The fix does not
survive a fresh clone, and there is no single place to correct all three.

### Pattern worth naming

Three guard defects in one day, all the same shape: **the guard was correct and its composition was
not, and every test asserted the guard rather than the composition.**

1. The trust-boundary matcher compared with a quoted RHS — literal entries passed, wildcard entries
   silently matched nothing, and the test suite covered only literal entries.
2. The epyc-root pre-commit wrapper discarded a hook's non-zero exit — the hook had tests, the
   wrapper had none.
3. The same in epyc-orchestrator, still open.

The standing screen this project already has — *"can I make this check pass by deleting the thing it
inspects?"* — would not have caught any of the three. The complementary screen is **"does the thing
that runs this check propagate its answer?"**
