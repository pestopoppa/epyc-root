### C4 — the premise inverted

C4 asks to demote C1 from "the current production solo shape" *on the grounds that* the realized
stack is quarters-only. **That ground is gone.** `982adb0c` retired quarters; `stack_topology.yaml`

So the relabel lands on **C3**, not C1. C3 (4×quarters) is what the design note calls "the status-quo

### T4 — and a retraction of my own A6 correction

T4 says to fix the batch drain "with more prompts, or a closed-loop arrival process". Read the driver
first: **it is already closed-loop** — `run_cell_driver` binds N×K streams permanently and pulls from
one shared queue, and says so in its docstring. Half the proposed remedy was already in place.

The real cause is the fixed 43-prompt quantum against `T = instances × np`:

| T | requests/stream | empty trimmed window |
|---:|---:|---|
| 1 | 43.00 | 0 / 3 |
| 4 | 10.75 | 0 / 5 |
| 8 | 5.38 | 0 / 7 |
| 16 | 2.69 | 0 / 8 |
| **32** | **1.34** | **5 / 8** |

At T=32 most streams serve exactly one request. The run is ramp plus drain with no middle, so there
is no steady state to find. It is a sample-size defect, not a trimming defect.

**This forced a retraction of my own A6 package.** Its §2 "corrects" the brief for saying *every T=32
cell*, arguing two of the five blocked cells are `np=16`. Wrong: `T` is *instances × np*, and both
those cells (`C2-np16`, `C1b-np16`) run **two instances** — they are T=32. The three `np=16` cells
that passed are `C1-np16`, one instance, T=16. I read "T" as "np" and then corrected the row for a
conflation that was mine. Retracted in place, append-only; the recommendation never depended on it.

The connection that matters: **T4 and A6 are the same defect from opposite sides.** A6 is the
read-side decision about what the gate should do with an empty window; T4 is the write-side fix that
makes the window non-empty. Ratifying A6 does **not** make the T=32 rung interpretable — it only
stops the empty window from voiding the grade. The rung stays uninterpretable until the quantum
grows. Floor stated so the ask is concrete: ≥128 prompts for 4 requests/stream at T=32, ≥96 for 3.

Not implemented, and the blocker is nameable: the 43-qid batch is a **pinned** instrument and
re-sampling is explicitly forbidden, so growing it changes the instrument and breaks comparability
with every banked cell. That is an operator ruling, and it should be recorded as an **era boundary**
rather than an edit — the same argument the 2026-08-11 rider makes for objective changes.
