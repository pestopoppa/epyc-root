### C42 was running and still not firing — the bug was mine, in the wiring

The supervisor restart at 00:26:25Z made it source-current, so the check should have fired. It did
not: **zero detections logged**, daemon demonstrably stale, and the predicate returning STALE when I
ran it by hand against production values.

Cause: I hooked `check_stale_source` into `check_once`, but the loop's healthy branch does
`sleep; continue` and **never calls `check_once`**. So the check only ever ran on the *unhealthy*
path — where the daemon is about to be restarted anyway and the question is moot. The entire point
is a daemon that is **up and answering while running old code**, and that is precisely the path it
was not on.

**My tests could not have caught it, and that is the durable part.** They exercised the predicate
directly and `check_once` directly — *a* consumer, not *the* consumer. The loop was never in the
test's reach. So I added a static wiring assertion that the loop's healthy branch reaches the check,
and **mutation-verified it**: removing the call takes the suite 8/8 → 7/8 with the failure naming the
defect. A test that cannot fail on the bug it was written for is decoration.

### C43 — lock contention exited 0 with no evidence

`coordinator-agent` filed it from the 00:25:09Z relaunch that logged *"another supervisor holds the
lock; exiting"* and exited **0**. That was true at the time, but the exit code says SUCCESS, so
nothing downstream can distinguish *"correctly skipped, one is already running"* from *"failed to
start, nothing is supervising."*

**I deliberately did not change the exit code.** For the documented cron idiom (`*/2 * * * *
bus_supervisor.sh once`) a skip is the normal case, and non-zero there would page on every ordinary
tick — trading a silent gap for constant noise, which is how a real alarm gets ignored. The fix is
the *evidence*: it names the holder pid and whether it is ALIVE or DEAD, and reports a dead or
unreadable holder loudly, because that is the shape where nothing is supervising and everything
still looks fine. Same fail-open family as a heartbeat that outlived its process.

Verified live: `once` against the running supervisor prints `lock holder: pid 1336629 (ALIVE)`.
