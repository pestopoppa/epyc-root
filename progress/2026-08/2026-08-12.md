### C42 has a bootstrap problem, and it is live

Verifying my own shipped work rather than assuming it took effect, which is the discipline this
whole handoff has been about. The result is recursive and worth stating plainly: **the watchdog that
detects stale daemons is itself stale.**

Measured, not theorised:

- `bus_supervisor` pid 489217 started **08:48:01Z**; C42 landed in `bus_supervisor.sh` at
  **22:40:02Z**. The running supervisor predates its own check and has logged **zero** stale-source
  detections.
- So it never noticed the coordinator-daemon (pid 942753, started 22:25:55Z) is running pre-rotation
  code.
- So the rotation I landed has **never fired**: `advisory.jsonl` is still **1,044 MiB with no
  shards**.

The chain is **stale supervisor → undetected stale daemon → un-run rotation**, and one supervisor
restart collapses all three. After that C42 keeps the chain closed by itself.

This is **OP-9** — *nothing restarts the supervisor itself* — in concrete form, and the strongest
argument yet for that cron decision: C42 cannot bootstrap itself past a supervisor that predates it.
I declined the cron half earlier tonight as a host-level operator call and I still do; restarting is
process lifecycle and outside C-OWN's lane. Filed as an open sub-item with the measurement attached.

Worth naming the shape: I built a detector for committed-not-live, shipped it, and it was itself
committed-not-live. That is not irony so much as the reason the defect class is durable — every
mechanism that carries a fix to where it runs is itself a thing that has to be carried.

### Absence-inference filed as a cross-cutting rule (`mainA`'s ask)

Per CLAUDE.md the belief-kernel write side is cheap and permanent while the read side cannot be
retrofitted, so this got filed immediately rather than queued: **a field used to discriminate KIND
must BE an explicit kind, never a present/absent test.**

`mainA` raised it from four absence-inferred fields found in one night, and the generalisable point
is not carelessness — **two of the four were introduced by the person fixing that exact class, hours
apart.** Presence/absence is the cheapest discriminator at design time and its whole cost lands on
whoever reads the store months later, who cannot tell *"this kind has no value"* from *"nobody wrote
one"* from *"the writer predates the field"*.

Recorded with the three same-day read-side instances that show it is not confined to manifests:
`mainB` reading merge stage `:3` after a `git add` (stages 1/2/3 collapse, so `:3` returned empty and
empty made every comparison pass), my own `--check` reporting "index is current" while covering only
bus-known gates, and the auditor's receipt index asserting `ratified` over untracked files. Each was
**true about a smaller set than it appeared to speak for.**
