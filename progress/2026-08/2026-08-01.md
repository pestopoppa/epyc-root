### 3. The GPU cutover was a no-op until the last hour

`_append_cpu_only_device_args` appended `--device none --device-draft none` to **every**
default-builder role, and `_build_role_command` never read `flags["device"]`. The launcher resolved
the correct HIP binary and then disabled every device on it.

| | before | after |
|---|---|---|
| VRAM used | 13 MB of 68.7 GB | **53.6 GB** |
| `architect_general` argv | `--device none --device-draft none` | `--device ROCm0 -ngl all` |
| host threads | `-t 24`, node-1 quarter | `-t 8` on `184-191`, `membind=3` |

It reported `healthy / attest ok` throughout, because the runtime attestation table checked every
declared field **except** `device`. Root cause ran deeper than the flag: `LD_LIBRARY_PATH` outranks
`RUNPATH`, and this host's ambient path contains `llama.cpp/build/bin`, so `/proc/<pid>/maps` showed
the HIP binary loading CPU-only ggml. `ld_library_path` is now derived from the same backend that
already chose `binary_dir`.
