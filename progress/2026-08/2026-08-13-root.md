## opencode "crash" diagnosis + hardening

**Problem.** opencode sessions (coordinator, build, mains) repeatedly wedged and were lost —
operator reported "crash" (pane dropped to a shell prompt, mains' panes disappeared) with no
dispatch/coordinator involvement, single-session and fleet-wide, under plumbing that had run
claude-code for days without issue.

**Root cause.** Forensic signature on the wedged processes: kernel state `T (stopped)`,
wchan `do_signal_stop`, with `SIGTSTP` (signal 20) pending in `ShdPnd` and `SIGCONT` unable to
resume (group-stop with the stop signal still pending). Two contributing factors:
- opencode ships a `Ctrl+Z → "Suspend terminal"` keybinding (`terminal_suspend`), default on, but
  installs **no `SIGTSTP`/`SIGTTIN`/`SIGTTOU` handler** (`SigCgt` bits 20/21/22 clear), so the
  suspend path stops it dead with no recovery. Verified in the running binary (`terminal_suspend:
  H("ctrl+z","Suspend terminal")`) and in `/proc/<pid>/status`.
- the mains additionally received `SIGHUP` (tmux window teardown) downstream of the stop — the
  panes disappeared because the wedged process was torn down.

**Changes.**
- `~/.config/opencode/opencode.jsonc` (config, outside repo): `keybinds.terminal_suspend: "none"` —
  disables the self-suspend path for all sessions.
- `scripts/coordination/opencode_guard.sh` (new): bash wrapper that `trap '' TSTP TTIN TTOU` before
  exec so spawned mains start immune to terminal stop signals (SIG_IGN inherits across exec).
  Verified: a process through the guard reports `SIGTSTP` ignored. Note: tmux default-shell is
  fish, and fish's `trap '' SIG` does NOT set SIG_IGN (verified) — hence the bash guard.
- `scripts/coordination/tmux_adapter.py`: `spawn` now launches through the guard
  (`/bin/bash opencode_guard.sh <shlex.quote(launch_cmd)>`).

**Verification.** Adapter test suites all green: `tests/test_tmux_adapter.py` 136 passed,
`scripts/coordination/tests/test_tmux_adapter_live.py` 2 passed, submission/doorbell/working_claim
101 passed (239 total).

**Monitoring.** `/tmp/opencode/crash_watch.py` runs in the background (polls `/proc` 1s, snapshots
state/`ShdPnd`/process tree/opencode.log on any stop, pending-signal, or exit) so a recurrence is
caught with its exact signal and full context. perf/ptrace/tracefs unavailable (non-root, no caps).

**Next.** Re-spawn mains so the config + guard take effect (config is read at start); watch
`/tmp/opencode/crash_watch.log` for a recurrence. If `SIGTSTP` still recurs on the *interactive*
sessions, the remaining external stop source is upstream of the pane (stale tmux clients / host
layer); the guard already covers spawned mains.
