## The three things worth carrying forward

**1. A tuning constant is valid only for the call shape it was measured against.** Five instances today
(`intra_op` per-call vs per-corpus, `intra_op` single-row vs batched, `-fa` per-model, quant CPU vs GPU,
worker count from core-count vs measurement). Every one degraded silently with all tests green. Compiled
to `wiki/benchmark-methodology.md`.

**2. Existence is not validity.** I declared OP-24 complete from *"every `emb_path` resolves to a file"* —
which a file truncated mid-write passes trivially. The operator challenged it; the honest answer was that
I was not certain. Proper verification: all **27,405** embeddings loaded, 0 corrupt, sampled **across the
reboot boundary** first because a post-reboot-only sample cannot detect pre-reboot damage. Full validation
cost **0.3 s at 7,270% CPU** — cheaper than the rebuild that was on the table, because validation is a
load-and-check while re-embedding is a forward pass.

**3. I retracted my own loudest claim.** I raised a P1 that production GPU serving silently ran CPU ggml.
It was an artifact of running `ldd` in my own shell rather than the launcher's composed environment. The
operator's falsifier — *"we've been measuring ~50 t/s for qwen3.6-27B which would be impossible on CPU"* —
was available the whole time and I did not seek it.
