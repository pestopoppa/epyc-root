## LRC P4.5 Phase A — journal soft-label extraction (2026-06-26)

### What was done

Implemented and ran `scripts/graph_router/extract_journal_soft_labels.py` (new script, epyc-orchestrator).

**Phase A: data extraction (zero inference, complete)**

540 per-qid soft-label records extracted from 141 journal trials with `question_results`. Dataset in `orchestration/reports/p45_soft_labels/`.

Key data facts discovered:
- The `route` field (not `route_used`) in compact question_results was present in 6,210/12,640 questions
- qid → question text recovery is **blocked**: journal stores only SHA256 hashes; the question pool JSONL doesn't match (questions come from dynamic HuggingFace loads at runtime)
- BGE server offline (ports 8090/8091) → Phase B (MLP embedding + retraining) blocked

**Routing findings — statistically validated (Wilson 95% CI, both arms n≥20):**

| Suite | frontdoor | better route | gain |
|-------|----------:|--------------|-----:|
| cruxeval | 0% (n=22) | worker_general 87% (n=188) | **+87pp** |
| cruxeval | 0% (n=22) | coder_escalation 47% (n=74) | +47pp |
| bigcodebench | 33% (n=165) | coder_escalation 69% (n=109) | **+36pp** |
| gpqa | 39% (n=245) | coder_escalation 65% (n=37) | **+26pp** |
| general | 84% (n=591) | architect_general 98% (n=48) | +14pp |

**Important correction**: my first-pass analysis flagged `simpleqa` (4.9% fd → "100% architect") and `mode_advantage_hard` as the top routing misses. **Both were sample-size noise** — the "architect 100%" on simpleqa was n=1. After applying Wilson CIs with n≥20 required on both arms, simpleqa drops out completely. simpleqa scores ~5% across *every* route (it's a capability/benchmark-difficulty ceiling — obscure factual recall that small local models can't do, not a routing problem). Caught via the `feedback_verify_test_method_before_calling_it_a_bug` discipline: check sample sizes before calling a gap a defect.

**Genuine actionable finding**: coding/reasoning suites (cruxeval, bigcodebench, gpqa) route to frontdoor when coder_escalation/worker_general handle them far better at comparable cost. cruxeval (code-output prediction) is the standout: frontdoor 0% → worker_general 87%. This is suite-level autopilot-eval evidence; production routing is per-request, so the value is in the LRC learning these content patterns (Phase B).
