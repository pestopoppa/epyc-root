## LRC P4.5 Phase B — KL soft-label A/B (NULL result, complete 2026-06-26)

### qid→text was never actually blocked

The Phase A "blocked" claim was an error: the journal qid is `sha1(f"{suite}\x00{prompt}")[:16]` (SHA1, null separator) — I'd tested SHA256 with `::`. Correct hash resolves **1367/1382 journal qids (98.9%)** and **540/540 soft-label records** to question-pool text. No blocker.

### Pipeline executed

Brought up 2 BGE servers (8090-8091, `-c 2048 -np 4` = 512 tokens/slot — the default `-c 512 -np 4` gave only 256 tokens/slot and rejected prompts). Wrote and ran two new scripts:
- `embed_soft_label_dataset.py` — qid→text resolve, BGE CLS embed, 1031-d features matching production RoutingClassifier (1024 BGE + 5 task-type + norm_ctx_len + has_images), per-item fallback + prompt truncation (1400 chars). 540/540 embedded.
- `train_routing_classifier_kl.py` — HARD (cross-entropy) vs SOFT (KL divergence) arms on identical split. KL logit gradient = (probs − soft_target).

### Result: robust NULL across 5 seeds

| seed | hard | soft | delta |
|------|-----:|-----:|------:|
| 1 | 53.7% | 53.7% | +0.000 |
| 7 | 49.1% | 49.1% | +0.000 |
| 13 | 51.8% | 51.8% | +0.000 |
| 42 | 53.7% | 52.8% | −0.009 |
| 99 | 55.6% | 55.6% | +0.000 |

Decision gate was ≥+1pp role-success accuracy. **Soft labels do not beat hard labels. Keep hard-label training.**

**Why** (mechanistic): role-success accuracy depends only on the argmax role; hard_label = argmax(soft) by construction, and both objectives converge to the same argmax decision boundary on this frontdoor-dominated (415/540), polarized data. Confirms the original handoff caveat with measurement. This is a legitimate negative result, not a failure.
