## Bugfix: autopilot dashboard HV plot — pareto_epoch_ts deinflation not applied to in-memory archive

**Problem**: User observed the GEPA+Pareto Frontier HV plot on the dashboard appeared stale — it showed max HV≈67.86 while the live autopilot log reported `Trial 966 complete: HV=76.0929`. Suspected real-time update failure.

**Investigation**: The backend endpoint (`/dashboard/api/pareto`, `dashboard.py:1652`) reads the journal file fresh on every request — no caching. It returned `journal_max_trial_id=967`, `state_trial_counter=968` (in-flight), `stale_state_warning=None`, and `hv_last=[967, 67.8619]`. The plot was genuinely up to date through trial 967.

**Root cause** (not a staleness bug — a metric inconsistency bug):

The dashboard reconstruction applies `pareto_epoch_ts` (2026-06-01T19:20:16Z) speed deinflation (×0.5) to pre-epoch trials before reconstructing the frontier. Five pre-epoch trials (77, 118, 146, 166, 207) had inflated speeds of 71–86 t/s (from the speed-double-count measurement bug that existed before June 1). Without deinflation those 5 entries stay on the raw frontier, giving HV=76.09. With deinflation their speed is halved to ~35–43 t/s and they get dominated by genuine post-epoch entries, leaving 7 frontier members and HV=67.86.

The autopilot's `_journal_archive_payload_for_authority()` called `reconstruct_archive_from_journal_rows()` without passing `deinflate_before_ts`/`deinflate_factor` — so the in-memory archive always used raw undeinflated objectives and `archive.hypervolume()` returned 76.09, while the dashboard returned 67.86. This also meant the autopilot's dominance checks for new trials incorrectly compared against the inflated pre-epoch frontier, potentially suppressing genuine frontier improvements.

**Fix** (`epyc-orchestrator` `scripts/autopilot/autopilot.py`, commit `b781c569`):

| Change | Location |
|--------|----------|
| Added `deinflate_before_ts` + `deinflate_factor` keyword params to `_journal_archive_payload_for_authority()` | line 2008 |
| Added `_deinflate_params_from_state()` helper that reads `pareto_epoch_ts` + `pareto_pre_epoch_speed_factor` from `state` | new ~line 2031 |
| `_apply_journal_archive_authority()` now extracts deinflation params from `state` and passes through | line 2055 |
| `_sync_startup_archive_from_journal_authority()` count call also passes deinflation params | line 2084 |
| `_run_loop_inner()` startup archive build now uses deinflation params | line 2426 |

**Verification**: Manual reconstruction confirmed: deinflated HV = **67.8619** (matches dashboard). 252 pareto/journal unit tests pass, 1 pre-existing unrelated failure (`ParetoArchive.save()` missing method, test `test_cluster_and_representative_persist_round_trip`).

**Effect on live run**: `_apply_journal_archive_authority` runs on every trial save. After the next save the in-memory archive will be re-synced with deinflation applied, removing the 5 inflated pre-epoch entries from the frontier and making `archive.hypervolume()` consistent with the dashboard. No restart required.
