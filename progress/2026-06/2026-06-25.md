## iqk-kernel port into v6 — STAGE 1 + STAGE 2 COMPLETE (full stack coverage)

**Goal**: graft ik_llama's `iqk_mul_mat` AVX-512 quantized-GEMM kernels into `production-consolidated-v6`
so v6 gets ik-class CPU speed AND keeps its framework/MTP/features (single-kernel consolidation, retires
the ik_llama dependency). Worktree `/mnt/raid0/llm/llama.cpp-v6-iqk` branch `iqk-port`. **Production
`/mnt/raid0/llm/llama.cpp` untouched on `production-consolidated-v5`** (verified each step). Flag-gated
`GGML_IQK=1`, single build, runtime A/B — no separate binary.

### Result — all 3 stack quant patterns covered, correct, measured uplift (same-build GGML_IQK on/off, llama-bench)

| Model | Path | Quant | Prefill pp512 | Decode tg128 | Correctness |
|-------|------|-------|---------------|--------------|-------------|
| gemma-4-31B | dense | Q4_K_M | 155.9→232.5 **+49%** | 8.66→9.34 **+7.9%** | byte-identical |
| gemma-4-26B-A4B | MoE | Q4_K_M | 577.7→707.5 **+22.5%** | 44.5→48.5 **+8.8%** | byte-identical |
| Qwen3.6-35B-A3B | MoE | Q8_0 | 401.0→500.6 **+24.9%** | 26.3→26.4 ~0 (BW-bound) | correct, FP-cascade |

Q8_0 decode neutral is expected: 8-bit is fully DRAM-BW-bound on EPYC, the kernel can't add headroom
(no regression). Q8_0 chat output is correct (Paris+primes, coherent) but not byte-identical (early
tokens identical → late FP-cascade) because the dequant/repack prefill path is distribution-preserving,
not bit-exact ([[project_q8_8x8_avx512bw_outcome]]) — eval-suite parity is the deploy gate, not bit-compare.

### Two root-cause fixes en route (debugged, not patched)

1. **Dequant crash** (commit `715383cde`): ASAN found a `type_traits[]` global-buffer-overflow READ —
   `is_dequant_better` returns ik-only repacked types (Q8_0_R8=208, Q8_K_R16=397) which were passed to
   v6's `ggml_row_size`, indexing past its 42-entry table. Fix = `iqk_row_size()` shim using ik's
   block-size formulas at the 3 dequant call sites. (Earlier "heap corruption" / "8-vs-16 packing"
   diagnoses were red herrings — ASAN gave the primitive evidence.)
2. **Prefill only +16% vs ik's +62%** (commit `c9bf4dad4`): `GGML_USE_CPU_REPACK` intercepted >85% of
   Q4_K matmuls on v6's generic-C kernel BEFORE the iqk hook. Fix = guard in
   `ggml_repack_get_optimal_repack_type` returning nullptr for iqk-supported types when GGML_IQK=1.
   This also revealed decode was repack-STARVED, not BW-capped — closing the guard restored +7.9–8.8%
   decode on Q4_K (superseding the earlier "decode neutral / BW-bound" read for 4-bit).
