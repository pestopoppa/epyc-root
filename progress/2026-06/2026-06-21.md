## A9 offline reward-oracle stress rows

Landed `epyc-orchestrator` `e5bb62a4` (`Add offline reward oracle stress
rows`) for the learned-routing NEXT-A2/A3 offline-quality-oracle lane. This
extends the A9 evaluator plumbing with a mandatory stress-row builder:

- `scripts/graph_router/build_offline_reward_oracle_stress_rows.py`;
- `tests/unit/test_offline_reward_oracle_stress_rows.py`.

The builder consumes scorer-input JSONL from
`build_offline_reward_oracle_rows.py` and emits grouped variants:

- `base`: original positive reference/response row;
- `paraphrase`: deterministic correct rewording wrapper;
- `confound`: plausible wrong response borrowed from a different row.

It deliberately strips any pre-existing `oracle_score`; candidate offline
reward models must score these rows before
`evaluate_offline_reward_oracle.py` is run. The committed tests cover grouped
variant generation, `--no-base`, CLI output, and malformed optional `q_reward`
fallback behavior.

## A9 NeuralTxt scorer adapter

Landed `epyc-orchestrator` `8fecf4a2` (`Add NeuralTxt offline reward scorer`)
to close the next scorer-tooling gap in the A9 offline quality-oracle lane.
Added:

- `scripts/graph_router/score_offline_reward_oracle_neuraltxt.py`;
- `tests/unit/test_offline_reward_oracle_neuraltxt_scorer.py`.

The adapter consumes scorer-input JSONL rows with `reference` and `response`,
loads the published `paperbd/neuraltxt-reward-tiny` checkpoint via the model
card recipe (`AutoModel` + tokenizer + mean/max pooling + `head_weights.pt`),
and writes `oracle_score` plus scorer metadata for downstream
`evaluate_offline_reward_oracle.py`. The script remains offline-only and
dependency-optional: it does not add `torch`/`transformers` to orchestrator
runtime dependencies and fails with an explicit invocation hint if those
packages are not supplied.
