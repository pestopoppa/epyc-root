## Summary

Reasoning traces are the dominant token cost on the architect lanes, and every lever that reduces them is a (model, quant, template) property, never a stack default. The per-request budget path is one field wide on the server, so the 2026-08-21 dive nominated **TALE-EP** — a prompt-level numeric budget that needs no server support — as the unblock, with an evaluation designed but not yet run and a fixed adoption rule. The effort ladder gained a third calibration axis (`template_sha`, amended 2026-08-21, practiced at CT-E7), and a binding constraint: effort must be steered by the prompt, never by a bare `max_tokens` cap. OPSDC's headline accuracy claim was corrected by its own authors to parity.

## Compiled Update — 2026-08-23: the per-request budget path is one field wide, TALE-EP is the unblock, and effort calibration is now template-stamped

**Confidence: verified** for the git/static-analysis/live-probe findings and the measured effort-ladder endpoints; **observation** for the pending-inference items (TALE-EP run, hybrid-SSM budget fix); **external** for paper- and vendor-reported numbers.

### The per-model calibration invariant is now enforceable — and a chat template is a calibration-voiding axis (E-7, amended 2026-08-21/22)

The effort ladder is a property of a **(model, quant) pair**, never of a role or the stack — levels are defined generically (prompt templates) but certified per model, and a role default is a (model × level) pair that a model or quant swap invalidates (E-7, 2026-08-10 → enforceable validator). Two adjacent dials already showed per-model divergence: native `<think>` non-termination (48% of items for Qwen3.6-35B-A3B even at a 16384 budget; whether Qwen3.5-122B-A10B-IQ2 does the same is a separate measurement) and spec-dec draft depth (122B-IQ2 → `n-max 2`; 27B-dense and 35B-A3B → `n-max 4`; inheriting one model's setting cost ~29% throughput). The **2026-08-21 amendment** adds the chat template to the voiding set: `architect-model-selection-bench.md:267` already ruled the prompt-template axis a per-model property, and the 2026-08-21 fleet sweep found **three distinct embedded templates across four production models** — so the certification stamp extends to `(model, quant, kernel/era, template_sha)`. The amendment is already **practiced**: the 2026-08-22 terse-pilot recalibration voided frontdoor + architect_general and re-measured both on the live path with template `1443ea9ab4bb` in the stamp (CT-E7, belief-graded Witnessed/Attested); the validator extension itself remains open. A binding design constraint travels with the ladder: **do NOT implement effort as a bare `max_tokens` cap** — a hard cap truncates the model mid-derivation and a truncated answer scores wrong (the "thinking-off loses" artifact is the same failure); steer effort by the PROMPT, with a cap at most a backstop that needs a graceful close (`--reasoning-budget-message`-style).

### TALE-EP is the unblock for per-request reasoning control — evidence-backed, evaluation designed, run still pending (RC-T1/T2, PRB-T2)

The per-request-budget handoff has been blocked since 2026-04-17 on server support for `thinking.budget_tokens` on hybrid SSM models (Steps 3–4 need a running server). The 2026-08-21 dive found the unblock path: **TALE-EP** (arXiv:2412.18547v5) is a *prompt*-level numeric budget — per-question budget estimated zero-shot by the model itself, placed in the prompt — needing **no server support at all**. Reported **67% token reduction at −2.72% average accuracy** (461.25 → 148.72 avg output tokens; 83.75% → 81.03%) and **+3.11% accuracy on GSM8K at 75.7% fewer tokens** (318.10 → 77.26); it supersedes stylistic conciseness prompting as the preferred form of the same intervention (intake-276's April 2026 prediction, now evidenced). Two caveats must travel with the headline: **(1)** generalisation is worse than the average — MathBench-College shows −8% (GPT-4o-mini) and −4% (GPT-4o) vs vanilla CoT; **(2)** the estimator costs an **extra model call per request** — invisible on closed APIs, **unmeasured on bandwidth-bound CPU decode**, so the 67% is not a net win until estimator overhead is charged. The evaluation is **designed but not run** (PRB-T4, gated on an exclusive inference window): the harness (`eval_tale_budget.py`, 2026-04-09) already exists and has **never been run**; it does not charge the estimator call, its prompt says "words" where the paper says "tokens", and neither anchor suite (GSM8K, MathBench) exists in our question pool — so the run can only measure our own stack, never confirm or refute the published numbers. Fixed decision rule: ADOPT only if ≥3 of 4 suites show ≥30% net token reduction at ≥−1.0pp accuracy with no suite worse than −3.0pp and TALE beating the static-limit control; ADOPT `static` instead if it matches at equal accuracy (then the estimator is pure overhead).

### OPSDC's accuracy claim corrected 2026-08-10: parity, not uplift

The earlier "+9–16 points" accuracy figure came from the v1 abstract and **the authors revised it away**. Current Table 2: Qwen3-8B MATH-500 **95.7 → 95.7 (+0.0)** at 56.9% reduction; Qwen3-14B **93.0 → 96.3 (+3.3)** at 56.3%. Per the authors' own Appendix D, the "+9–16" was the *base* model being mis-scored by a boxed-only grader. **The compression result stands; treat accuracy as parity, not uplift** — which is the right expectation anyway under the reasoning-is-rarely-harmful reading of the effort ladder. (`intake-110#record` claim_corrections claim_index 4; dive-verified.)

### The `--jinja` workaround is obsolete (PRB-T1) — and the body→template route is exactly one field wide (PRB-T3)

The 2026-04-15 workaround dropping `--jinja` for architect_general (commit `0879ed56`, guarding a Qwen3.5-122B hybrid `<think>`-loop) was **reversed 2026-06-26** (commit `f4a8a3ca`) and `--jinja` has been on for the role ever since: compiled priors emit `jinja: true`, and the J12 gate passed 2026-07-06 (0 think-leaks, n=15). Neither Qwen3.8 template defect that re-opened the question post-dates the workaround's motivation (they are four months younger and live in a different template), so no action was needed — **except** a residual defect: `orchestrator_stack.py:1397-1402` still carries the reversed policy as a comment and a live fallback default that silently re-inerts `enable_thinking=false` if the compiled priors ever return `{}` for the role — a real possibility given the **three-plane divergence** (stack template names Qwen3.8-27B, compiled priors Qwen3.6-27B, master registry `qwen36_27b_mtp_q8`; compiled priors not regenerated since the 2026-08-20 template swap — unverified whether staging or drift). The 2026-08-21 static dive also closed PRB-T3 **decisively**: a top-level `reasoning_effort` is **silently dropped** on frozen v9 — 0 occurrences tree-wide, jinja globals are a closed literal (`common/chat.cpp:883-895`), and `chat_template_kwargs` is the **only** body→template route (`server-common.cpp:1073-1077` two-layer merge). Live-confirmed the same day via `/apply-template`: a top-level `reasoning_effort: low` renders **byte-identical to a no-kwargs request (59 B both)**, while `chat_template_kwargs: {reasoning_effort: low}` renders the steering instruction (225 B). Any orchestrator code setting a top-level `reasoning_effort` is a no-op today — the same silent-no-op shape intake-946 records for a top-level `enable_thinking`.

### The stop-signal abstraction is designed, but the hard-cap producer still lacks the hybrid-SSM fix

The per-request budget path's root cause was traced 2026-04-17: on **hybrid SSM+MoE models**, `budget_tokens=0` fails because the reasoning-budget sampler state machine (IDLE→COUNTING→FORCING→DONE in `reasoning-budget.cpp`) must detect `<think>` in the prefill before promoting to FORCING, while the SSM recurrent layers update state during generation (`llama-context.cpp:3345-3354`) — the first generated token after `<think>` commits the model to a reasoning trajectory even though the sampler is about to force `</think>` (works correctly on pure MoE). Fix candidates A (force FORCING before first token / strip `<think>` from SSM prefill) and B (suppress the think scaffold at budget=0 in the chat template) are unimplemented — Steps 3–4 need a running server. The **2026-07-29 design** wraps whatever producers land behind a `StopSignal` contract (`producer: hard_cap | certainty_probe | draft_hidden_exit`; `disposition: continue | request_close_think | abstain`; evidence-ref; optional confidence): a deterministic arbiter where `hard_cap` is authoritative once its state machine reaches the forcing boundary and **every other producer is advisory and fail-closed** (missing evidence, unsupported architecture, or disagreement ⇒ `continue`), one advisory producer per explicit experiment identifier, records retained for deterministic replay. The candidate advisory producers are CGR-style certainty probing (intake-566; caveats: bimodal brittleness, ASRR's non-zero ~1.2% pass@1 loss) and SpecExit-style draft-hidden-state exit (intake-592; inherits the shelved spec-dec gating issue at bs=1). Note the **DeepConf-offline spike is already a decisive negative** (2026-05-24): confidence-weighted vote ties plain majority, and the confidence signal is anti-correlated with correctness (overconfident on wrong short answers) — the stop-signal design must not be funded from that family. The design changes no production sampler, server, or kernel.

## Key Findings

- **Per-request budget control is blocked one field wide** — `budget_tokens` fails at 0 on hybrid SSM models (state machine must detect `<think>` prefill before FORCING); **TALE-EP** (prompt-level numeric budget, zero server support) is the unblock, reported 67% token cut at −2.72pp, estimator call uncharged, MathBench worse — evaluation designed, not run, with a fixed adoption rule (≥3/4 suites at ≥30% reduction, ≥−1.0pp, none worse than −3.0pp).
- **Effort calibration is per (model, quant, template_sha)** — the 2026-08-21 amendment adds the chat template to the voiding set (three embedded templates across four production models); already practiced at CT-E7 with template `1443ea9ab4bb` in the stamp; never implement effort as a bare `max_tokens` cap.
- **OPSDC's accuracy claim is parity, not uplift** — the "+9–16pp" figure was the base model mis-scored by a boxed-only grader; corrected by the authors (Appendix D), current table Qwen3-8B +0.0 / Qwen3-14B +3.3 at ~56% reduction.
- **The stop-signal abstraction is designed but unfunded** — `hard_cap` authoritative at the forcing boundary, every other producer advisory and fail-closed; the DeepConf-offline spike is a decisive negative (confidence anti-correlated with correctness).
