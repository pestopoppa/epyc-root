# Prospective host supervision activation receipts

Future canonical installer source can opt in with `--all --capture-activation`. It preflights the regular canonical source, source-byte agreement, registry snapshot, backup directory and writable receipt paths before fetch/pin/backup/cron mutations. Both producer and tick run as node. Ordinary `--all`, process-substitution/outside-source callers, dry runs and fleet-watch-only keep their existing behavior; capture with fleet-watch-only refuses argument misuse. Publication alone deploys none of these changes.

`host_supervision_activation.py` records immutable native dependency rows for installation and a later eligible heartbeat, binding installer source, supervisor pin, registry bytes (snapshot only, not deployment proof), cron backup and the selected actual cron readback. Native pending and consumed markers are separate. Duplicate keys, traversal, symlink/nonregular paths, altered/resealed records and invalid chronology refuse; activation locking serializes producer/callback, and recovery preserves original marker bytes. A capture/readback failure after cron application exits explicitly without claiming rollback: installation may already have applied.

After the tick's state publication, a nondry tick imports the adapter from its published code root only if real pending JSON markers exist. The adapter reads and fsyncs the same opened state FD and parent directory before eligibility and publication. Read/sync failure retains pending and emits no heartbeat receipt. No-marker ticks do no adapter import, state read/sync, lock or native write. Callback errors preserve tick liveness/state and report through stdout logging; the optional callback runs after the regular hygiene log flush.

The heartbeat means first eligible post-marker state observed by the callback, not first physical heartbeat, atomic state/marker race exclusion or power-loss proof. Registry bytes are a canonical snapshot, not an independently observed deployed projection. Records stay dependency-evidence-only, ungraded: no ClaimTuple, support frame, measurement tuple, witness or grading ladder until a human-approved shared carrier/warrant exists. Original OP73 bootstrap/PIN00e receipts remain unchanged and are excluded from retroactive capture.

The existing native CI verifier independently observes synthetic source conformance and uses the existing shared grader; this outer fixture observation is separate from the ungraded operational rows.
