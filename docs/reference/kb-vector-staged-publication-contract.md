# KB individual vector publication

`kb_rag.build_index` and `update_files` serialize each NPZ to an owned exclusive sibling temporary file. Serialization and close must succeed before same-filesystem `os.replace` publishes the canonical name. Before successful replacement, partial serialization or replacement refusal leaves prior canonical bytes intact; an absent target stays absent. Caught exceptions remove only the owned temporary file and propagate the original failure. Existing regular-file permissions are copied; absent targets use standard0666 creation subject to umask. NPZ key `emb`, canonical names, catalog/FTS/caps/query behavior and native dependency scope remain unchanged.

This is individual file publication, not a DB/filesystem transaction. Successful replacement followed by later SQL/native-record failure can still leave changed vector bytes; crash cleanup, concurrent writers, ownership/ACL/xattr preservation and vector attestation are not supplied. Native catalog dependencies identify logical SQLite state only. No fsync/durability guarantee is added.
