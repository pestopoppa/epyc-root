# Calibration input byte bindings: non-inference evidence dependency

Calibration receipts now carry an additive `input_binding` field. Its versioned schema is `typed_decisions.calibration_inputs.v1`; it identifies exactly `state_file`, `questions_file`, and `labels_file`, each with a lowercase SHA-256 of the original bytes, their byte length, and an optional bounded path hint. The CLI reads each file once and hashes and parses that same byte buffer, using UTF-8 and universal-newline behavior compatible with the prior text readers. Full paths and contents are not copied into the receipt.

CLI-produced bindings use `method: cli_read_once`. Optional metadata supplied through the direct API is strictly validated and always stamped `method: caller_asserted`; absent metadata remains `null`. Callers cannot assert CLI custody. The validator requires the exact schema and keys, a 64-character lowercase hexadecimal digest, a nonnegative integer byte length (not a boolean), and a nonempty printable path hint no longer than 128 characters without path separators. Invalid metadata is rejected before a primitives call. Hashes are never synthesized from parsed or reserialized values.

This identity is a provenance dependency for future calibration evidence, not proof that the original files are independently available, that labels are correct, or that calibration is valid. Existing rows, ECE/Brier/accuracy and reliability-bin definitions, metric directions, local-confidence semantics, and shared provenance consumers remain unchanged. No model pin, metric, grader, admission rule, historical backfill, or calibration-quality claim is added. TD-18's broader receipt-upgrade work and the live TD-16, TD-29, and TD-1d.3 gates remain separate.
