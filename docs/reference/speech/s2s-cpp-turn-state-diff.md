**Ours**: `epyc-orchestrator/src/voice/controller.py` (a transport-neutral controller: one active turn, `cancel()` / `apply_retain_cancel_choice()`, ordered cleanup hooks); CS-18 (retain/cancel decision through the existing cancel path), CS-23 (cancel chain: queued audio, then interlocutor generation, then vocoder, then orchestrator), CS-22.V1 (VAD grid), CS-47 (turn-end bake-off), [`turn-taking-measurands.md`](turn-taking-measurands.md). | s2s.cpp element (pinned) | Default / behaviour | Our equivalent | Disposition |
|---|---|---|---|
| States IDLE, USER_SPEAKING, PENDING_END (`C:27`, ARCH 76-85, H 8-15) plus a `committed` flag and revision counter | 3 phases; commit returns to IDLE (`C:255-263`) | None; the controller starts at `respond(turn)` with the turn already delimited | **No counterpart.** Reference for the CS-22 state design |
| `vad_threshold` 0.6 / `vad_neg_threshold` 0.45 (H 65-66; ARCH 129-130) | Silero start at 0.6, stay while at or above 0.45 (hysteresis) | CS-22.V1 Silero threshold grid {0.35, 0.5, 0.6} | **Sweep starting point (CS-22.V1)**: add 0.6/0.45 as a named hysteresis reference row |
| `min_speech_ms` 192 (H 67) | opens a turn while the assistant is silent | CS-22.V1 min_speech_ms {100, 250} | **Sweep starting point (CS-22.V1)**; 192 sits between our two grid values |
| `min_silence_ms` 64 (H 69) | speech-to-silence boundary that triggers the end-of-turn classifier | CS-22.V1 min_silence_ms {100, 300, 700, 1200} | **Sweep starting point (CS-22.V1)**; 64 is below our grid; add as a low anchor only |

## 2. Revision, release and the recognizer/responder split

| s2s.cpp element | Behaviour | Ours | Disposition |
|---|---|---|---|
| Turn identity + revision counter; `TURN_RESUMED` (`C:300-309`, H 58) | a speaker who resumes before the turn is final stays in the same turn, next revision; the previous revision's answer is dropped before anyone hears it; the whole utterance goes to the recognizer again (ARCH 115-121) | `VoiceTurn` carries `turn_id`; one active turn, a second `respond()` is refused with "another voice turn is already active" (`controller.py:74-122`) | **Conflicts with CS-18/CS-23 cancel semantics** if lifted as is: dropping an unheard answer silently is a cancel without the CS-23 ordered hooks, and our cancel names session and turn. Design a revision step as "cancel via CS-23 chain, then new turn_id" rather than an in-place void |
| `release` / `TURN_FINAL` (H 120-124; `C:220-243`; V:1038) | answer is "ready to be heard" only after grace has run and the responder released; repeat releases are no-ops | none | **No counterpart**; candidate for CS-22 design, since it is what makes early compute under a held silence safe |
| Recognizer (`Recognizer-N`) / responder (`Responder-N`) threads, queues between them; responder copies settings and history when it picks a turn up; superseded revision gets no recognition (ARCH 37-66) | recognition and answer are decoupled so a stuck LLM request never blocks live recognition | cascade + interlocutor backends behind one controller, single active turn | **No counterpart** (our STT/LLM/TTS are separate services with their own queues); keep as a reference for CS-8 streaming-STT latency work |
| Session lock shared by reader and responder; session itself holds no lock (H 113-118) | caller serialises | `_state_lock` in the controller | Compatible |

## 3. Barge-in and the cancel flag

| s2s.cpp element | Behaviour | Ours | Disposition |
|---|---|---|---|
| `barge_in_ms` 384 (H 68; `C:309-311`) | while the assistant holds the floor, speech must last 384 ms (twice `min_speech_ms`) because the echo canceller leaves a residue | CS-23 barge-in policy ablation (CS-49); echo cancellation deferred to the client (D7) | **Sweep starting point (CS-47 / CS-49 policy sweep)**. Caution: 384 ms is calibrated against their server-side LocalVQE echo canceller (ARCH 292-333); with AEC deferred to the client (D7) the residue differs, so re-sweep, do not inherit |
| `set_speaking(bool)` (H 118; V:1387) | the session is told whether the assistant holds the floor; that alone turns a speech start into a barge-in | no equivalent signal into a detector; the controller knows the active turn | **No counterpart** yet; the active-turn state is the natural source |
| `BARGE_IN` handler (V:1058-1066): `conn->cancel.store(true)` on a shared `std::atomic<bool>`, polled by synthesis and by the LLM HTTP request (`src/llm-client.cpp:330, 390, 407`; `src/http-client.h:87-91`), then `response.cancelled`; cleared when the next answer starts (V:780) | one boolean cancels everything downstream, unordered | `cancel()` runs ordered hooks: queued audio, then generation, vocoder, orchestrator (`controller.py:165-193`), each attempted, errors aggregated | **Conflicts with CS-23**: a single flag has no stop-queue-first ordering and no per-hook completion timestamps, which our cancel-latency measurand needs (turn-taking-measurands cancel latency p50/p95). Lift only the idea of one flag polled by long HTTP calls for the `cancel_orchestrator` hook |
| Every barge-in cancels | no retain path; "of which nothing was heard is not filed" (ARCH 168-170) | CS-18: "yeah, exactly" **retains** the result, "no, forget that" cancels (`apply_retain_cancel_choice`) | **Conflicts with CS-18**: s2s.cpp has no backchannel-retain semantics. A 384 ms threshold cannot separate a backchannel from an interruption; our backchannel stratum (CS-45) must decide, so this default cannot be adopted as a policy |
| Client flushes playback and keeps what was heard (ARCH 160-166) | the unit-level played-sample accounting decides what enters history | CS-23 "stop the queued audio" | Compatible in intent; the heard-prefix bookkeeping is a **no counterpart** idea worth a CS-23 note |

## 4. Summary for the sweeps

Starting points to register in the run plans: CS-22.V1 (hysteresis pair 0.6/0.45, min_speech 192, min_silence 64 as a low anchor, speech_pad 500 as a high anchor); CS-47 (turn_threshold 0.5 as a named reference row only, incomplete_delay 600, turn_max_wait 2000, reopen_grace 800, continuation 192, barge-in 384 re-swept without their AEC). Conflicts to resolve before CS-23 implementation: unordered single cancel flag versus ordered hooks; silent revision drop versus explicit cancel; unconditional barge-in cancel versus the CS-18 retain choice. These defaults are a single implementation's choices, measured on their own hardware and models; they are priors for a sweep, not evidence about our stack.
