# DTAP additive native failure ledger

`harness.run_matrix` writes `failure_ledger.json` beside its existing matrix after returned runs and the existing native timeout capture finish. It preserves each case/arm/seed, original typed outcome, completion/timeout state and closed trace reference. A trace hash is reported only after native chain/returned trace-ID verification and matching before/after bytes; missing or changed traces explicitly remain unavailable. The original RunResult serialization, judges, task/attack outcomes, counters, denominators, matrix JSON and timeout receipt authority remain unchanged. Unexpected execution exceptions continue to propagate; the sidecar is not promised when execution itself raises.

The sidecar carries failure type, a hash of the original failure object and allowlisted timeout counts/flags; raw messages/nested API bodies remain solely in original native custody. Native benign task_success is higher-better; nonbenign attack_success is lower-better. Native failures remain failures and unresolved primary booleans remain unresolved. First-try valid-call, repair/recovery, no-valid-call and separate verifier results stay unmeasured/unmapped when no native event defines them.

Token counts come only from complete nonnegative nonboolean integer prompt/completion pairs reported for successful endpoint responses. Missing/inconsistent usage is null; successful-response coverage is separate from total-attempt cost, which remains incomplete because failed/unobserved requests and retries have no complete usage. No token estimate or inferred repair denominator is added.

Optional repeated `matrix --compare-arm BASELINE:CANDIDATE` validates distinct declared unique arms and compares only matching case/seed units. No comparator is inferred when absent. Gain/give-back direction follows the native metric; missing pairs, native failures and null values have separate counts. This descriptive report does not replace grading or supply a new ClaimTuple ladder.
