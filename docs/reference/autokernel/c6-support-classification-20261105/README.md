# C6 support census: unsupported case classification

The paired, seed-71 census is a **descriptive support comparison**, not a correctness or promotion gate. Its corrected image reported 326 unsupported `MUL_MAT` and 2,229 unsupported `FLASH_ATTN_EXT` cases; the baseline reported the same counts and the same per-identity support status. The only case-status changes in the two suites were the two q4_K n=4 `MUL_MAT` failures becoming passes. Images differ in libraries and instrumentation, so this comparison does not isolate a sole cause. The zero-unsupported full-suite rule remains unchanged.

All 326 unsupported `MUL_MAT` cases have an F16 right operand and a non-F16 left operand: 62 f32/f16 and 33 each for eight quantized left types. The pinned base's `ggml/src/ggml-cuda/ggml-cuda.cu` lines 4904–4913 explicitly returns false for this type combination, before kernel dispatch. The retained candidate patches do not modify that file. This supports an explicit backend limitation, not proof that lifting the guard would compute correctly.

For `FLASH_ATTN_EXT`, the base's `ggml/src/ggml-cuda/fattn.cu` lines 461–479 and 523–585 reject unsupported KV types, combinations and head/GQA shapes; lines 752–753 expose the selected kernel's `NONE` result as unsupported. The build receipt records `GGML_CUDA_FA_ALL_QUANTS=OFF`. Among the 2,229 unsupported cases, 1,344 have q4_1, q5_0, q5_1 or iq4_nl KV types: the first three are excluded with that flag off, while iq4_nl is excluded by the type switch regardless. Other restrictions may overlap; the remaining 885 are **not** assigned a unique cause here. In particular, this count does not prove that enabling the flag would make all 1,344 supported, nor that the remaining cases need a new kernel rather than a supported fallback.
