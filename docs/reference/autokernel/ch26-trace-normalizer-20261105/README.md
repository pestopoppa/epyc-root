# CH-26 scheduler normalizer prototype

`trace_normalizer.py` decodes the existing producer's raw `PERF_RECORD_SAMPLE` body using the supplied tracefs `sched_switch` format, checks event and CPU identity and reconstructs each observed per-CPU switch chain. It rejects malformed layouts, unknown or mismatched event sources, truncation, nonmonotonic events, broken chains and an unbracketed request. Run the six synthetic controls with `python3 -m unittest -v test_trace_normalizer` in this directory.

This is an offline prototype, not a live row, a loss-accounted observer, or a floor-admission predicate. Ring decoding and producer integration, authenticated tracefs format and FD attributes, raw snapshot custody, event loss accounting, CPU topology and thread identity, interrupt nesting and contention, observer overhead, and integration and qualification on the target host remain unproved. Apparent chain continuity cannot prove absence of unobserved events. Output always marks coverage and loss unknown, placement and contention unproven, and measurement admission none. The bracket requirement is deliberately conservative and may reject an idle CPU whose request contains no switch.

The previously retained `akagg-ch26b-mmap-abi-r2-20261102` packet contains four single-switch child-scoped raw perf samples. Run `python3 replay_retained.py` to check the pinned manifest SHA-256 `57ff7749b88c79078afd42a62b7a19b487b92d8111b98d398eeb0032aac97d77`, ring digests, event and CPU identities, and the declared child PID. On 2026-11-05 it decoded all four. One event per CPU cannot verify a continuous switch chain, and the input's tracepoint format and source metadata remain within the original producer trust boundary. Current tracefs format access was denied, so correspondence to the current host was not verified. No new measurement was run.
