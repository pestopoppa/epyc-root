# CH-31 diagnostic instrumentation candidate

`ch31-instrument.patch` targets C5 base `c72ec82f5417bb2937310326120f149b665e8400`. It is an **unbuilt, unrun diagnostic candidate**, not a kernel fix or a production image. When `CH31_TRACE_DIR` is set, the Linux hook selects only `node_13` `MUL_MAT`, records tensor metadata and the top-level `iqk`, `tinyblas-original`, `tinyblas-converted`, or `generic-vecdot` path, and adds two all-worker barriers around rank-0 metadata capture. Without that variable the hook takes no capture barriers. These barriers alter synchronization; a bounded runtime fixture must establish participation and absence of deadlock before publication. Static tests do not prove either. Non-Linux capture is disabled.

**Tensor-byte capture is entirely disabled.** Neither `src0` nor `src1` is proven to be non-weight data; no existing independent verifier binds a live buffer range to non-weight provenance. The hook reads tensor descriptors only and emits `activation_capture=UNAVAILABLE`. A future capture mechanism requires independent authentication of the actual buffer and range, not a caller-supplied flag or address. The hook requires caller-supplied model, pregrant receipt and patch SHA-256 claims; it does not verify them. A future launcher must independently establish their pregrant custody.

Metadata and route files are separate: absence of either, a partial or unknown route, duplicate descriptors, malformed identity or invalid tensor layout is refused. File existence alone does not establish a complete run, successful computation or trustworthy source identity. A future launcher and consumer must establish an exclusively owned scratch directory, prevent path substitution, and authenticate and retain the finished files. The hook uses exclusive creation for individual files but does not itself establish directory custody. Its event cap and I/O failures abort the diagnostic; EXL3 and Hadamard paths that return before the hook remain unknown. The IQK label does not identify its microkernel.

`compare_inputs.py STEM_A STEM_B --a-row N --b-row N` validates supported F32, F16 and Q8_0 metadata layouts, rejects empty or overlapping dimensions/strides and malformed or partial records, and displays route and descriptor comparisons. It does **not read tensor bytes**. Even for valid records it exits 2 and reports weight identity unproven, activation identity unavailable and `same_input_proven=false`. Tensor metadata and claimed model digests do not establish equality of in-memory inputs. No causal, performance or original Q38FN server conclusion follows from this candidate.

Before use, compile in an isolated C5 checkout and validate instrumentation identity, actual node-name matching in both graph modes, process cleanup, scratch custody and barrier behavior with bounded model-free fixtures. Establish independently authenticated buffer provenance before enabling any byte capture. Earlier snapshot-based drafts are superseded and must not run.
