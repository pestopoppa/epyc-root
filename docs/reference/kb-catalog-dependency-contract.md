# Native catalog dependency contract

APP source `efd67c526acedca69e15059846d86fa7bf63084f` contains the prospective writer and read-only exporter. The native `catalog_dependency` row is dependency evidence for a named completed-writer final transaction, not a ClaimTuple, scientific measurement or retrieval-quality result. No live index was opened or ingested by this implementation boundary.

Covered completed commits are `build_index` final commit, `update_files` final commit, `remove_files` final commit, parallel `_prepare_encoding_contract` final stamp-preparation commit, and `rebuild_catalog` final commit before VACUUM. Schema/FTS initialization, build checkpoints every25files, post-rebuild VACUUM and any outside writer are excluded. Earlier committed portions of an operation cannot be rolled back by a later failure; this is not whole-operation atomicity or concurrent-writer safety.

The producer streams canonical ordered original `chunk`, `index_meta`, and active `chunk_fts` content plus explicitly named original schema/index declarations. The dependency row/table/schema is excluded. Hash work scales with logical catalog content at each named boundary; no cost or performance result is claimed. Physical SQLite bytes, vector-file bytes, file existence and retrieval quality are outside the digest.

Stored tokenizer/width/caps/convention/model-path stamps are captured as native raw fields and remain authoritative. Already-loaded encoder identity is captured separately under the per-process state transaction, including the digest bound to the actual tokenizer construction buffer and the process-local generation. Legacy missing/empty stamps remain unknown. Removal records unknown loaded identity and never initializes a model. The reader opens mode=ro and one read snapshot, checks original producer row/table/contract/hash against current logical contents and returns unknown for absent historical rows; it never synthesizes a record or restamps history.

The row self-hash detects changed bytes relative to its stored checksum but is not an authenticated external anchor. An actor able to replace both the row and checksum can forge that pair. MAIN's independent trusted source/custody review supplies the external publication binding for accepted synthetic findings; the checksum alone does not.

NI07-12 fixes model-free removal rollback: pending physical deletion occurs only after successful catalog/native finalcommit and only for paths without surviving catalog references. Hash/commit failure preserves active rows and bytes. Postcommit cleanup errors leave orphan files, preserve committed catalog success and are reported separately through `embedding_cleanup_ok`, `orphaned_embeddings`, and `embedding_cleanup_errors`; cleanup status is not part of the logical catalog digest. No cross-process/concurrent catalog writer claim.

Write/record errors roll back the active transaction and close the connection through actual caller cleanup. Build/update vector writes and earlier existing commits remain outside that rollback. Canonical source enrollment, task states, document dependency custody and acceptance are MAIN-owned. No new authority/source class, ledger tuple producer or grading ladder is added.
