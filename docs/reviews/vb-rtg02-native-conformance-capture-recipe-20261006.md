# RTG02 bounded native conformance capture recipe

This package preserves a source-only, synthetic verification of the existing core-pool input-echo guard. It does not rebuild a pool, read a journal or question corpus, run inference, invoke model scoring, or change a scoring rule. The only programmatic scorer path exercised uses pure text predicates; explicit controls prove that `llm_judge`, `code_execution`, `math_verify`, `exact`, and unknown methods do not load the scorer.

The APP source proposal is pinned to commit [`ceb3ea84feba2dbc654987e3bc2ec12fb061f177`](https://github.com/pestopoppa/epyc-orchestrator/commit/ceb3ea84feba2dbc654987e3bc2ec12fb061f177). The bounded test selection has exactly 23 expected JUnit identities, recorded in `scripts/ci/rtg02-expected-cases.json`: all 14 existing controls relevant to input-echo behavior, the six new non-programmatic/cache-safety controls, and the three existing compatibility controls for LiveCodeBench shape, a constant expected answer in another suite, and a varying oracle. Other tests remain excluded by exact node ID. Existing selected case identities and assertions remain intact.

The APP module-time local source closure is 16 files: the selected test, `core_v2_select.py`, `experiment_journal.py`, `journal_shards.py`, `debug_scorer.py`, and the `src` / `src.autopilot_core` package initializers with their transitive local imports. The test's `--noconftest` invocation excludes APP `tests/conftest.py`; its exact bytes are retained in the readset to record the fixture boundary. `pyproject.toml`, `uv.lock`, and all expected identities are pinned as explicit reads. Source context binds every tracked source/config file in both ROOT and APP.

Use CPython `3.13.15`, Linux x86_64, with `scripts/ci/rtg02-hosted-requirements.txt`. The driver installs only its six locked pytest wheel dependencies using `--require-hashes --no-deps --only-binary=:all:` and records installed versions, platform, installer output, source context, and all explicit read bytes. The workflow is push-triggered only on `codex/ni08-rtg02-capture-20261006`, checks out the workflow commit and the fixed APP source SHA, initializes status before setup, and uploads retained outputs with `if: always()`.

The driver runs the 23 exact selected APP test node IDs with plugin autoload disabled, `--noconftest`, `/dev/null` configuration, APP as the explicit pytest root, empty configured `addopts`, and cacheprovider disabled. It confirms the interpreter is the isolated runner virtualenv, then checks original JUnit identities and requires exactly 23 passed with zero failures, errors, or skips. It projects the original fixture receipt through the existing `ci_conformance` adapter and `ClaimTuple.grade()`, requiring its existing `Judged / Located` ceiling. It hashes original artifacts before and after shared grading and retains the original JUnit, carrier receipt/request/readset, environment, dependency-install log, source context, and validation result. A failed capture remains an honest failed/unknown result and its originals are not resealed.

The verified local import closure is a static source review, not a runtime import trace. There is no claim about an actual pool, model quality, inference, verifier performance, or production frequency. No code-execution, LLM, or math verifier is called, and no core pool or ledger is written.
