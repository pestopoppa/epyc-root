# NI08 VB RAW-anchor bounded native-capture recipe (proposal)

This private proposal exercises the prospective RAW-source retention and adapter controls against
synthetic bytes. It does not fetch a live paper, write the canonical research intake or Vidya ledger,
backfill an existing anchor, run inference, or introduce a grading rule. The existing fixture receipt
is projected through the existing `ci_conformance` adapter and `claim_tuple.grade()`; expected
ceiling is `Judged/Located`.

The branch-filtered workflow checks out the exact ROOT recipe commit and the APP commit
`cfcf3768716de888a971bf66489397f5b91241df` only to bind the locked dependency file. It installs the
seven hash-locked binary wheels in an isolated Python 3.13.15 virtual environment, with pytest plugin
autoload and bytecode writes disabled. The driver uses `--noconftest` and selects 51 exact test
identities from `vb_raw_anchor_expected_cases.json`. The source set includes the raw-anchor store,
source verifier, frame/fold/impact and alias paths, existing native carrier/shared verifier, and the
four selected original test modules. No production server, model, or raw dataset is loaded.

The run retains the status, original JUnit, fixture receipt and readset, source-context manifest,
validation envelope, environment/install records, and generated fixture bundles. The validation
checks exact case identities and zero skips/failures/errors; one native receipt yields exactly one
shared-grade tuple; both Q/T values match the existing ceiling; and SHA-256 snapshots of all
shared-grade inputs match before and after projection. A failed setup or failed case remains a
retained failure and cannot be treated as conformance.

This is a prospective test recipe. It is not evidence of live-source accuracy, source-capture
coverage outside the selected cases, historical artifact recovery, or permission to merge the
source proposal or activate a production artifact root.
