# DCP-12 native A0 repeatability calibration, prospective protocol

The finite pilot describes these four source tasks in their native frontdoor role and prompt profile. Its repeatability is not a calibration of the delegation population used by DCP-6; transfer would require independent justification.

Question: how often does independently graded task correctness change between two executions with identical configured seed and settings on this fixed source-backed frontdoor-native graph? This is a four-task feasibility pilot, not a DCP-on comparison and not a population estimate or universal noise floor. Before DCP-6, use the pilot as a planning input with its severe uncertainty; a larger independently sampled task population and a specified treatment effect are needed for power decisions.

The four CF-3c coverage cases retain their original prompt, context and source grader: ifeval_2801, longcot_mini_18, ruler_niah_4096_25, gsm8k_01110. Schedule one baseline and two consecutive A0 reruns per case, fixed seed per task, identical role, temperature, graph limits and environment; a fresh private request workspace per execution. The sequential runs use the same model-visible current-task path, then archive the complete attempt before recreating an empty workspace. Compare the first generation request bodies byte-for-byte as a pairing witness; absent or unequal first requests make that pair ineligible for the primary flip rate, while preserving both outcomes. Roles and allowed helper calls are those of the pinned frontdoor graph. Both DCP feature flags are explicitly disabled and checked in each graph child, which writes a custody receipt. This profile bypasses the delegation route and does not measure DCP itself. Source, scoring data, server model, build, template, linkage, wire, native trajectories and usage follow the sealed CF-3c instrument; weights use its prior hash receipt and file identity, never a grant-time rehash. Allocator-owned publisher smoke first runs the offline calibration tests and records their exit code and output; failure refuses qualification before server startup. Official grants do not run tests. The publisher smoke uses two same-case runs and a separate oversized run only for transport, pairing-witness and budget qualification, never the official matrix.

Official execution requires its own unexpired allocator grant holding q0-q3 and gpu-quiet, no actual autopilot process, and four server cores. The quiet-host declaration is a booking requirement; neither a queued launcher nor a private server attests quiet. The runner verifies the grant before starting and before each official cell and preserves the exact grant bytes, digest, timestamp and process-scan visibility; it refuses an unreadable live-process scan. The publisher's four-core smoke is exempt from the whole-host condition and supplies no performance or flip metrics. Official scratch remains under the DCP-12 root; publisher smoke writes to the allocator-owned FILLER_DRYRUN_DIR. No production configuration or services change. Stop after twelve observed cells, or on first UNKNOWN, STOP, deadline or custody failure including a mismatched first request; retain all outcomes, partial evidence and unattempted units; no retries or replacements.

The accuracy convention follows the native instrument: a terminal no-answer or exhausted budget is NA and a miss in the independently gradeable cohort; observed answers with absent or failed graders are grade_unavailable, and transport/instrument/custody failures UNKNOWN. Do not coerce missing grades or UNKNOWN to misses. The primary pairing uses baseline versus first rerun only, so each task contributes at most one independent pair. The second rerun is descriptive and cannot inflate the primary sample size. Flip rate is discordant correctness / fully paired eligible tasks, with all statuses and denominators separately reported, including NA pairs and unattempted. Keep the native result and wire receipts. Repeats share a task; they are not independently sampled tasks. Four pairs imply 25-point rate increments; with zero flips in four independent eligible pairs the one-sided 95% binomial upper bound is approximately 0.527. An observed zero or nonzero rate does not establish a universal floor. Report an exact binomial interval for the pilot if making uncertainty statements.

For a prospective two-sided exact McNemar test at alpha 0.05, the included calculator averages the exact conditional binomial rejection probability over Binomial(n, q), with q=p01+p10. Its illustrative alternative is p01=0.075, p10=0.025 (discordance 0.10, paired difference 0.05), independent task pairs, target power 0.80. It reports a curve, not an inferred treatment effect: select the first n meeting power from an appropriately fine grid and state all assumptions; alter q and effect for plausible scenarios and account for multiplicity and task clustering. This pilot cannot validate those assumptions. No adoption claim follows.
