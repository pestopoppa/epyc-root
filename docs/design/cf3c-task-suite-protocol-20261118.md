# CF-3c native REPL task-suite protocol

## Question and first shard

Can the declared deterministic history policies materially change the prompts of source-backed, model-driven frontdoor REPL trajectories? When they activate, what task answers, no-answer outcomes, tool re-fetches, token cost and wall time occur on the same fixed tasks and seeds? The 24-cell first shard is a diagnostic for activation and outcome capture. It cannot resolve the parent’s 1 percentage point adoption margin or warrant a deployment change.

The packet freezes four text tasks and one seed per task across six arms. REPL actions and history grow from turn one. The companion inventory preserves all 50 source cases with the image-input omissions and independently gradable cohort documented. The frozen future schedule holds 48 text cases at four repeats across six arms. It is custody for a subsequent design review. The launcher executes only the first shard. Cases with unavailable graders remain scheduled and their observed termination, tool calls and costs are retained. The first shard includes a long-prompt case to exercise pre-generation budget exhaustion. All selected tasks remain in their assigned cells even if they finish before any policy can activate. This schedule has no BAPS eligibility test, reserves or replacement draws.

## Intervention and execution

- **A0** uses the pinned graph’s `context_arm_ab` full-history renderer. All arms share the native prompt builder, per-observation source spill behavior, full verbatim log, REPL execution, parser, and graph end states. This is a private, source-pinned graph profile.
- **A1(k=4, 8, 12)** uses the pinned `ContextCompressor` on a paired message view of observed REPL turns, before native history rendering. Two positions stand for the initial system and task instruction. Within each executed action, the assistant position holds code and the tool position represents the actual output. Opaque IDs pair these positions for the compressor. Error-bearing results pass through the compressor’s native error classification. The graph still records the original code, output, error and offsets. Only replacement text selected by the compressor changes the rendered observation. The reported threshold counts the native compressor’s middle-zone tool or assistant-with-tool-call messages, with its original protected-zone geometry. The pair view applies the production algorithm to this experimental graph seam. The production OpenAI-compatible route has a different history carrier.
- **A2** preserves the newest three observed REPL actions and truncates older output after 180 characters with the declared omission marker. Code and the separate error field stay visible.
- **A3** requests keep-latest-without-historical-reasoning. The pinned graph’s history stores executed code, output and error. Historical reasoning has no carrier in that projection. The adapter records A3 inactive and keeps executable code intact. This produces a control-equivalent intervention at this seam.

Every primary native request carries a role, graph turn and one-based attempt ordinal within that turn. Graph-native continuations and retries each retain their own render receipt, wire exchange and reported usage. The transport hook checks the selected history block after the same control-token neutralization as the graph. Raw request, sent request, response bytes and their digests are preserved with the policy activation receipt and native trajectory. The graph executes in a private request-scoped workspace with edit mode `none`. The only extra read root is the current trial’s private REPL-artifact directory, so native spill pointers remain usable. Native session logs retain their exact-file capability checks. The source request scope refuses `run_python_code`, and the runner supplies no external tool or script registry. Gold records and scoring configuration stay in the outer scoring process, outside the REPL read scope. The frontdoor and bound REPL model helpers use the row’s private model endpoint. Calls to unbound roles or independent chat helpers fail explicitly. The runner verifies the served model, template file, linked library set, process affinity and listener ownership. The native transport override disables KV reuse across calls and saves both request versions.

The shared caps are 18 graph turns, at most 384 completion tokens per generation, a 16,384-token native graph prompt budget, 420 seconds wall per task and 10,800 seconds per four-core window. The serving kernel and model come from the sealed CMP4 receipt. All controls use the same role profile, seed pairing, transport, graph caps and logging. Qualification uses separate A0 runs for the short task and the oversized task. The short control must produce captured native generation with complete reported prompt and completion usage. The long control must yield a native pre-generation context-exhausted event with clean tokenizer custody and zero generation requests. Neither qualification outcome is part of the 24 scheduled results.

## Measurement and stopping

The pinned source answer scorer independently grades eligible terminal answers using their source expected value, method and configuration. Native terminal flags are observation fields. A graph terminal with no answer receives `NA`, including turn exhaustion, context exhaustion and an answer rescued at the turn limit without a native final action. Reaching the declared task wall allowance also receives `NA` after confirmed child exit and preserves its partial trajectory and available costs. An NA in the eligible accuracy cohort contributes a miss. A completed answer with an unavailable scorer records `grade_unavailable` and keeps its denominator status explicit. Native help-request detection is reported as a give-up proxy. Instrument, custody and transport failures are `UNKNOWN`. Observed tokens from completed generations and any fully received SSE prefix frames survive as lower bounds when a later request is interrupted. Each counter has its own observation and completeness count. Complete-cost means require terminal-verified native exchanges; counters recovered from an interrupted response prefix remain lower bounds. No estimated generation cost replaces server counts.

The expected diagnostic signal is at least one A1 or A2 change witnessed in a sent native request. Activation can be absent because the real tasks terminate too quickly or produce little eligible output. Four task blocks give a smallest possible observed task-accuracy step of 25 percentage points across the full shard. No comparison at this size can establish a 1-point margin. Review per-arm activation, outcomes, costs and retrieval counts after the first shard. If all cells are observed and no A1 or A2 solicitation changes the native history, mark scaling futility for this profile and leave the later frozen schedule idle. If a treatment activates, review its coverage and interval design before any scale-up. An inactive A3 stays an inactive control even if other policies activate.

Stop on completion of all 24 observed fixed cells. Stop on futility at the first instrument, transport or custody failure, the allocator STOP or deadline, or the window cap. Retain row-level UNKNOWN and unattempted counts and all available partial evidence. There are no automatic task retries or schedule substitutions. Graph-native task continuation is part of the tested trajectory. This diagnostic does not authorize production flags, scheduler changes, broader inference or adoption.
