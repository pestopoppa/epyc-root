# EV-15b: score-token read-out specification

This is a prospective instrument specification, not a reviewer-quality finding or a selector deployment. It does not replace EV-15a, EV-15c, EV-15d, EV-15e or the existing cross-family and evaluation gates.

1. Construct the exact prompt with the model's pinned chat template and force its assistant-generation prefix. Record the template and tokenizer identities, exact prefix bytes and token IDs, and the full prompt identity. The first scored position is completion position **0**, immediately after that prefix; do not take a later token. The pinned task uses no chain-of-thought in the response before the score.
2. The first implementation chooses nine scores, the single-character strings `1` through `9`, in that order; this is an implementation choice within the task’s single-digit alphabet, not a claim about the paper’s particular labels. For each supported tokenizer and actual prefix context, verify that each alternative is represented by exactly one distinct next-token ID and preserves the intended completion boundary. Bind the exact tokenizer identity and the resulting ordered string-to-token-ID mapping. A missing, multi-token, duplicate or context-ambiguous mapping is a refusal, not a scored result. No tokenizer has been tested merely by writing this specification.
3. Set temperature to exactly `1.0`; capture the score for each of those nine IDs at completion position 0 under that same prefix. Let their full-vocabulary log probabilities be `l_i`. Compute `w_i = exp(l_i - max(l))` and `p_i = w_i / sum(w)` for only those nine IDs. The subtraction is a numerically stable identity, not an extra temperature. Non-score tokens are excluded from this conditional distribution; no individual non-score token is allocated to a score. Keep original log probabilities and token IDs for audit rather than only the normalized vector.
4. Equivalently, for the unmasked full-vocabulary logits `z`, at T=1 the result is `exp(z_i)/sum_{j in scores} exp(z_j)`: the common full-vocabulary normalization cancels. This identity does not authorize a temperature-scaled or candidate-conditioned native distribution as a substitute. A counterexample and fixed vectors are in [test_ev15b_readout_spec.py](../../tests/test_ev15b_readout_spec.py).
5. This contract requires all nine scores for its exact normalization. A truncated head must not silently masquerade as complete. EV-15d separately owns its missing-score/retained-mass fallback and refusal-floor design; EV-15c separately owns thinking-token and template failure checks. Evidence of a prefix or position alone does not establish either guard.

The instrument does not set a reviewer acceptance threshold, prove tokenizer compatibility, choose a production model, supply model logprobs, or establish a scientific quality result. Live comparisons, objective-verifier precedence, presentation-order aggregation and promotion remain governed by their existing tasks and protocols.
