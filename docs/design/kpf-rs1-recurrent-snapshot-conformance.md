# KPF-RS-1: recurrent snapshot conformance design

Status: design only; no capture, kernel change or conformance result. Source baseline is experimental llama.cpp commit `8952a0f693fb923918157eb25117641b74766230`. All paths and line numbers below refer to that commit, not to the frozen production tree. Re-resolve the candidate and obtain source-bound upstream impact before editing it.

## What exists and what is missing

`src/llama-memory-recurrent.cpp:35-39,73-114` allocates per-layer `cache_r_l*` and `cache_s_l*`, plus `cache_ple_r_l*` where present, with `size * (1 + n_rs_seq)` rows. Buffers are initially cleared (`:117-125`). `src/llama-memory-recurrent.h:69-115` carries the cell ownership set, position, source and tail, per-sequence `rs_idx`, and the layer tensors. A cell can be shared: `seq_cp` attaches the destination to the source tail (`.cpp:246-280`). A bounded partial removal changes `rs_idx` and position instead of copying a snapshot (`:187-200`); `s_copy` later chooses a plane and resets the index (`:1296-1313`). Consequently, sequence number alone is not a physical row address.

The ordinary checkpoint writer resolves a logical current row using `rs_idx`, cell `src` and physical cell index (`.cpp:759-800`) and writes selected R/S/optional P rows (`:887-946`); the reader resets rollback indices (`:840-865`). It is not an all-snapshot dump. `tests/test-recurrent-state-rollback.cpp:11-17,94-167` fixes `n_seq_max=1`, tests rollback and full/partial restore via logits at `1e-5`, and includes a dirty destination. It neither compares all backing planes nor proves their contents belong to the intended sequence. The state source does not expose a per-plane written bit: do not infer one from a nonzero value, `rs_idx`, or allocation alone.

## Test-only capture interface

Add an opt-in test-only observer on the experimental candidate's recurrent memory object, invoked at a synchronized post-operation boundary. Enumerate every active layer's R, S and optional P tensor, all physical cells and every plane `0..n_rs_seq`; read full tensor rows through the backend tensor API after the owning backend is synchronized. Record failures or inaccessible buffers as **unsupported/unknown**, never empty bytes or a pass. Include tensor name, ggml type, full dimensions and strides, row byte count, backend/device, physical cell and plane, cell position, `src`, `src0`, `tail`, sorted owners, per-owner rollback index, and row bytes. Preserve the full raw manifest and per-row digests; aggregate using a versioned length-prefixed binary encoding (fixed-width little-endian integers, UTF-8 names with explicit lengths, stable tensor-name/layer, cell, plane order, then exact row bytes), SHA-256 and schema version. Reject duplicate identities, missing layers, unexpected byte counts, failed synchronization and incomplete enumeration. Record skipped/null layers explicitly.

Capture a separate **logical view** that maps each sequence's live cell and rollback index to its effective row. Keep physical mapping and shared-owner metadata alongside it: compare logical rows by sequence, logical position, tensor and plane semantics, not raw cell numbers across independently allocated contexts. A byte equality result is valid only when type, shape, representation and defined-state semantics are identical. CPU and gfx90a each compare with their own same-backend reference; no cross-backend byte-identity assumption.

Written/unwritten status must be supplied by test-only provenance instrumentation at each actual snapshot write, reset, copy, restore and reuse, including destination and logical position, rather than guessed from bytes. Unknown provenance remains unknown and fails a complete-capture gate. Capture bytes for unwritten planes as well, but do **not** assume an unused plane after restore must byte-match an unrelated fresh context: define the expected initialization/clear contract and legal retained bytes first. Use controlled poison patterns and distinct per-sequence histories to prove an unwritten plane cannot be selected or expose another sequence's state. If a mode does not promise clearing, compare defined rows and use explicit isolation/selection tests for undefined rows; report residual bytes without calling them equal or safe. If semantics cannot be established, report INCONCLUSIVE rather than normalize or discard the bytes.

## Paired experiments and negative controls

For each backend, run `np=1` and `np=4` with fixed model, tokens, batch geometry, sequence-to-cell mapping evidence and snapshot depth. The four-sequence case includes different histories, shared fork source, diverged children and reuse of a previously occupied cell. Capture after each operation and synchronization:

1. Fresh same-token prefill reference and repeated same-shape reference, establishing whether the relevant bytes are deterministic under that backend and schedule.
2. Full and partial checkpoint restore into both fresh and poison/other-sequence dirty destinations; compare the logical current state with its paired reference, and check the complete plane inventory and isolation as specified above.
3. Fork from a checkpoint, verify both parent and child ownership, then advance each independently; compare each applicable state with a matching same-token re-prefill reference and verify no unintended changes to other sequences.
4. Speculative rollback at each exercised depth, including nonzero `rs_idx`, followed by replay; compare the selected logical state and defined snapshot planes with a reference constructed using the same sequence and history. Preserve every attempted case and unsupported or failed operation.

Plant a test-only mutation at the actual snapshot-write operation that suppresses one named, otherwise-required write; record exact source patch/hash, target tensor/plane/position and observed write event. The honest control must pass under the same capture and the mutant must produce a specific row/provenance or isolation failure. Also include an unwritten-plane poison control that deliberately attempts an invalid selection and must be refused or detected. A crash, missing capture, or unrelated setup failure is INVALID, not successful mutation detection. The existing logits checks remain a separate observable, not a substitute for state-byte coverage.
