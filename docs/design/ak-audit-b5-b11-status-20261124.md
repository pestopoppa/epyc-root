## B9 — same-RESULT re-run guard: partial

`rowflow.py:7004` checks a FILED receipt, matching spec/code identity and current native result hash, and `:7056` logs `SAME-RESULT` on resume; `publish_row.py:985` and `:1056` warn at publish (`5e6064b1c`). These are warnings, not a refusal. The check is scoped to the same id and available recorded identity/digest, and it does not establish equivalence across successor ids. The complete-result no-auto-requeue rules (`smoke_verdict.py:80`; `544ca0b4a`, `f95b97193`) and SLOT-KEEP correction (`04d40f485`) address other paths and do not turn this warning into a re-run guard.

Proposed fix: at publish and explicit resume, refuse a matching filed result with unchanged sealed spec and code before archiving the receipt or scheduling work, and name the receipt, digest and resolution in the error. Provide an explicit owner-attributed override with a required reason for intentional additional work, logged durably; distinguish a resumable partial result from a terminal filed decision so legitimate continuation is possible. Define successor lineage matching using a durable identity rather than guessing from id alone, and test matching and changed result/spec/code, missing legacy receipts, terminal versus partial results, override, and no side effects on refusal.
