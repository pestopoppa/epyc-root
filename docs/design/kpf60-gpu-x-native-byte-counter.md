# KPF-60.GPU-X: native attention-KV byte accounting design

Status: design only, 2026-11-04. Source reviewed at experimental integrated llama.cpp commit `8952a0f693fb923918157eb25117641b74766230`. Re-resolve the full candidate and run source-bound impact analysis before implementation. No measurement, crossover result or authorization to inject hybrid chunks follows from this design.

## Question and quantity

For an existing sequence and a complete, resident position interval `[p0,p1)`, count the bytes of the attention K and V payload actually selected for a prospective chunk transfer, by layer and tensor, and distinguish it from serialization metadata and allocation. Record K and V dtype, dimensions, row layout, selected cell count, native read ranges, and byte totals. Count the bytes the selected representation would transfer: block scales and padding included when present. Recurrent state, allocator capacity, backend buffers, protocol headers and chunk-store overhead are separate fields; unknown costs stay unknown. A count alone is not an observed PCIe or NVMe transfer, and no hybrid state is made reusable by the counter.

## Source anchors and proposed implementation

- `src/llama-context.cpp:4243-4287` resolves a plain `llama_kv_cache`, deliberately refuses hybrid memory, synchronizes, and calls `chunk_export`. Keep this export and its refusal unchanged. Introduce a separate read-only, experimental measurement entry point, initially internal to the test executable, that synchronizes and selects either a plain attention cache or `llama_memory_hybrid::get_mem_attn()` (`src/llama-memory-hybrid.h:81-86`, `.cpp:217`). Any other memory implementation, null attention cache, SWA, mirrored cache, unsupported tensor layout or unresolved row size fails closed with an explicit reason; do not silently fall back to full hybrid serialization.
- `src/llama-kv-cache.cpp:2307-2378` already validates stream, range, and unique complete sequence positions and creates physical `cell_ranges_t`. Factor that selection into a shared read-only helper rather than duplicate it; preserve the export's existing `chunk_supported` checks, semantics and tests. The diagnostic counter may bypass *shift/reuse* eligibility only for explicitly recognized hybrid attention caches, never the unique-position, range or layout checks. Do not enable hybrid export, injection or RoPE shift.
- `src/llama-kv-cache.cpp:2927-3042` is the serialization source of truth: `state_write_meta` emits positions and sequence metadata; `state_write_data` emits layer headers and selected tensor ranges. Refactor its traversal into one shared visitor that reports each `write_tensor` operation as `(layer, K|V, tensor type, shape, stream, source offset, length)` and separately reports non-tensor writes. The normal writer must retain identical bytes and order. A counting sink uses checked 64-bit addition and rejects overflow, absent K, invalid bounds, unsupported quantization or an unrepresentable transposed V layout; count only existing V tensors and report their absence per layer. Use `ggml_row_size` for the actual K/V type and embedding extent; do not multiply by `ggml_type_size` as if a quantized element were independent. For transposed V, count the actual per-row selected reads and validate block alignment; otherwise report unsupported. Distinct ranges and shared physical cells must not be double-counted within the selected sequence interval. Do not infer per-sequence unique memory savings from the payload count.
- `llama_memory_hybrid::memory_breakdown` (`src/llama-memory-hybrid.cpp:195-202`) combines attention and recurrent allocations; it is unsuitable as chunk payload. If allocation is recorded, present per-backend attention allocation separately and label capacity/padding, without treating it as bytes transferred.

The native JSON record should contain source commit and dirty-state/build manifest, binary and mapped ggml digests, model identity, argv, sequence/range and complete cell count, context/KV configuration, per-layer data and tensor-read ranges, K total, V total, metadata total, and serialization total. Validate `total = K + V + metadata` with overflow checks. Emit explicit unsupported/error records with no numeric verdict. Model/launch inputs must be bound before the run; actual mapped libraries and HIP residency are captured during it. Capture the prospective write-side measurement warrant and project through the existing belief-kernel ladder before relying on the record.

## Calibration and acceptance before the 27B run

1. Use a tiny deterministic plain-attention fixture with known F16 K/V dimensions and filled sequence positions. Independently compute `cells × sum(ggml_row_size(K) + ggml_row_size(V))`, then compare it to the counted tensor reads and an actual serialized blob's exact length minus independently parsed metadata. Test at least two chunk lengths and fragmented physical ranges, plus identical selected range with shared cells. Verify every layer and K/V subtotal, not just the grand total.
2. Add hybrid fixture coverage with known attention and recurrent layers: populate both, count attention only, and confirm changing recurrent snapshot bytes does not change the attention payload. Compare against an independently constructed actual tensor read or serialization of the same attention component; the hybrid exporter must still refuse. Include missing position, duplicate position, invalid sequence, empty range, offset/size overflow, unsupported SWA/mirror, invalid dtype/layout, and transposed/block-quantized V refusal or verified cases. Check feature-off and legacy plain export byte identity.
3. CPU and HIP paths run their own synchronized fixture and compare counting to actual bytes on that backend; do not require CPU/GPU numeric KV values to match. During a HIP run prove own-process mapped ggml libraries and GPU residency. A dummy writer's size alone is not proof that a backend transfer happened.
4. Freeze model, build and manifest hashes, position intervals and chunk lengths, raw-record schema, backend/representation and failure handling before the target run. The 27B test reports each per-chunk count and payload bytes/token; missing or unsupported cells make that observation inconclusive. Present K/V payload, metadata and measured/unknown overhead separately. Preserve each attempt and failures.

After valid native counts, calculate per declared length `load_s = measured_chunk_bytes / bandwidth_bytes_per_s` and `recompute_s = tokens / prefill_tokens_per_s`, using the stated bandwidth and prefill provenance and units. A comparison based on prior bandwidth/rate measurements is a derived estimate, not an end-to-end measured crossover; evaluate variable per-chunk/header costs and confidence limitations. The earlier 65,536 B/token number remains an analytical estimate until the native counter is validated and run.
