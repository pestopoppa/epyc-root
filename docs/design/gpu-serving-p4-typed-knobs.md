## Contract

A candidate is exactly `{tenant_id: str, np_slots: int}`, with no extra keys, bool excluded from int, np_slots > 0 and tenant IDs drawn from an explicit reviewed allowlist populated only after P3-5. The actual measured bound must be computed at evaluation time for the selected tenant, actual launch mode, context and budget profile, rather than supplied by a strategy or copied from old stock/FF numbers. Default-off feature gating must precede reading candidate data or touching the store. Flag-off, missing/invalid flag, missing or stale/unknown tenant, unattested artifact, inconsistent model identity, unavailable measurement, unknown mode or budget, unmeasured context, malformed input and exceptions all refuse without changing the incumbent.

Use existing `scripts/server/gpu_shadow_lane.py::load_np_ceiling_policy(path=None, *, feats=None)` and `np_ceiling(policy, tenant_id, *, dynamic_budget_gib, slot_context_tokens, mode)`; `None` means refuse and context uses the next covering measured bucket, not extrapolation. The mode must be the selected tenant's mode, not a fallback; `tenant_id` maps via `Tenant.np_policy_tenant` rather than assuming policy key equals tenancy key. Use `scripts/server/gpu_shadow_lane_tenancy.py::load_tenancy` and `cross_validate(tenancy, policy)` to reject inconsistent artifact/policy data before evaluating. `resolve_lane_plan(...)` is proposal-only but invokes `build_tenant_launch_plan`; the typed admission seam should not invoke it if that would pull the compiler/kernel-store import seam into pure validation. Review and isolate a pure policy seam first; never turn a calculated plan into a launch command.

Bind trial proposals to policy identity/version and serving shape; immediately before any eventual control-plane request, re-read/revalidate so changed policy or mode cannot reuse stale authorization. If the effectful control-plane seam or a reviewed, authorized way to select tenant does not yet exist, return refusal. Do not implement an alternate launcher, registry mutation, restart, lane lifecycle or model download. The code is opt-in, shadow/eval only, and no implicit traffic admission follows from a validated candidate. No new runtime flag should be registered as available until the control-plane semantics and scope have been reviewed.

Treat every HTTP 500–599 from any invoked application/evaluation operation as failure of the trial and halt further actions for it; preserve status/evidence, do not classify a 5xx as success or silently retry to promote. Exceptions, missing responses, timeouts and non-success outcomes must also not authorize promotion. Do not infer that a previous successful HTTP response protects the current request. Automatic rollback semantics need an existing reviewed owner/control-plane contract; without one, do not introduce an independent lifecycle operation.

## Seeding and test seams

Follow `scripts/autopilot/seed_operator_strategies.py` and `scripts/autopilot/operator_seed_strategies.yaml`: the existing typed `SeedRow`, identifier audit, future/live binding distinction and repeatable strategy-store path are precedents, not permission to label an unbuilt surface live. Test seed generation on temporary directories using `tests/unit/test_seed_operator_strategies.py` patterns and `orchestration/repl_memory/strategy_store.py::StrategyStore`, with no access to the production store. Seeds are declarative suggestions only; mandatory runtime validation remains authoritative. Do not seed deleted tenant IDs or substitute placeholders as live strategies. The number of clean trials for widening stays unset until P4-1 review (P4-2).

Model-free tests with an explicitly injected policy and tenancy fixture should cover: flag off causes zero store/control-plane calls; unknown/missing tenants and deleted/unattested artifacts refuse; path/size/hash mismatch and invalid policy fail closed; positive integer and no extra knobs; each selected mode/budget/context uses its own measured frontier, exact ceiling admitted and ceiling+1 refused; unknown mode, unavailable budget, above-largest context and missing ceiling refuse; no cross-mode fallback; stale policy at actuation refuses; all 5xx values including 500 and 599 refuse, and transport errors do not count as success; no store or controller effect on refusals; repeated isolated seeding is idempotent; forbidden launch/registry/lifecycle APIs never called. Use fake data only for policy evaluation, never as proof of kernel-store identity, linkage, GPU residency or model presence. Tests must not trigger a server, hash/download model weights, touch the live strategy store, or invoke production.
