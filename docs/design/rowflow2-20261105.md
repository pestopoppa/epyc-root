## Model (P3.4)

- **Tokens:** `c0..c95`. SMT siblings follow their core. `gpu` is the MI210 plus host threads 184-191. Counters: `ram_gib`, `disk_gib`.
- **Smoke lane:** fixed cores c20-23 (+116-119). It is never granted to rows and is carved out of every expansion: `q0`→20 cores, `0-95`→92.
- **Spec:** the 12 fields (+ `quiet_reason`, `measured_ack`, `supersedes`). A grant = the declaration stamped with a window of `1.5 × max(estimate_s, min_window_s)`.
- **Tick:**
  1. `reconcile()`: measured busy per core, KFD, idle release after 2 samples (only once a grant has shown a busy core; quiet grants never release), overrun alert at 1.5× estimate, smoke deadline kill, **IDLE-HELD** (decision 9): a grant wholly idle for 300 s warns its owner once, for 900 s ends `rc=75` and is re-queued.
  2. `admit()`: strict priority by (rank, published_at, id).
  3. `file()`.
- **9 tunables:** `SMOKE_CORES`, `IDLE_SAMPLES=2`, `IDLE_PCT=2.0`, `SMOKE_DEADLINE_S=1200`, `OVERRUN_FACTOR=1.5`, `QUIET_MAX_RANK=10`, `FILE_OWNERLESS_S=1200`, `CLAIM_TTL_S=7200`, `IDLE_HELD_S=900` (the 9th, operator 2026-11-05; its warning `IDLE_WARN_S = IDLE_HELD_S // 3` and retry count `IDLE_HELD_RETRY = 1` are derived/fixed facts, not tunables — nothing among the 8 expresses a wall-clock idle budget).
- **No inference from job text, argv, OMP or regex.**

## Decisions made in the build

1. **Legacy → `gpu`.** A row needs the gpu if `regions` contains `mi210*` or `shape` is gpu/gpu-q3.
   - **exclusive** for `gpu-q3`, `quiet-host` or `admission_class` `block-timing-*` ("timing exclusive").
   - **shared** for correctness, diagnostic or block-correctness ("correctness shares").
   - **No declared class → exclusive** (conservative). Most live GPU rows carry no class, so owners should declare one at republish.
   - `184-191` without gpu → unmappable.
2. **Hold.** Only the first non-fitting row holds, and it holds tokens only (not RAM or disk). Its ETA is the end of the grants that free its soonest option. A worse-ranked row may take held tokens only if `now + window ≤ ETA`. Better-ranked rows are admitted before the hold exists.
3. **Over-declaration is refused, never shrunk.** A small job declares `any-N-of-qX`. A successor whose predecessor measured `busy_p95 < 0.25` of its cpus is refused without `measured_ack`.
4. **Smokes** are FIFO on the lane, one at a time. They never produce COMPLETE: a `.complete` without a grant is rejected.
6. **Backfilling replaces the hold budget (operator decision 2026-11-05).** The earlier daily `HOLD_BUDGET_QH` ledger is removed; `FILE_OWNERLESS_S=1200` is restored (8 tunables). The top waiting row computes its earliest feasible start (ETA = when running grants' ends free enough of its tokens); a lower row may take held tokens only if its estimated end is at or before that start, else it waits. No budget, no counter; same semantics as the frozen keeper's DRAIN "new rows only if they end before then". **No reservation when the start is unknown (2026-11-07, mirrored from the keeper's backfill-if-fits):** only the FIRST non-fitting row may hold, and it holds nothing when its ETA is not in the future (a needed grant has no end, or is past it) or lies beyond the longest busy window (`NO_RESERVE_UNKNOWN`; negative control in `tests/test_nohold_backfill_mirror.py`). The operator emergency stop `HOLD_<NAME>` matches exact names only; `*.lifted*` / `*.disabled*` / dangling links never hold (`operator_holds`).
7. **SMT siblings for timing rows (main-inf22 report, 2026-11-05).** A row may declare `timing: true` (legacy `block-timing-*` maps to it). A timing CPU grant holds the SMT siblings of its cores. Cores 88-95 have siblings 184-191, the MI210 host lane, so a timing row may use them only with `gpu: exclusive` (gpu-quiet); otherwise `validate` refuses a concrete q3/88-95 placement and `admit` strips 88-95 from class/any-N options, so `any-quarter` lands on q0-q2 (or waits). Correctness rows are unaffected; the gitnexus-q3 coexist shape (72-87, never 184-191) stays legal. Origin: iqk-q8-prefill-ab-r6 on q3 shared 8 of 24 decode cores with c6-gpu-27b-identity's host threads during a 27B reload; requests ran 20-70% slow (incident fixture `test_7`).
5. **Shadow** is read-only, enforced by a `sys.addaudithook` write guard under the flags dir. Live dry runs count as occupied tokens. Each id is logged once.

8. **GPU timing grants hold 88-95, never the rest of q3 (operator 2026-11-05, "Narrow + emergency deploy").** The mirror of decision 7: a `gpu: exclusive` (timing) row's grant is its declared cpus **plus** cores 88-95 — the SMT siblings of the host threads 184-191 the gpu token carries — and nothing else of q3; cores 72-87 stay grantable to any CPU row beside it, and a whole-q3 row waits because 88-95 are held. `gpu: shared` (correctness, production) rows hold the gpu token alone, unchanged. Implemented as `grant_need(spec)` = `parse_cpus` → `timing_need` (decision 7) → `gpu_timing_need` (adds 88-95; `Need.fixed` carries them for width needs); `admit`, `_pick`, `_make_hold` and `fits_need` honour it, and the test oracle (`rf2.oracle_need`) re-derives it independently. A timing row that needs a quieter neighbourhood declares it (`cpus: "72-87"` + `gpu: exclusive` = all of q3). Replaces the frozen keeper's "GPU timing holds all of q3" (rowflow `GPU_Q3_TOKENS`, same date, emergency-deployed): q38p4b-int8 was refused "q3 busy" by an 8-core AITER build on 80-87. Incident fixture `test_8`.

## Gate

  - no shared token

  - closed `.ended` reasons

- **Hypothesis fixtures.**
- **Whole-tick replay:** reconcile → admit → file + publish + fake filler.
- **Gated idle budget:** 0.5 q-h / 0.25 gpu-h per day, asserted on 4 seeds, with a negative control.
- **Incident fixtures:** shrink, gpu-quiet on CPU rows, rank-100 drain, GPU-blocked reservations starving smokes, smoke-as-COMPLETE, double grant, q3 timing grant without SMT siblings (7), GPU timing grant holding all of q3 (8).
- **Plain backfilling:** a backfill is granted iff `now + window <= top row's earliest start` (hypothesis), the top row's start is never delayed, negative control (fit check removed -> test fails).

**Hold price (reported, not gated):** 1.5–9.9 q-h and 0.07–0.97 gpu-h per synthetic day. Bounded by plain backfilling (decision 6); there is no budget.

9. **IDLE-HELD grants warn, then end `rc=75` and re-queue (operator 2026-11-05, "Warn now; auto-end in rowflow2").** rock-aiter-tests-r3-20261105 hung on a stale lock and held gpu-quiet + 88-95 at 0% for ~20 min (21:20-21:41Z) while 7 GPU rows queued; the frozen keeper logged `IDLE-HELD` every tick and told nobody (the earlier `IDLE-HELD q3` under kvu16g3-retune-r3 was the same silent signal). The frozen keeper now only *warns* (notify-only, `rowflow.idle_held_notify`: one `[warning]` to the owner after 300 s under 10 % busy, one repeat per 15 min, dedupe state `ws58-keeper-state/allocator/idle_held_warn.json`; emergency-deployed). rowflow2 acts: in `reconcile()` a grant is **wholly idle** in a sample when every core it holds reads `< IDLE_PCT` **and** (gpu `none`, or its own KFD pid set is *known* and empty); a grant with nothing measurable (no cores and no gpu, or an unmeasured side — core sample missing, poller pid invisible) is never idle, because an auto-END must not act on a guess. Continuous idleness `>= IDLE_WARN_S` (300 s) emits `('idle-warn', id, idle_s)` once per grant (`IDLE-HELD-WARN` line; the owner notification rides the cutover filler's notify path), `>= IDLE_HELD_S` (900 s) emits `('idle-end', id, idle_s)`: `tick()` writes `dryrun/<id>/IDLE-HELD-<n>.json` (resumable record, `rc=75 reason=idle-held`, fix task) and, on the first end, **removes the grant** so the row is `pending` again next tick (its PASS stands; the same tick's `admit()` already hands the device to the next waiting row); the second idle end (`IDLE_HELD_RETRY = 1`) is **terminal**: `.ended rc=75 reason=idle-held`, routed by `file()` — a hung launcher can never loop grant → idle → re-queue (the F4 class). One busy sample resets the clock and the warning. **Exemption, the simplest correct one:** there is no `idle_grace_s` field and no build-class carve-out — a load, compile or build phase keeps at least one core above 2 %, so it never reads wholly idle, and the clock cannot predate the grant's first sample, so the first 900 s after start are the grace. Shadow logs `SHADOW-IDLE-WARN` / `SHADOW-IDLE-END <id> idle=<s>s rc=75 re-queue`. Property test `test_idle_held_warns_once_then_ends_only_after_continuous_idle` (independent oracle over random busy/KFD sample sequences and step lengths; the unmeasurable grants never read idle), incident fixture `test_9`. Cutover requirement: the filler must treat a vanished `.grant` as "stop the running item, rc=75" at its poll boundary (today `filler_run15` only waits for a new grant when none exists).

10. **Keeper-divergence closures (2026-11-07).** Three rules the frozen keeper had and rowflow2 lacked. (a) **CPU multi-quarter never takes q3** (keeper `ec6aba4b1`, operator 2026-11-06): `cpu_multi_quarter_need` now also filters the `any-N-quarters` option list (legacy accepted `multi-quarter(N)`), not only the width form, so a CPU row waits for q0-q2 instead of taking q1+q3 (lsa-quality-32k-r5-pca idled the MI210 ~40 min); a single-quarter `any-quarter` row may still land on q3 unless it is a timing row (decision 7). (b) **Only GPU TIMING rows hold 88-95**: `is_gpu_timing` = `gpu: exclusive` and (`timing: true` / legacy `block-timing-*`, or legacy shape `gpu-q3`). A class-less legacy `shape: gpu` row stays exclusive (decision 1) but holds gpu + 184-191 only, as in the keeper. (c) **Job sha**: `job_sha` hashes the launcher plus every existing file its filler engine line references (port of keeper `parse_launcher`/`referenced_paths`, K:255/347/601, no further inference); SMOKE.json, smoke verdicts (stamped at smoke end), FAIL-deadline and PARKED records carry `job_sha256`, and a record binds only if launcher sha and job sha (unrecorded = match) both equal the current ones, so editing `job.py` under an unchanged launcher re-smokes a FAILed row. Tests: `tests/test_decision10.py`; `lineage_fails` (dead code) removed.

## Shadow week (starts 2026-11-05)

`run_shadow.sh` runs as its own process (pid in `/mnt/raid0/llm/tmp/rowflow2-shadow/shadow.pid`) every 120 s. It logs to `/mnt/raid0/llm/tmp/rowflow2-shadow/shadow.log` and writes `diff-<date>.md/json` at each UTC day rollover. The live keeper is untouched.

## Switch-over criteria (all must hold over 7 consecutive shadow days)

1. Zero shadow crashes (`SHADOW-ERROR`) and zero write-guard refusals.
2. No shadow grant violates a two-sided invariant against the live snapshot.
3. Shadow idle token-hours with runnable rows ≤ live, each day, and within 0.5 q-h / 0.25 gpu-h of budget.
4. Every live/shadow disagreement in the daily diff is reviewed. Each is classified as shadow-correct, live-correct (→ fix rowflow2 + add a fixture) or spec defect (→ owner republish).
5. Every not-done row maps (`map-report` unmapped-not-done = 0) or has been republished.
6. The gaps above are closed, with tests.
7. The cutover is one deploy at a grant-quiet boundary. In-flight grants are honoured. The P3.3 deletions land in one commit.
