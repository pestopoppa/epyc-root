Loop-Owned Fleet

Code owns the loop. Models judge at choke points, with examples in the prompt. Workers run in visible panes you can steer — but the machine's only channel to them is spawn-args in, report file and exit status out.

Built from a six-reader audit of the design docs, both defect ledgers (C1–C56, F-01–F-43), the live-run logs of 2026-08-12 → 08-14, and the automation code — then attacked by two adversarial reviews (failure-class red team, 20 findings; proportionality delete-lens) and ratified decision-by-decision by the operator on 2026-08-15. Implementation tracker: handoffs/active/loop-owned-fleet-implementation.md (RTG-52, deps RTG-34/RTG-48); the in-repo copy of this plan lives at docs/design/loop-owned-fleet.html (task P0-0).

00Symptoms this plan must fix

  • "I keep pressing Enter for my own fleet." Manual delivery rescues roughly daily; 42 refused nudges over 38.4 h on one main.
  • "Everything is idle while the backlog is full." 8–9% compute duty cycle on the flagship night; 11 h of dead fleet on 08-14 while the daemon assigned into the void.
  • "Half of everything written is the coordination layer repairing itself." ~50% of report volume, 08-11 → 08-13.
  • "I can't stop writing flowchart rules." Doctrine corpus ~67% incident patch; ~40 incidents each minted a standing rule.
  • "The coordinator needs hand-holding between prompts." RC-4: the role runs on prompt; between prompts, nothing runs.

Module reference

Alarm channelNEW

ONE operator-reachable push mechanism (ntfy vs email presented as a decision package at dispatch). Day-1 sources: fleet/runner dead, supervisor death. Queue-aging joins with P3-3 and aged compute-requests with P3-5, on this same channel. Emits once on state change.

Red-team #1: every prior alarm went to advisory.jsonl, delivered to no one — 11 unnoticed dead hours on 08-14. Gate: kill the fleet in a drill, verify exactly one alarm arrives. Phase 0.

Cold-start skillNEW (D3)

The hardened /coordinator-agent one-shot: after a reboot (operator-only by policy, so you are present), one command relaunches the supervisor tier, verifies daemon health, and runs the alarm drill. Replaces the cron dead-man — manual relaunch, packaged properly, per your ruling.

Token queueKEPT

Operator-signature pipeline: token-requests relayed by the daemon, receipts checked, ratifications accumulated into one command. C27/C33/C39 closed; kept as-is.

Coordinator consoleSHRUNK

The one agent you talk to under normal operation. Conversation, status, decision packages, priorities, merge serialization — and, under amended D4, editor of the compute policy file and approver of choreography recipes. Reads state; never owns the clock; never reads instruments (receipts-not-dials).

"Shrunk" means its load-bearing role shrank, not its conversational one: nothing in the loop depends on it ticking, so closing it costs only conversation. Gate: 7 days with the console closed ≥12h/day and nothing degrading, alarms included.

inference sessionKEPT (D4 amended)

Stays interactive and keeps running whatever the coordination level prioritizes — AutoKernel, AutoPilot, either, or neither. Under amended D4 it is a compute consumer like every other: it requests windows through the same bus mechanism as pool workers. Ownership (policy authorship, recipe approval) sits at the coordination level.

This amends bus rule 11 ("compute owned by ONE main") — ownership becomes policy authorship at the coordination plane, executed mechanically by the daemon, rather than a session's per-request discretion.

coordinator-daemonKEPT + EXTENDED

The 45s tick — the only clock owner. Fold → boundary detect → pick (gated) → assign → exec runner; transport for the two survivors; fleet/runner gate; mechanized compute grants + choreography step-through. Zero discretion: judgment enters as typed fields or classifier verdicts. Internals ↓

worker_runnerNEW

Exec'd FRESH per assignment (committed-not-live impossible by construction). Claim → typed brief → premise preflight → permission profile → lane lockfile → spawn in visible pane → lease timer → collect. Roster row {id: workerpool, role: main, endpoint: "exec:worker_runner"} — the one schema extension permitted. Harness is a config knob (worker_harness:), per-lane overridable (D2). Internals ↓

premise_screenerNEW

The one day-1 classifier: point LLM call at preflight; still-needed | stale | UNKNOWN, typed, forced-choice, evidence quote mandatory; UNKNOWN routes a fix task. Few-shot examples in the prompt are where your positive/negative examples live; eval fixtures carry label_provenance.

headless auditorNEW

Per completion packet, pointers only; derives the diff from git independently; one mutation probe. Never grades the worker's claim (red-team #12).

workersNEW (D8)

≤4 concurrent, one per lane worktree, batch ≤3 statically-grouped rows, each fanning out its own 3–5 subagents (subagents_spawned in the report — the multiplier finally measured). Runs in a visible tmux pane: you can watch, steer, and answer permission prompts by hand. The machine's channel is spawn-args in, report file + exit + signals out — it never types into or decides from the pane; it may capture scrollback as evidence for your eyes.

session busSLIMMED (D5)

Stable core kept: queue.jsonl, O_EXCL claims, tokens/, outbox+cursors ×2 — runtime relocated off-tree behind a tracked symlink (survives git clean -ffdx). Deleted: relay fan-out to N mains, acks, nudges, worker heartbeats, ~11 unwired message kinds. Internals ↓

lane worktrees + merge gateKEPT (D7)

mainA–D lanes, absolute gitdirs, pathspec commits; runner refuses to spawn outside a lane. Promotion = typed row through merge_gate.py/serialized_push, one at a time. D7: the five .orphan backups get archive-tarball-then-delete after verifying their tips are contained in lane branches — never prune; the 11 ghost rows/claims get a one-time signed release after owner-death verification.

03The pivot: pool workers in visible panes

A worker is spawned per dispatched batch into a lane worktree, in a tmux window you can watch and steer. The machine's contract with it is minimal and typed: spawn-args and a brief file in; a schema-valid report file, artifacts, and exit status out. The machine never types into the pane and never makes a decision from pane text — those were the two channels that produced the C51–C56 / F-33–F-43 delivery class and the 94%-false-positive perception class. Panes are human-authoritative: your inspection-and-steering channel, plus captured scrollback as evidence on failed rows.

The multiplier survives. The point of mains was the two-level tree: N independent dispatchers, each fanning out 3–5 subagents, with the coordinator negotiating dispatch and compute across them. Pool workers keep that tree, and subagents_spawned in the report makes the multiplier measured instead of self-reported (F-15 / RTG-49).

Kill-with-salvage (D6 as ratified): lease expiry ⇒ SIGTERM, grace, SIGKILL — then a mandatory salvage: uncommitted worktree state committed to salvage/<task_id>, harness transcript and pane scrollback attached, row marked FAILED with a salvage_ref. Commit-per-unit keeps salvage small; nothing is ever discarded. This is a scoped amendment to BUS_PROTOCOL rule 8 (quiesce-and-drain): the salvage-kill exception applies to POOL WORKERS ONLY — interactive-session reclaim stays drain-only — and the rule-8 amendment lands with operator ack before the kill path first runs (P2-4).

Self-repair gate (D9 as ratified): the fleet may file typed defect rows and proposed patches, but merging any change under scripts/coordination/** requires operator ack — the architecture cannot autonomously rewrite itself or its instruments. The self-repair metric is computed by commit-path classification, never self-reported.

06Ratified decisions (operator, 2026-08-15, this session)

D7RATIFIED Ghost sweep + orphan disposal, with safeguards: owner-death verification and an enumerated list before the signed claim release; archive + containment check before orphan deletion.

07Metrics & kill criteria

  • Compute duty cycle on unattended nights: 8–9% → >40% within two weeks of Phase 3.
  • Operator delivery interventions: ~daily → 0 (steering by choice stays; rescuing by necessity goes).
  • Coordination self-repair share: ~50% → <10% — computed from commit paths (scripts/coordination/**), never self-reported (D9).
  • Alarm fidelity: every drill alarm arrives; zero alarms on well-run nights.
  • Kill criteria: pilot breaches the D1 ceiling, or audit quality drops — operator spot-review overturns ≥2 of the 3 reviewed pilot rows, or post-pilot operator-vs-auditor disagreement exceeds 20% over any 7-day window ⇒ halt and reassess. Any single-writer or trust-boundary violation by the runner ⇒ immediate authority revocation. Meta-kill: any phase exceeding 2× its estimate stops the plan.

08Explicitly not built

No general workflow engine. No new message kinds beyond the workerpool endpoint. No classifier for any surface Phase 3 deletes. No policy-DSL for exotic leases — recipes are data. No autonomous merges to the loop plane. No re-litigation of ratified invariants.
