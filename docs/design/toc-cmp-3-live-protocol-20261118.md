# CMP-3 isolated REPL integration screen

Question: does the source-pinned compaction-contract candidate preserve its caller-supplied six-field brief and governance text in the actual post-boundary generation request when driven through the real REPL graph, and does the omission-manifest arm describe the dropped spans?

This is an integration screen. It follows the controlled fixed-summary comparison rather than replacing its governance controls. Run paired baseline summary-only, contract summary-only and contract verbatim-manifest arms with the same task and seed, bounded tasks and forced boundary. Summary arms must use the actual model-backed summarizer. The boundary must have at least two prior history turns and omit at least one: a forced boundary alone is insufficient because the renderer always keeps the latest turn. The manifest arm natively describes omitted history without generating a summary. Persist all native events and exact generation request and response bytes.

The decisive integration evidence is boundary reachability, dropped-span evidence and a subsequent captured generation request containing the candidate-rendered contract. A contract present only in a state field or rendered file is insufficient. Missing boundary/continuation and incomplete generation stay UNKNOWN. Literal equality establishes preservation only; semantic entailment, governance compliance, live-hook enforcement and production-tenant behavior remain separate questions.

A two-task, three-arm screen has two observations per arm. A single answer changes an arm's accuracy by 0.5, so no efficacy, MDE or population inference is supported. Higher confirmed literal delivery is better; transport failures, lost content and unknown delivery are separate fields. The original source also remains available in the REPL context, so exact-match answers are task-delivery diagnostics, not isolated recall or summary-retention evidence. Record accuracy and latency descriptively where available. Never substitute a failed or unobserved boundary with an affirmative result.

Stop at the fixed matrix; stop on the first transport, source/runtime identity or protocol error, allocator STOP/deadline, or the declared row time cap. Preserve partial/UNKNOWN outcomes without automatic retries. Smoke checks one contract-on summary trajectory, actual post-boundary delivery and cleanup, and is excluded from the official ledger. It does not qualify measured outcomes for the baseline or manifest arm; the six-session row supplies those observations. No production reload, feature enablement or kernel changes.
