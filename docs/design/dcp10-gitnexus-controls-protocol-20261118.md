# DCP-10 direct-edge controls

This preparation separates the two graph policies in DCP-10 on its original three-task
cohort. It does not authorize a new cohort, application behavior, or a quality claim.
Native graph capture remains gated until the producer can prove the pinned base,
index and source identities. Synthetic controls must not enter cohort denominators.

The question is whether direct graph evidence changes candidate selection under the
same discovery caps. Higher macro file/line recall, precision and F1 mean greater
gold overlap. Three tasks are diagnostic only: one task can change macro recall by
one third. No significance, promotion or population-quality conclusion is available.

The producer must preserve the original task IDs, issue queries, base commits and
application bytes. Before native execution, seal the ColGREP seed outputs, graph
source bytes, index bytes, edge query and output schema. A stored one-hop relation
must name both endpoint files and a finite stored confidence at least 0.9. Do not
substitute traversal confidence, injected seeds or transitive paths. Reject escaping,
untracked or missing files and preserve failed/empty attempts without replacements.
Seal the local comparator and its helper bytes in the request as well; pinning
only GitNexus would leave the experiment's admission and ranking code unbound.

The locally installed GitNexus package reports version 1.6.1. Its
`dist/mcp/local/local-backend.js` exposes raw Cypher through `cypher()` (line 753)
and substitutes per-relation confidence when an impact result lacks positive
stored confidence (line 1728). `dist/core/lbug/schema.js` declares a stored
`CodeRelation.confidence` double. Pin those source bytes in the admission record;
the version string alone does not identify the behavior. A direct stored-edge
query avoids treating that fallback value as observed graph confidence.
Its `dist/core/ingestion/parsing-processor.js` stores tree-sitter row coordinates
plus a file offset (lines 320 and 428). Native capture must bind the applicable
coordinate conversion before emitting ContextBench one-based inclusive spans.
Missing graph spans are missing line evidence; do not manufacture a line-one hit.

For append, preserve original candidate order and append eligible new neighbors
under the original eight-file cap. Eight existing files leave no append capacity;
record that outcome. If all three admitted seed rows are saturated, append file
selection is a deterministic no-op; record that policy result without treating it
as evidence of graph quality. For rerank-only, score and reorder existing candidates using
the same eligible direct relations, retaining original order for ties. It must never
introduce a file. Neither policy may change query text, top-20 retrieval or
2,000/4,000/8,000 estimated-token budgets. Retain actual pack/render provenance
separately from candidate ordering and cost-based scoring.

Preparation stops when source identities, synthetic policy controls and refusal
controls are recorded. Native comparison requires a separate prospective request
bound to original ColGREP output and validated graph capture. Stop that finite
comparison after three predetermined attempts, or at the first source/isolation
failure, allocator STOP or declared deadline; no retries or substitutions.

Use the existing `VB-CONTEXTBENCH-DISCOVERY-WIRE` source task and shared verifier
grade. The original writable-ancestor capture refusal and trusted-packer mismatch
remain in force. Source pins and successful fixture controls do not establish index
