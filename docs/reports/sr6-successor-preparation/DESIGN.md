# SR-6 successor design (preparation, not a runnable row)

Question: on the current pinned target and kernel, does draft width 3 improve decode throughput versus width 4 on the same recipe and sampled workloads? The July 2026 sweep's request settings and source packet were not located; this is a new comparison, not an exact replication. It cannot independently authorize a registry change.

Before publishing: capture and seal the actual selected model, binary and libraries, launch flags, template, and request sampler from the current registry/launcher, with their source commit and value provenance. If a parameter is unset, explicitly pin the actual runtime default after verifying its source. Choose and seal a fresh, disjoint, realistic code/RAG/prose prompt manifest and distinct per-prompt seed manifest; record repeated-5-gram numerator, denominator and fraction for every rendered prompt. Prove disjointness from prior SR-6 prompt hashes and do not use model-generated text copied from a prior response. Preflight GGUF identities before grants, never during them.

Each independent whole-host grant is a separately sealed window. Use four arms: composed ngram-mod,draft-mtp at widths 3 and 4, and draft-mtp-only non-context controls at widths 3 and 4. Use exactly matched formatted prompt, sampler and seed across arms, rotated counterbalanced arm order, fresh server per arm and cache_prompt=false. An additional repeat of one arm per block measures local A/A drift. Never use a previously exposed prompt after interruption; preserve exposure markers and partial failures. Declare at least three independently booked windows and their untouched prompt partitions before the first exposure; no post-hoc extra windows to rescue a result. Repetitions of the same prompt are paired across arms within a window, not independent samples.

Retain raw native output and request settings, all failed/unknown attempts, grant/CPU and runtime identity, actual rendered prompts and hashes, draft counts, predicted token counts and times, stop reasons, and residency/placement evidence. Verify token-level output identity as a diagnostic; sampled output divergence is possible and invalidates speed comparisons where matched generated work is not comparable. Compute per-prompt throughput and window/aggregate token-weighted throughput, A/A differences, context-control effects, per-class results and repeated-5-gram fractions. No warm-server repeated-prompt sequence is permitted.

Predeclare a paired, prompt-clustered uncertainty method and a practically meaningful threshold before running. Recommend requiring a positive lower confidence bound above both the predeclared practical threshold and observed within-window A/A variation across the independent windows, with consistent direction in the non-context control; otherwise inconclusive. Report the composed-arm comparison separately from the non-context control, and do not infer composition's benefit from a difference in unlike output lengths. Fail closed to UNKNOWN for missing provenance, unmatched prompt/seed/formatting, interrupted blocks, inadequate repetitions, invalid residency or inability to compare comparable work.
