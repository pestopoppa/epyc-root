# SR-6 prospective decision rule — draft, not yet predeclared

This proposed rule is a preparation artifact. To predeclare it, review and seal this document, the analysis code, three independent grant windows, the complete prompt/seed partitions, runtime/sampler pins, output-comparability rule, and exposure plan **before any exposure**. No part of this document approves a run, a registry change or a claim about historical composed/sampling results. The design's external source, runtime, placement, admission, complete-inventory and interruption controls remain mandatory. Missing any control yields UNKNOWN; the program cannot verify those controls.

For each of exactly three independent whole-host windows, preselect at least 15 distinct prompts, with at least five each in code, RAG and prose, and nonoverlapping prompt/seed partitions. Pair four arms and the MTP-width-4 A/A repeat on each prompt with matching formatting, sampling, seed and equal generated token sequence/count. Retain all attempts and failures. Each prompt is a cluster: its arms are never resampled independently. A failed or divergent pair is not discarded to rescue the result. The preregistered inventory is the denominator.

Per prompt compute log throughput ratios: composed width 3 / width 4; MTP-only width 3 / width 4; and MTP width 4 repeat / first. For each window the point estimate is the equal-prompt mean of log ratios (exponentiate and subtract one to report geometric relative gain). Resample prompts with replacement **within class and within the same window**, preserving each class's observed count, 10,000 draws with Python `random.Random(20261102)` and windows sorted by ID. Use the empirical lower 1.6667th percentile, specifically sorted index `floor((0.05/3) * (10000-1))`, as a one-sided Bonferroni-adjusted lower bound per window. This is a percentile bootstrap: its approximate coverage needs independent representative prompt clusters within each class and a suitable empirical distribution; class-stratified convenience selections do not establish population coverage. Three windows and five prompts per class are only minimum design floors, not a power guarantee. Report the intervals and uncertainty limitations, never claim the program proves them.

The candidate signal requires **every** window's composed lower log bound to exceed both `log(1.05)` (the prospective 5% practical threshold) and the largest absolute per-prompt MTP A/A log difference in that window, and its MTP-only mean log ratio to be positive. Otherwise the result is INCONCLUSIVE. The A/A quantity is a conservative observed drift comparator, not a calibrated noise quantile. Report the composed and MTP-only effects separately; this control does not estimate the causal effect of composition. Report per-class summaries, token-weighted aggregate throughput, all repetition metrics, per-window results and raw failures separately; they are not silently substituted into this decision rule. Finite-sample percentile behavior, fixed workload selection and across-window dependence can limit interpretation. No change to stopping, threshold, sample size or prompts after exposure may rescue a null result.

`decision_rule.py` consumes the current paired-analysis prototype plus a separately supplied `window -> [prompt_id]` inventory. It checks matching IDs and numbers but **does not** verify the inventory's seal or metadata, real window independence, source and tokenizer provenance, output identity, selection bias, CPU/GPU residency or complete attempt history. Its `CANDIDATE_SIGNAL_ONLY` is a calculation, never a final science verdict. Native-evidence joins and full fail-closed gating remain implementation work.
