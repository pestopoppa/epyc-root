# CH-26b loss and coverage replay prototype

This standalone diagnostic adapts a retained four-CPU sched_switch smoke receipt to the independent ring verifier. The replay completed structurally. Its `capture_overlap_ns` is the overlap of the captures’ enable intervals, synthesized for this structural check; it is not an actual serving request window. Empty error arrays supplied to the verifier are adapter scaffolding, not producer error receipts. The result does not authenticate the producer or kernel, verify that sample PIDs belong to the recorded child, establish losslessness or host coverage, prove placement or lack of contention, or admit a noise floor. It is not wired to the CH-26b calibration launcher.

The replayed receipt and raw rings are retained at `/mnt/raid0/llm/tmp/autokernel-cross-workload-keep-gate/ch26b-loss-coverage-verifier/receipt/`. The retained manifest SHA-256 is `8f67dc879ec4b117ff88db78575abc4963e0ac15dcf28e564c3a52587c989fee`; it binds the raw ring digests. `RESULT.json` records the diagnostic output. Run the synthetic structural tests with `python3 -B -m unittest -q test_loss_coverage_verifier test_replay_receipt` from this directory. The real receipt replay requires that retained packet and is intentionally separate from those tests.

To replay the retained packet, run `python3 -B replay_receipt.py --manifest /mnt/raid0/llm/tmp/autokernel-cross-workload-keep-gate/ch26b-loss-coverage-verifier/receipt/manifest.json --manifest-sha256 8f67dc879ec4b117ff88db78575abc4963e0ac15dcf28e564c3a52587c989fee --cpus 0,1,2,3 --output /mnt/raid0/llm/tmp/autokernel-cross-workload-keep-gate/ch26b-replay-result.json`. The receipt location is scratch custody and is not guaranteed to remain available.
