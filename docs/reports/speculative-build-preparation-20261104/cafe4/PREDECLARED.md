# CAFE-4 real-MTP rollback/fault candidate

Build-only row. The native controls below are implemented source, not executed results. The current lifecycle-only build package remains untouched. Source is a detached current-v10 worktree plus the exact target-context snapshot diagnostic and CMake integration patch. No production tree is modified.

The executable requires an MTP-bearing model, CPU-only target and MTP contexts, no shared recurrent memory between target and drafter, target snapshot ring >= 8 and a prompt below 120 tokens. It runs three fresh matched trials: diagnostic off, observe, fault. Each uses a real greedy MTP proposal of 2–3 tokens. The sampled target boundary remains pending until one D+1 verify batch. A diagnostic acceptance cap at floor(D/2) forces rejection of a suffix even if the native proposal fully matches. The resulting accepted count must satisfy 0 < accepted < D. This cap is explicitly a harness intervention, not a native acceptance-rate measurement.

It calls common_speculative_accept, removes the rejected suffix from BOTH target and draft contexts at boundary+1+accepted, then processes the pending sampled token. The fault is confined to the exact target recurrent memory: a pending nonzero rollback snapshot index is replaced by zero while sequence positions and KV metadata remain unchanged. Trial comparison requires identical draft IDs and retained prefix in all modes. Missing target selection/fault counts, failed decode, unsupported suffix removal or any missing proof yields UNKNOWN.

Each trial constructs independent cold-prefix target contexts for serial and batched kept-prefix logits. The floor is max(off-batched vs serial, observe-batched vs serial) + 1e-5, fixed before any exposure. Off and observe must agree with their cold serial reference within this floor and with each other within the floor. Fault must both differ from its cold reference and from matched observe by more than ten times the floor. No token-identity, performance or CAFE-4 result follows merely from compiling this code. Batch effects, unavailable strict partial acceptance or an insensitive fault are UNKNOWN, never a native PASS.

The build proof binds v10 source commit, exact git diff, candidate and bridge digests; full binary, common/ggml DSOs, CMake cache and build/linkage logs are content-hashed. Qualification performs one real candidate source-object compilation, writes an invocation-isolated smoke result and stops cleanly; it proves no full link or runtime behavior.
