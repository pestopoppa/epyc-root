# Authenticated own-child map acquisition component

`acquire.py` is an importable native acquisition component, with no CLI and no implicit process launch. It was prepared without executing or importing it, running tests, starting a process, reading target maps, or accessing a model/GPU.

The owning supervisor creates `OwnChild(argv, env=..., cwd=..., stdout=..., stderr=...)`, keeps that object, invokes `capture()` during its own native phenomenon, persists the returned raw record, and invokes `close()` in its own finally block. The component opens a pidfd immediately after spawn, captures `/proc/PID/stat` birth ticks, checks immediate parent and birth before and after capture, brackets reads using CLOCK_MONOTONIC_RAW, and reads selected executable file ranges through `/proc/PID/map_files/START-END`. It records exact raw maps, object device/inode, range offsets, byte counts and SHA256. The selected ranges are executable mappings of the child's executable and llama/ggml DSOs. Weight files are never selected or hashed. Map-file permission denial, a vanished process, changing maps, short reads or oversized ranges yield UNKNOWN with partial observations retained.

The byte digest covers the file-backed mapping range only. It does not cover runtime-relocated resident memory, non-executable ELF sections, every byte of a DSO, or establish a complete binary image digest. Map snapshots are bracketed observations, not atomic freezes. A file writer could mutate file bytes during acquisition; production integration still needs its separately sealed immutable artifact manifest. The producer must retain the complete raw record before adapting it to a shared grading ladder; no grading rule is added here.

`close()` signals only the captured pidfd, escalates TERM to KILL, reaps the immediate child and verifies that its birth identity is absent. It deliberately reports `descendants_verified=false`. Use only an explicitly leaf child until the owning supervisor supplies captured-descendant custody and verifies its own tree cleanup. Do not use this component alone as a server launcher. pidfd support, Linux procfs and appropriate map_files access are required; no permission bypass is attempted.

Integration remains unqualified. Future smoke must be separate from native full work, exactly four granted CPUs, and use a model-free leaf child with normal and denied-map controls plus STOP and cleanup controls. Full collection needs current grants, the real native supervisor's custody, deadline/STOP integration, source and runtime seals, image-manifest comparison, output writer and a qualifying original run. This component establishes no profiling, historical-cell, request/task binding, HIP residency or ≥20% trunk-attention verdict and publishes no row.
