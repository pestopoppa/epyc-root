# KVU-19b profiler clock binding: prospective qualification design

Scope: model-free design, no profiler, HSA runtime or GPU executed. Installed `/opt/rocm/include/hsa/hsa.h` identifies `HSA_SYSTEM_INFO_TIMESTAMP` as monotonically increasing at a constant rate and `HSA_SYSTEM_INFO_TIMESTAMP_FREQUENCY` as Hz (the header describes 1–400 MHz, while a retained MI210 witness reports 1 GHz); it does not declare the clock equivalent to host `CLOCK_MONOTONIC`. `/opt/rocm/include/hsa/hsa_ext_amd.h` describes an agent timestamp frequency separately; do not substitute it for the system query without evidence. The locally unpacked ROCm 6.2 extractor `.../libexec/rocprofiler/tblextr.py` records `DispatchNs`, `BeginNs`, `EndNs` and `KernelName`; the column suffix alone is not evidence of epoch equivalence to host or HSA clocks.

Per profiled child, bind profiler, backend DSO, model-free calibration binary, target binary and HSA library hashes, tool version, execution PID/birth, MI210 BDF/GPU ID, queue/dispatch identity, trace paths and exact window. Preserve raw output and manifest before deriving any labels. Under the same held GPU/host claim, capture >=2 HSA system-clock samples both before and after the target interval: each sample brackets `hsa_system_get_info(HSA_SYSTEM_INFO_TIMESTAMP)` with `CLOCK_MONOTONIC` readings and records frequency. Fail closed for absent runtime, failed call, zero, invalid or changed frequency, backwards host/ticks, host bracket reversal, missing samples, changed process/device/profiler identity, or missing raw trace.

For each bracket [b,e], tick t and frequency f, compute the host-minus-HSA ns interval [b-ceil(t*10^9/f), e-floor(t*10^9/f)] with checked integer arithmetic and rational quantization. Samples must bracket the full interval; multiple samples must give a consistent model within the error budget. Do not assume HSA/profiler ns epochs match merely because intervals intersect: launch a unique, named GPU witness (with HIP synchronization) at both edges, timestamp host start before enqueue and host end after completion, and require exactly one profiler row for each with its complete translated `[BeginNs,EndNs]` interval contained in the corresponding host bracket. Multiple witnesses spaced throughout the interval are needed to validate any drift/interpolation bound; freeze the acceptable bound and spacing before measurement. Before/after overlap alone cannot rule out interior non-linear drift. If no validated bound exists, phase intersections are UNKNOWN, not zero.

An existing reference is `/mnt/raid0/llm/tmp/heterogeneous-slot-fabric-residency/kpf50-row-20261104/runner/{hsa_clock.py,verify_clock_smoke.py}`: it provides sample capture, integer offsets and one named GPU/host containment check, but is prior source, not a passed calibration for this process, profiler, device or entire window. Validate its assumptions against the exact planned rocprof configuration; do not reuse its old result or infer trace timestamp origin from code names. Count and retain all witness rows, verify exact PID/birth/device/queue where available; refuse duplicated, absent, truncated or misbound witnesses, noninteger/negative times, `BeginNs >= EndNs`, missing or multiple candidate trace streams, and failure to establish a bounded offset and drift.

Only attribute a kernel fully contained in a single host phase under all allowed translations; classify boundary-straddlers or those whose uncertainty overlaps a boundary as AMBIGUOUS, retain them, and report counts and total unassigned time separately. Bind phase IDs and host monotonic start/end to the same exact process and ensure trace collection covers all phases. Do not use inclusive sum as wall-clock duration with overlapping kernels; report both total kernel work and interval union. Missing per-phase kernel coverage, trace loss or incomplete shutdown is INCONCLUSIVE rather than 0 GPU time. Smoke at most establishes clock alignment for its declared conditions; a full run needs fresh bracketing and independent native residency/custody.

The observed 1 GHz witness invalidates an unconditional 400 MHz parser ceiling. Positive integer frequencies must still be checked for valid arithmetic and consistency within each attempt; see the [corrected synthetic parser qualification](../kvu19b-target-marks-r2-result-20261105/RESULT.json).
