# KPF-50 prospective native receipt: source inventory

This is a source-level specification for the existing four-window diagnostic, not a native result, a new grading rule, or authorization to run. The retained `kpf50-counterfactual-20261102/out/rocprof/` contains profiler configuration XML from plan construction; the four interrupted attempts have no retained target request/profile. The prospective `kpf50-row-20261104/out/` is empty. No real per-window receipt can be manufactured from these files.

The predeclaration fixes Qwen3.8-27B plus DFlash2, source `1e8a6d5da9836a27e8f1d2010a02e6cebd95abdc`, four independent fresh windows `full/mask/mask/full`, four 80k sequences, and a 60k shared trunk. Each window receipt should bind its window index, mode, run ID, exact argv and prompt-set SHA-256, server/source/model/drafter and all loaded library identities, attempt start marker, raw artifacts and their digests. The marker must precede the first possible target request; an existing start marker means its exposure must not be redrawn. A completion record cannot erase an incomplete exposure.

The following fields have identifiable native sources but **must be extracted and validated from the actual window**, not populated from configuration:

| Required evidence | Prospective native source | Refusal condition |
|---|---|---|
| Four child HTTP outcomes and individual fork tokens | Runner `rows/<run_id>.jsonl`, four `role=child` rows with unique suffix indices, `http`, `error`, and `timings.n_fork_tokens`; `Run.row()` raises on failed HTTP | Missing, duplicate, error, non-integer or fewer than 60,000 fork tokens for any child; the existing `fork_expected` test only checks key presence and is insufficient |
| Target input/phase, first qualifying step, 4 sequences, verified 60k mask and layout | Server log `KPF30_PHASE`, `KPF50_INPUT`, `KPF50_STEP_BEGIN/END`, `KPF50_TRUNK_MASK`, and enclosing `KPF50_ITER_*` / `KPF50_DRAFT_*`; pinned research `select_step.py:first_step()` checks and extracts first eligible step | Missing/ambiguous brackets, token/position join, rc, phase, four distinct sequence IDs, mask verification, expected 60k, timing or iteration/draft evidence. Further cross-window comparison must reject mixed decode/verify and mismatched inputs/layout/dispatch family |
| Profiler dispatch and clock alignment | Raw rocprof CSV `KernelName`, `BeginNs`, `EndNs`; bracketed `hsa_clock.py` output; a real separate clock-witness profiler trace validated by pinned `verify_clock_smoke.py` | Missing witness, unstable calibration, unknown or boundary-crossing dispatch, no independent process residency. Whole-run attention totals cannot stand for trunk attention |
| Live GPU/process and binary custody | Runner `residency` and raw sampler/process maps, tied to captured server PID and birth; exact binary and mapped-library hashes | Missing request-overlapping own-PID KFD/positive-VRAM samples, HIP mapping, expected device, executable or identity; device-wide allocation is not own-PID evidence |
| Owned-process cleanup | Successful supervisor lifecycle receipt with each captured PID, birth identity, signal/escalation if any, exit/reap and independent final absence, including actual descendants | Any unknown, survivor, reused identity, failed cleanup, stopped/partial execution, or unverified descendants. The old `Server.stop_rec` records only server PID, signals, return code and `ps` absence; it omits birth and descendants. Outer `cleanup()` logs and swallows exceptions, so rc0 or an old record alone cannot establish complete cleanup |

`Run.finish()` records the raw rows path and digest, binary/argv/readback, DFlash2 status, residency summary and server stop receipt. However it can also write partial records after an error, and `stop_step()` calls it in a `finally` even when stopping fails. A completion producer must require a non-partial native result, independently verify the raw records and a separately controlled cleanup receipt, and reject the absent/false cases above. A source-bound runner change and independently tested supervisor are necessary to supply the missing cleanup guarantees. Do not synthesize those fields from `rc=0` or the current XML-only output.
