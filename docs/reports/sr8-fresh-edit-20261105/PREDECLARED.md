# SR-8 synthetic multi-file successor diagnostic

This is an independently specified experiment; it does not amend the previously stopped UNKNOWN held-out run. The inputs are five distinct, newly authored BEP-style multi-file tasks. They are not the canonical BEP track: a positive result is a candidate for subsequent canonical testing, never a serving route decision. Each block uses the same task and exact pre-rendered prompt across plain, current DFlash2, and prompt-lookup arms, on one newly started server per request, with np4 and one active request, greedy sampling. At most five interleaved blocks are run. A verifier failure or any incomplete request, unbound process, missing in-request residency, inconsistent/ambiguous native counter or invalid observation ends the run UNKNOWN; there is no adaptive extension. Only five complete blocks allow reporting the paired geometric mean of lookup/DFlash2 decode rates and proposing-round weighted accepted length; 1.5x is a candidate signal, without route authority or a noise-floor claim.

The bound production server is v10 commit `ffc1bac82eeca6f9099e1ccd9ba49703c460a115` and preflight pins its executable digest. Frozen `tools/server/server-context.cpp` (reset around lines 341–343, 371–373; accumulation around 3151; task timings around 576–579; logging around 670–686) and `tools/server/server-task.cpp` (around 261–264) establish that the native response and acceptance log omit draft counters when no draft tokens were generated. Only for a complete, untruncated sole-request response on a fresh pinned server, with both fields absent and no same-slot acceptance line, this protocol records zero generated and accepted draft tokens; its proposing-round mean is undefined. A single missing field, an incomplete response, or a contradictory log is UNKNOWN. If proposals are present, counters must match exactly one same-slot acceptance line, and its two-decimal mean must admit exactly one positive integer round count under an inclusive rounding interval; otherwise UNKNOWN. Zero-draft requests contribute zero proposals and no proposing rounds; if the entire arm has zero rounds, the mean is null, not zero. Preserve every response, request, native log, verifier verdict, and windowed residency observation.

Preflight reuses the prior full model digest receipt only after checking its full file identity/stat tuple; the grant repeats the stat check without hashing model weights. A new runtime manifest pins worker, corpus, verifier, prompts, preflight, checks, and test files. Source proof supports the prospective zero rule alone; it does not reclassify the prior UNKNOWN cell.

All arms use the same trace verbosity so initialization of the requested speculative implementation is observable, including when it proposes no tokens. Startup logging can perturb timing; the paired comparison is limited to this capture configuration. Smoke must capture a positive-proposal DFlash2 request with complete native observations. Every accepted response must stop normally at EOS or a stop word, not a token limit. The runtime precheck verifies the store manifest digests for the server and its relevant libraries, while live process maps establish the server implementation libraries and HIP backend are loaded.
