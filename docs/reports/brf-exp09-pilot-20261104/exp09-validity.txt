This supports neither an EXPAND nor completed STOP gate under the manifest; it is an operational stop only. Existing per-cell values remain useful exploratory observations.

Repair recommendation (without confounding, truncation, or live compute)
1. Preserve the current immutable corpus, prompt text, model/kernel/template identity, answer-scoring code, arm order, and raw outputs as the baseline. Do not edit job.py and then treat combined results as one comparable run.
2. Fix the confound in run order: the current plan runs all controls, then arm blocks; model/server state and time can drift by arm. Use a fresh, explicitly versioned job that runs paired item blocks with arm order rotated/balanced by item and records order, while retaining identical answer prompt and decoding settings. If matching original manifest is mandatory, report this as a new revised pilot, not continuation of EXP09 as specified.
3. Avoid context truncation by testing every prompt’s rendered byte/character length and tokenization against the exact server context setting, including chat-template overhead and max output budget. Do this offline using the pinned tokenizer/template, with a conservative margin; do not silently clip the 4,000-character source span or answer observation. Record full input hashes/lengths and assert they fit before any inference. Existing 16,384 context suggests ample nominal room, but no recorded per-request prompt token counts prove it.
4. Validate repaired control and quote logic without starting a server: import the frozen orchestrator under the pinned environment and inject a deterministic fake llm_primitives adapter that records prompt, context_slice, role, n_tokens, skip_suffix; assert first-spill call parameters and output path, and separately exercise static fallback. Unit fixtures should test exact-match acceptance, one-byte mismatch rejection, absent/empty quotes, malformed JSON, status mismatch, fail-without-failure-evidence, empty/oversized summary, and pass/fail logs. Verify expected saved view and fallback text byte-for-byte.
5. Run the offline score/capture validator over archived results and synthetic fixtures: enforce one unique (item, arm, run-version) record, exact item sha, all required raw inputs/outputs, parse status, and completeness accounting; make futility results explicitly ineligible for the full-matrix decision rule. A dry-run server smoke is still live compute and should be omitted for the requested no-live-compute validation.

Limitations
- Corpus builder’s selection is deterministic against current disk and creates immutable copies, but provenance is limited to local source paths; hashes establish content integrity, not representativeness. Gold failed IDs are capped at the first 10 unique FAILED rows, so “recall” is defined against a partial reference for logs with >10 failures (e.g. items 03 and 09); label that metric accordingly or revise gold extraction before a new pilot.
- The answer scorer’s failed-ID matching uses substring inclusion in either direction, which can produce ambiguous matches; prefer exact normalized node IDs for a revised analysis, versioned separately.
- Existing results are sufficient to establish the preflight and capture claims above, not full pilot completion or a gate decision.
