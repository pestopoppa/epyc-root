# Single-proposal verification invariant

For a verifier that accepts a proposal exactly when the sampled target token equals the draft token, a verification round with one actual proposal has either zero or one accepted draft. Across such rounds, accepted drafts divided by proposed drafts therefore equals the observed single-token draft/target sample-match fraction. Exclude rounds with no proposal and the bonus token; preserve the numerator and denominator. This is an accounting identity for this verification rule, not a throughput claim or an assertion about acceptance under every speculative sampling algorithm.

In the frozen v10 source (`ffc1bac82eeca6f9099e1ccd9ba49703c460a115`), `common/sampling.cpp:671-683` samples the target, compares that token to the draft and stops on mismatch; `:686-693` samples the separate bonus token only when the draft is fully accepted. The `LLAMA_SPEC_DIAG_ACCEPT` trace at `:643-668` records sampled target, draft and match. Check the actual implementation, actual proposal count and sampling configuration before applying the invariant; greedy equality is not interchangeable with agreement of stochastic distributions. The handoff's 91.88–96.58% third-party range is a sanity reference for a different 4-bit-draft/8-bit-verifier design, never a local baseline.
