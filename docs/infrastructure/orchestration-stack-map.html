Request lifecycle

1chat → orchestrator :8000 → role router → front door :8070 (+episode)
2route task_type → role → port; escalate on low confidence
3serve full 96t for solo turn, quarter 48t under burst
4knowledge kg_search + embed/rerank → answer, write 1 episode

Autopilot learning loop

Aobserve telemetry + journal shards + baseline ledger
Bact config applicator, least-cost tier that fits the change
Cevaluate eval tower T0→T3, gated by MEASUREMENT protocols
Drecord journal → pareto frontier; refuted → learning_exclusions
routing / orchestrator API serving · llama-server + MTP knowledge · memory · embed autopilot control evaluation · governance gate
Single kernel: production-consolidated-v6 (upstream llama.cpp + native MTP/NEXTN spec-dec + forward-ported CPU kernels + ik_llama iqk AVX-512 GEMM, GGML_IQK=1). ik_llama.cpp binary deprecated 2026-06-26 — one binary, no second kernel. Autopilot strategy store is file-based (JSON/JSONL/YAML) — distinct from the orchestrator's repl_memory (FAISS+Kuzu) episodic store. Every decision-gating number carries a protocol id; the autopilot reads the measurement layer but can never amend it.
