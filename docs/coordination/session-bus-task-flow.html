Mutation invariants

  • Worker mutates only its source task, artifacts, per-agent progress shard, and lane commit/push.
  • Coordinator alone accepts receipts, chooses integration order, promotes, clears, closes, and dispatches follow-ons.
  • Auditor alone authors verdicts; it never directs the originating worker.
  • Inference alone authors intake dispositions/windows and owns compatibility, leases, claims, and safe drain.
  • One leased heavy-wrap writer mutates shared handoff/index/generated/wiki surfaces.
  • Derived projections are regenerated from authoritative append-only inputs; humans/workers never edit them.

Forbidden transitions

  • No clear, close, promotion, or completion claim before a valid durable checkpoint receipt.
  • No audit or integration state from a quarantined/invalid receipt.
  • No ready → running compute shortcut: planning, lease, grant, and physical claim are mandatory.
  • No Coordinator-authored compute window or Auditor-authored worker requeue.
  • No direct Auditor → source-main instruction edge.
  • No auto-expiry or same-roster reclaim of a long-lived wrap lease without its operation token.
  • No reboot-ready state while any roster receipt, physical claim, promotion, wiki watermark, or wrap receipt is missing.

Known gaps / audit questions

  1. Deployment versus pushed code: the checkpoint engine, canonical publication, closed bus schemas, receipt admission, audit fold, and integration-ready path are pushed at 82c1c5b4. A live daemon reload and instruction acknowledgment are still separate evidence; a commit alone does not prove process cutover.
  2. Compute producers: the deterministic planner is pushed, but no live bus relay creates intake/window records or writes the generated projection. Who invokes it, where its append-only inputs live, and how Inference acknowledges instruction SHA remain open integration work.
  3. Resource claim provider: delegated GPU grants remain disabled until a general provider is named and enabled. Confirm open/close receipt semantics before canary.
  4. Receipt-driven heavy wrap: typed wrapup-request/wrapup-complete schema exists locally; no end-to-end immutable-cut executor currently replaces the manual wrap routine.
  5. Authority cutover: protected policy/role changes and any narrow subagent writer exception require operator ratification. Until then, Auditor main remains the writer and subagents are read-only.
  6. Live refresh: after merge, prove daemon reload and obtain every role's instruction acknowledgment before moving off → shadow → enforce.
  7. Negative controls: acceptance must prove unsafe cases fail for the intended reason: invalid receipt creates no audit, unleased wrap collides, wrong compute grade excludes, and pre-reboot missing coverage holds the barrier.
