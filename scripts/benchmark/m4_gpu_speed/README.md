# M4 GPU speed source (unarmed)

`server_np_sweep.py` is derived from the former private `m4-fold-gates/speed-gpu/native/server_np_sweep.py`. The V2 entry uses `launcher.py` and the sibling `m4_cpu_ownership` cgroup/pidfd guardian. Enrollment is intentionally empty and disabled in `enrollment.py`. A reviewed plan, producer/library seals, actual role/model recipes and current resource admission must be bound before it may be enabled. The retired private launcher is not an entry.

The independently configured plan uses `epyc.m4.gpu.plan.v2` and a `cells` mapping. Each cell binds role, arm, source commit, absolute model path, recipe, complete argv, observed environment, device, np, `files` (binary, model, prompt and their SHA-256), mapped ggml file hashes, grant `{id, regions, stopfile}`, request count, request-payload SHA-256 values in index order, VRAM ceiling, device-specific `kfd_vram_file`, absolute `device_vram_path` and `watch_result_path`. The watcher path must be under the enrolled capture root. `M4_PLAN_CELL` selects a cell; the selector itself supplies no trust. The plan must be sealed independently before first use. Values are not filled by this source.

The entry checks the live grant and inputs before execution, the watcher monitors grant bytes, STOP, HOLD, deadline and owner/guardian liveness while containing children, and the runner captures native requests plus samples inside the batch. The writer rechecks the live grant and creates a unique V2 capture; strict projection waits for the watcher's successful post-drain receipt and replays raw throughput. Failed or interrupted native artifacts remain evidence, not successful measurements. `m4_gpu_speed_v2.py` is a prospective reader only; it is not registered in production.

The 38 model-free tests include the actual launcher under the real cgroup guardian with `--help` and interrupted by STOP while its native input is blocked. The actual `run_cell` and V2 writer were also exercised end-to-end against a fake HTTP server and explicitly mocked KFD, maps and grant boundaries, including retained 503 partial output and fail-closed projection. These simulated controls are not GPU evidence. It is not a model/GPU run, actual admitted measurement, quality gate or planning-context canary. The GPU sweep still needs a reviewed binding, same-entry fake-server/cutoff qualification including partial capture, resource receipt and actual admission before use. Never enable enrollment merely because these tests pass.

Fixture runs use a separate code-owned `DRYRUN_*` enrollment selected only by `FILLER_DRYRUN=1`; its Trust cannot project measurement. A missing fixture binding fails closed and never falls back to the live plan. Fixed fixture grant/STOP paths must be bound independently for the specific rowflow qualification.
