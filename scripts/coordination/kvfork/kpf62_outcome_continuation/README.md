# KPF-62 G3 outcome continuation candidate

`test-only.patch` applies to experimental commit `3ec14227a0e293bfc223c9026ed761ea3bdda9bb`. It adds a bounded segmented greedy outcome generator to the G3 **test executable**, leaving existing `complete` and `finish_reason` fields intact. `--g3-outcome-tokens` remains the total cap; the optional `--g3-outcome-segment-tokens` fixes a segment length before a run, defaults to the total cap and cannot exceed it. Context allocation still uses the total cap.

Each full/reuse arm retains its own decoder state throughout its segments and flushes `outcome_segments.jsonl` at each boundary. Ledger rows carry request ID, arm, segment index, token offset, token IDs and `continue`, `eog`, `length` or `decode_error`. A final row appears in `outcomes.jsonl`; `complete` is true only for EOG. A killed or interrupted process may leave a ledger prefix without a final row: this is incomplete, not a completed answer.

`guard.py` is a separate fail-closed input validator, not a quality scorer: supply the frozen request-ID JSON array, `outcomes.jsonl` and `outcome_segments.jsonl`. It requires exactly one complete EOG result per ID and arm, contiguous segment accounting and matching token sequences; it rejects missing, duplicate, interrupted, truncated and cross-arm records. The separate `scorer-only.patch` integrates the same guard into `scripts/chunk-kv/g3_gate.py` at scorer commit `6c0c017ee72b59ef708f9a32471988c433db3bbd`. Passing `--outcome-segments` validates the paired ledger before any exact or pinned text scorer runs and records the ledger SHA-256 in the result. The flag is explicit opt-in; historical invocations without it preserve the existing interface and output. The scorer and test-executable patches have different bases and must be integrated and reviewed together on the selected candidate before use.

Standalone model-free checks: the new C++ budget unit test covers immediate EOG, multiple continuations, exact-bound EOG, exhaustion, decode interruption, failed ledger writes, invalid budgets and separate full/reuse state; `test_guard.py` covers complete pairs, exhaustion, interruptions, duplicates, cross-arm contamination and token mismatch. The patch applies cleanly in reverse to its source worktree. Full G3 compilation, the actual scoring launch and model execution remain unverified. **No successor launch is authorized by this preparation.**

`joint-source.patch` combines the generator and scorer changes on base `3ec14227a0e293bfc223c9026ed761ea3bdda9bb`, including the required text-scorer/manifest interface from `6c0c017ee72b59ef708f9a32471988c433db3bbd`; unrelated acquisition/corpus changes are excluded. It passed clean-index patch applicability, 13 G3 pytest tests (4 subtests), and the standalone C++ bounded-generation test. These checks are model-free. A full G3 target build, actual scoring-launch integration and any model execution remain unverified. No inference successor is authorized.
