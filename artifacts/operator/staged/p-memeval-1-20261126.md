## P-MEMEVAL-1 — Memory-on vs memory-off long-context recall instruments, Tulving 200ch and BEAM 128K (RATIFIED 2026-11-26)

Admitted by the operator on 2026-11-26 (decision queue item OP-42: "admit both + one window"). This section admits
two instruments for the memory-program M-12 A/B (episodic retrieval on vs off). It does NOT grant the inference window;
that is a separate compute booking. Eval-pool registration of either dataset is a separate decision from this admission
(CJ-GATE precedent).

- **Question**: at a fixed reader, does episodic retrieval (memory-ON) recover the recall the full context buys
  (CEILING), and how far above memory-OFF does it sit, without losing abstention?
- **Common rules (both instruments)**:
  - **Prompt-matched arms.** Every arm carries the identical answer contract and closed-book instruction. The memory
    arm never receives an instruction the memory-off arm lacks. The arm a row ran is proven per row
    (`context_mode_by_prompt` for Tulving, the per-row context mode for BEAM), not inferred from the run name.
  - **Reader pinned per run.** The reader is named by its serving recipe (`recipe_hash`), with the launch argv
    generated, never transcribed, and a ggml linkage PASS. Arms are compared only under one reader recipe.
  - **Context, no truncation rule.** The per-slot context must hold the longest prompt plus its answer budget (BEAM
    100K-split prompts reach 191,456 Qwen3.x tokens, so >= 196,608 per slot). A run that needs a truncation rule
    is a different instrument and is not admitted here. Truncated rows are counted and reported per arm.
  - **One result directory per arm**, with a row-count check per arm after scoring (belief sidecars follow
    `--out-json`; a shared directory overwrites them).
  - **Belief write side.** Each scored arm emits its `belief_measurements.jsonl` beside its own artifact.
- **Instrument T — Tulving 200ch / 100K (M-12a)**:
  - Corpus: variant `Udefault_Sdefault_seed0`, `TULVING_CHAPTERS=200` (resolves to the 196-chapter parquet on disk),
    book identity recorded as `book_sha16`; 686 questions per arm; `score_tulving_run --chapters`, when given, must
    agree with the recorded rows.
  - Arms: memory-OFF (`none`), memory-ON (`retrieved`, trace-store chapter retrieval), CEILING (`full` book).
  - Scorer: the deterministic `score_tulving_run` (epyc-inference-research `scripts/benchmark/`). No LLM judge.
  - **Headline**: five-bin Simple Recall Score **with bin 0 (unanswerable, answer `None`) included**. Per-bin avg F1
    is reported beside it. Chronological Awareness is a diagnostic only until the M-12d tau fix lands.
    Entities/Times/Spaces are reported separately from Event-contents/Full-details.
  - Floor and sanity reference: the authors' shipped 12-arm results (`result_lenient_all_book_200.csv`). A result far
    below that floor is a configuration defect, never a finding.
- **Instrument B — BEAM 128K (M-12b)**:
  - Corpus: BEAM 100K split, 20 conversations x 10 abilities x 2 = 400 questions per arm. Dataset path and sha256 are
    recorded in each arm's `beam_run_receipt.json`. The dataset is staged locally. There is no SSL bypass.
  - Arms: `BEAM_CONTEXT_MODE=full` (BEAM Vanilla, memory-off), `rag` (BEAM `pair_chunk`, naive-memory control) and
    `trace` (FTS5 store + navigation, RRF k=60; the ingest filter is recorded as an experimental parameter).
    Control and test arms use identical chunking.
  - Scorer: `score_beam_run --arm full|rag|trace` over nugget verdicts from `judge_beam_run`, using BEAM's own fold.
    The score is never binarised. A verdict that will not parse is refused and counted, never coerced to 0.0.
  - **Judge** (operator 2026-11-09): judge model != reader model, and the judge is held FIXED across arms and named
    per run. Qwen3.8-27B may judge with the same-family caveat accepted. Every claim records reader family, judge
    family and that they overlap. The fallback in which the reader judges its own answers is BANNED. If the judge
    cannot be served, the judged leg is NOT RUN. Arms are never mixed across judges.
  - **Headline**: abstention is EXCLUDED. instruction_following, preference_following and event_ordering are reported
    separately. The headline is the discriminating-core fold over the remaining abilities. The exact ability list is
    pinned in the run receipt before the first row, from BEAM's original definition.
  - **Admission gate**: a run is admissible only when `admit_beam_runs.py` accepts its artifacts. That covers complete
    counts, source hashes, matched question ids, prompt/template/reader bindings and saved generation settings. All
    eight items of `beam_prerun_checklist.py` must PASS (`cleared`). The three 2026-09-18 runs and the 2026-11-11
    EVL-10 re-judge predate this gate and lack its receipts. They stay observations.
  - Floor and sanity reference: BEAM issue #125 Raw ChromaDB arm (49.0% author fold / 55.7% BEAM fold).
- **Comparisons**: within one instrument, one reader recipe and one judge (B) only. T and B are never pooled.
  Paired by question id. Significance and calibration follow P-AB-1 / P-PAIRED where a verdict is claimed. Otherwise
  the result is DESCRIPTIVE.
- **Scope**: this admits instruments. It sets no routing, promotion, deployment or threshold. Results under it that
  predate 2026-11-26 (M-12a 2026-09-18) may be cited under P-MEMEVAL-1 instrument T only if their artifacts satisfy
  the rules above. Otherwise they stay observations.
- **Claim tuple to carry**: instrument (T|B), arm, reader `recipe_hash`, judge identity and family (B), dataset or
  book sha, research commit, n per arm, truncated count, unparseable-verdict count (B), and the headline fold.
