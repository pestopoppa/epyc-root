DO NOT QUOTE

Two reads in this evidence are artifacts, not measurements

T=32 rungs · every group

All three groups set mixed_metric_basis: true at T=32, because the pair puts a raw_fallback cell against a trimmed one. R1 sets the flag correctly and then declares a winner anyway — so the winner field at T=32 is an artifact. A reader who trusts it without reading the flag gets a wrong provisioning answer.

Every R2 / R4 Pareto peak

Both mix bases and let a non-decision-grade cell define the peak. Worked example from W1: C2-np16 is named peak at 578.6 on raw_fallback, ranked above C2-np8 at 462.8 on trimmed — yet like-for-like, C2-np8 raw is 669.2 and beats it. It wins on no consistent basis.

Nothing is lost. The full per-request ledger (requests.jsonl) is persisted for every run, so a ratified alternative steady-state rule can be applied offline to these exact runs. Deterministic replay applies — no re-measurement is implied.

KNOWN DEFECTS IN THIS EVIDENCE

Recorded rather than smoothed over

  • Era mis-stamp. Every run manifest carries era.cpu_kernel: E6-cpu-kernel, which is the v7 era — these runs executed on v8. The stamp is inherited from frozen pre-registered manifests written before the v8 cutover. It is recoverable: each artifact records attestation.binary_version = 10107 (67a433bf4). No re-measurement follows.

  • T=32 rungs and all R2/R4 peaks are basis-mixed — see above.
