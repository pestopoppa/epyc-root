This is a new measurement profile requiring owner predeclaration; it does not revise the existing CT21 rule, 2352 native records, HOLD, default OFF, or classify a conditional subset as non-inferior. Interface v1 interprets the architect decision envelope. For one-line `D|<answer>`, pass only the answer to the unchanged suite scorer. `D|Approved`, a valid `I|brief:...|to:...`, malformed lines, and native answer parse failures are unobservable; retain every record and report counts by arm and paired transition. Refuse a suite accuracy or non-inferiority metric whenever any required final answer is unobservable. No row is dropped or counted correct; do not transfer the original -3 pp margin to any conditional direct-answer subset. For IB2, payload prefix matching is a separately named diagnostic, not a replacement for the frozen native predicate or verdict.

A prospectively defined *direct-answer-only* task set must be one whose production architect contract actually asks for an immediately observable direct decision; candidate coding tasks in the old set need delegation and cannot be made observable by parsing alone. A dry run must show exactly the complete production-builder rendered prompts, source/model/fixture hashes, matched OFF/ON membership, prospective output root, and no network or model load. New launcher must pass the real T1 same-entry boundary and owner scheduling checks before arming; no fake success or executable launch is asserted here.

Decision package for owner: (1) Full workflow: run investigate and the delegated specialist, capture the specialist result and synthesis, evaluate the final answer; best representation of architect routing, requires more calls, scheduler and explicit failure/time budget. (2) Direct-only diagnostic: fixed tasks that production really answers directly; cheaper and isolates envelope behavior but cannot support a claim about delegated coding or the original CT21 competence gate. Recommendation: use option 1 for a future replacement competence decision; option 2 may characterize the interface after its own predeclaration. Both require a new protocol and new run names; neither changes the old HOLD.
