## Pre-run manifest: minimum binding

The owner must review and freeze one canonical manifest **before** any measurement. Its digest and location must be captured at the original process write boundary, not attached retrospectively. It must bind:

1. Campaign and row identity; exact scope, role/model set, baseline and candidate source commits, current champion/fresh-tip determination and separately verified image manifests, binary and image-local ggml library digests. Verify runtime artifacts against those manifests before execution; path, version string and mtime do not establish content.
2. Producer entry, dispatcher, native runner, adapter and their source identities; canonical schema/version; precise paths of immutable input and retained output. An allowlist and source seals must be independent of the measurement row being checked. Resolve paths and reject traversal, symlink escape and unexpected source changes.
3. Exact per-arm role/model/recipe, treatment, output-token cap, launch arguments and draft/projector inputs; independently attributable best-recipe evidence and its digest. Bind model and auxiliary-file hashes, prompt pool/selection/seed and digest, context, np and planned repetitions. Baseline must be default-off and candidate's reviewed M4 treatment explicit; prohibit hidden environment overrides.
4. Resource and admission contract: actual grant/row identity, exclusive GPU and host placement, reviewed memory/VRAM/time/disk envelope and STOP/HOLD/deadline behavior; record receipts and time boundaries rather than inferring authorization from file names. Re-review old estimates rather than assuming they apply to a successor.
5. Expected output schema, native per-process request and event evidence, process identity and start/stop times, timestamps for the request batch and own-PID KFD/VRAM samples, image-local ggml mapping and verified owned-process cleanup. Preserve incomplete and failed attempts without turning them into successful measurements.

## Writer and projection checks

- The writer must attach the frozen manifest digest and original run coordinates to every native process record at creation. The reader must re-open the authorized manifest and source-bound records, verify all digests and reproduce the native aggregate throughput from request records; reject missing, tampered, conflicting, out-of-scope or unbound data. Do not trust self-reported producer hashes, model hashes, paths, source commits or recipe values alone.
- Verify at least one valid own-process GPU residency sample **inside the request-batch interval** and correlate PID/start identity and device; a sample taken only before or after the batch cannot prove residency during it. The current runner takes a ready sample before `run_prompt_batch` and collects periodically until it returns, but its present acceptance condition only requires a non-empty valid list; a short batch could have no sample inside the batch. Record interval boundaries and reject this case. Validate the reviewed VRAM ceiling and capture read failures, not only positive samples.
- Compare mapped ggml libraries against the independently bound image, not a path supplied solely by the measurement. Require an explicit post-run owned-PID dead check and validate request error/completion status and final controls. One process record is one fresh-server observation; do not treat overlapping operations as independent process repeats.
- Keep the fail-closed prototype disabled until actual native source/record schemas, immutable pre-run bindings, code-owned trust roots and the existing reader/CLI integration have been reviewed together. Unit and mutation controls must show rejections for changed source, prompt/model/image or recipe, wrong arm/treatment, forged paths, missing or out-of-window residency, wrong PID/library, interrupted request and missing cleanup. Model-free fixtures are not measurements or a planning-context canary.

## Remaining work before a row

Re-derive current scope, recut on the current champion under the fresh-tip rule, bind current source/images/recipes and a defensible resource estimate, implement a current safe launcher and durable cleanup ownership, then review writer/reader and run the permitted actual-entry and planning-context checks. Only a complete, source-bound row with a truthful result path and decision rule may be published; the keeper alone qualifies, grants and runs it. A separate promotion/fold gate remains open.
