# KPF18 R15 successor: 56 GiB planning forecast — proposed, not armed

The pre-existing original control source, scientific thresholds, X1/C1/X2/C2/C3 order, prompts, binary, original receipts, and 64 GiB own-output boundary remain unchanged. This proposal changes only the row `est_output_GiB` from 64 to 56 and adds a private continuous owner-only resource watcher at the launcher. It is not approved, armed, booked or run.

Budget derivation from `successor/controller.py`: three controls allow up to three construction attempts each, each attempt may save foreign2 and (after a valid cancellation) foreign3. R15's 32,000-token foreign2 raw save is 1,271,902,768 bytes; conservatively allocate that full size for both saves: 3×3×2×1,271,902,768 = 22,894,249,824 bytes (21.32 GiB). There are five trial views; budget 3 GiB for each view plus 3 GiB for the corresponding original server log, 30 GiB. This totals 51.32 GiB; 4.68 GiB remains to 56 for request/response JSON, metadata, auxiliary logs and overshoot. It is a reasonable planning estimate, not a mathematical upper bound: successful C1 has never been observed, failed constructions can emit before the view guard, and the 3 GiB guard is checked only when reading the trial view, not continuously against the server log. The prior 64 GiB estimate and output boundary also are not continuous guarantees.

`resource-watch.py` is a private adaptation of the accepted KPF62 watcher: 176 GiB sampled aggregate RSS across only captured owned descendants, 150 GiB available floor, STOP/HOLD and grant-derived deadline; birth-identity checks, SIGTERM/SIGKILL only on captured descendants, verified drain. The original driver/server HWM check remains in source. Native address-space limits remain inherited/unlimited as before; no ulimit is imposed. A sampled breach produces `RESOURCE_ABORT` / `INCONCLUSIVE`, never a scientific verdict, with raw artifacts retained. Sampling and unrelated concurrent writers mean no guarantee that a 150 GiB hard floor can never be crossed between samples. Even an unbounded burst can exhaust the margin; abort is mitigation, not an output cap. The watcher checks the floor, HOLD/STOP and deadline before launching the child too.

`launch.sh` is a source-only private successor wrapper which checks the original source guard and additionally binds its watcher to `SOURCE.sha256` and a MAIN approval seal; it runs the original `job.sh` under the watcher. `ROW-56.md` is a proposed row and has no real PID/armed state. Before use, MAIN must approve this exact design and source, owner must reissue the correct row and complete fresh same-entry preflight and real T1 at actual free space; no canonical row or enrollment has been changed here. A real T1 may still refuse for disk; the estimated output changes no floor or inference boundary. Same-source pre-model proof, evidence of correct GPU linkage/residency and captured-process ownership remain mandatory.

The private `precondition.sh` addresses the proposed 56-row file and rechecks this source seal, rather than falling back to the old 64-row. `same-entry.sh` is prepared for a fresh nonce-bound PF; its new proof destination is `$BASE/forecast56-dryrun/` within the original scratch root and is required to be absent. It never overwrites the original 64-GiB proof, and source scripts do not manufacture a proof or MAIN approval. The gate requires absolute paths in `SOURCE.sha256`; its own `checked_manifest` verified the proposed file. The actual same-entry PF is not yet run. It will need the appropriate actual claim, reviewer approval seal, and sufficient disk, and its newly created nonce/proof paths must be coordinated with the owner.
