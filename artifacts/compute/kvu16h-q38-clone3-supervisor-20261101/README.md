# Q38 atomic child creation primitive — source draft only

`atomic_spawn.c` uses Linux `clone3` with `CLONE_PIDFD | CLONE_INTO_CGROUP` so the kernel creates the child directly in a pre-opened cgroup and returns its pidfd as part of the same system call. Unsupported kernels, invalid input and syscall failures refuse the spawn. It never signals a PID. No process or build ran; the source has not been compiled, independently reviewed, or tested against the actual host/container kernel, seccomp, cgroup delegation or privileges. It is not a supervisor and must not be scheduled.

The caller must first prove exclusive custody of the cgroup and its descriptor, bind source, executable, loaded libraries and recipe, own child reaping exclusively, detect exec failure, and handle post-spawn errors without losing the returned pidfd. On stop, use a verified cgroup-owned descendant kill/drain protocol and confirm `cgroup.events` reports `populated 0` before a cleanup receipt; pidfd-only termination is insufficient for descendants. Ensure the cgroup cannot be reused while its handle is active. Integrate STOP, durable no-redraw journal, transport and actual keeper qualification. Those pieces are absent. A successful syscall alone proves neither server readiness nor valid cleanup.

Important API edge: if the kernel reports success but fails its documented pidfd invariant, this draft returns the distinct `Q38_SPAWN_CHILD_UNVERIFIED` result with `out` containing the child PID and negative fd; cleanup is unverified. Validation and syscall failures return `Q38_SPAWN_NO_CHILD` after resetting a supplied output structure. A production integration must explicitly retain the unverified-child state and never assert cleanup. A proper test suite must exercise syscall refusal, successful atomic capture, exec failure, exclusive reaping, descendants and real cgroup drain in an authorized isolated environment before deployment.

The source-level checks in `test_source.py` only verify the declared result branches and output initialization; they do not compile C, execute `clone3`, prove its ABI, or establish process cleanup.

A prospective CLOEXEC nonblocking error pipe now reports child setup or `execve` errno, and child-side `close_range(..., CLOSE_RANGE_CLOEXEC)` marks inherited non-standard descriptors for closure on successful exec; unsupported `close_range` refuses exec. Parent owns the returned pipe even for unverified-child status. A complete error record indicates failure; EOF alone is ambiguous because a killed child or failed write can also close the pipe. The future supervisor must perform bounded reads, close all returned descriptors, verify actual executable identity/readiness, and prove exclusive reaping and cgroup drain. This code remains uncompiled and unexecuted; static checks cannot establish Linux ABI, async behavior, descriptor behavior, or host support.

The caller must hold exclusive descriptor-table custody during spawn, provide open standard descriptors 0–2, and provide a cgroup fd at least 3; this draft checks but cannot enforce those conditions against concurrent threads.
