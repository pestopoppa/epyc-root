# VKQ3 tokenizer diagnostic: implementation contract

**Draft only — no runnable launcher, no published row, no measurement.** The full-mode run timed out after 120 seconds in tokenization; the short qualification did not cover that phase. This does not identify the cause or prove any longer timeout will complete. The distinct calibration prompt must not be retried until its exposure/custody audit is complete and its plan permits reuse; the earlier original prompt is exposed and remains no-redraw.

## Independent input and identity

Use a freshly authored, deterministic, synthetic non-conversation input distinct from both enrolled prompts. Commit the generator source, exact parameters, byte length and SHA-256 before scheduling. The input is for tokenizer diagnosis only; its token count and runtime cannot establish the original prompt's token count or response feasibility. Run the same bound `llama-tokenize`, model shard set and relevant ggml libraries as the failed attempt, verifying their content digests and launcher source catalog before each actual run. Record those identities and exact argv. Do not include personal conversation text in results or logs.

## Contract for a row-ready implementation

1. Use a new row ID and private scratch tree, a real keeper-issued grant and whole-host CPU shape. Include a separate dry-run mode with a short distinct synthetic control that emits a native qualification unit without marking full work complete. Dry-run qualification must verify the engine's mode propagation, scratch permissions and child cleanup. Do not copy or reset the prior run directory.
2. The full job launches the captured tokenizer with CPU-only environment and `--stdin --ids --no-escape`; record monotonic start/end and process exit, output size, SHA-256 and validated integer token count. Capture only bounded, sanitized stderr tail in a private file. Do not buffer unlimited stdout/stderr in memory or on disk: drain pipes concurrently with explicit caps, stop the captured child on overflow, and mark the result inconclusive.
3. Enforce grant identity, STOP, signal and deadline throughout. Bound the attempt by the granted deadline minus cleanup margin, rather than guessing a completion time. Record the exact ceiling and stop reason. Launch a single captured child under parent-death containment; terminate and reap that exact child on every exit path and prove cleanup before terminal receipt. Distinguish normal completion, nonzero exit, timeout, cancellation, overflow and failed cleanup. A failed cleanup cannot report a successful measurement.
4. Write atomic private per-attempt result and a valid JSONL unit for both terminal success and bounded failure; include no invented phase timings. If only total wall time can be measured, label it total tokenizer process wall time. Write a separate completion marker only after the result and cleanup receipts are durable. Preserve partial evidence on interruption. Define decision rule before publication: `completed` establishes elapsed time and token count for this synthetic input only; all other outcomes are inconclusive for target feasibility. Qualification events must be excluded from the full verdict.
5. Offline tests must exercise real short-lived fake subprocesses for normal output, oversized output, nonzero exit, timeout, STOP, child termination and reaping, deadline/grant loss, partial writes and mode isolation. Review paths through the actual rowflow/chroot engine before publishing. The worker, launch wrapper, plan, input generator and source identities must be pinned together; publish only after that integration and test evidence exists.

No inference, model loading or tokenizer execution was done in preparing this contract. Do not construe it as a launcher, a validated row, or a substitute for the failed calibration.

## Offline implementation checkpoint

`supervisor.py` is a dependency-injected draft for a **single captured child**. It concurrently drains stdout and stderr into independently capped in-memory buffers, closes stdin, detects stop and elapsed timeout, terminates and reaps the captured child, and reports terminal status. Run `python3 -B artifacts/compute/kvu-vkq3-tokenizer-diagnostic-20261101/test_supervisor.py`; eight tests exercise real short-lived Python subprocesses without loading the model or running inference.

This component is not a launcher or publishable row. It does not bind or check a grant, preserve receipts, verify executable/model/library identities, provide parent-death protection if its own process is abruptly killed, control descendants, implement dry-run/full separation, or supply the diagnostic input. Its caller must supply those features, derive timeout from the live deadline, protect buffered data, and perform integration and signal/forced-kill tests. Output overflow stops the child and is inconclusive; the bounded stderr buffer is a prefix, not a tail. Cleanup is proved only for the directly captured child in the live supervisor path, not an entire process tree.
