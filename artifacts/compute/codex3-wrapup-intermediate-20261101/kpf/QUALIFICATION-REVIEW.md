On a future fully admitted run, it checks actual keeper context and canonical qualifier, requires an all-writer custody provider (currently deliberately `None`), requires a pinned exact eight-thread calibrated full comparator work-unit and feasible window, verifies full 27B and drafter hashes, then starts the instrumented native comparator gate with the original full target argv, unified KV, four slots, eight threads, public prompt and group 0. `kpf18_gate_qual.REVIEW.py` and `active_capture_qual.py` are isolated copies of the actual comparator gate and active slot collector. Only a later actively processing slot sample and a live same-UID/group/birth CPU-advancing captured server can produce the cutoff-event consumed by the real qualifier. The bridge waits for actual STOP/deadline and terminates/reaps only its captured server. The normal job accepts only two self-hashed native records, exact model/draft/context/thread/slot/binary/prompt pins, native HIP mapping and verified server drain. The final nonce-bound proof is written to the keeper-provided proof path, never self-issued as a receipt.

The qualified job and outer launcher remain statically disabled. First-request and normal/cutoff target behavior have not been proven against a real 27B server. The current source is a review artifact, not a valid READY manifest or a deployable qualification.
