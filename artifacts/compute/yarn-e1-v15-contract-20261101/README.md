# E1 v15 entry contracts — private preparation

This directory is **not a launcher, not integrated into `run.py`, and not a READY packet**. It supplies reviewable components for a future candidate; no original candidate file, grant, keeper, job, or engine was modified or run.

`entry_binding.py` checks a request digest supplied by the caller, rejects the retired row ID, fixes the six scientific cells and verifies runner/root, helper, job, launcher and fixture hashes in the source seal. It also requires independently supplied, digest-pinned SHA256SUMS and VERSION attestations for each expected build and checks the actual binary and all four distinct ggml DSOs against both that pinned build manifest and the recipe. These caller-supplied attestation pins must be independently reviewed and bound by the final packet: using hashes copied from an untrusted candidate would be circular and this component does not establish authorization. It does not verify every dependency in SOURCE.sha256, model full bytes, entry script routing, temporal mutation after checking, or the rest of the runtime contract. It does not use mtime as proof. The existing retired request is rejected by ID.

`v15_lifecycle.py` is a pure loop for the six predeclared cells. The injected executor and completion validator must be real, source-bound components; the loop itself never executes a model or writes a result. Dry-run returns partial after one new validated cell without waiting for keeper polling, preventing it from starting a second item between the first output and stop. Production respects existing completion, stop and deadline between cells. The executor must honor stop and drain processes **during** an active cell; the loop cannot prove that. Qualification must point to a genuine native new output with unambiguous result units.

Run `python3 -m unittest -q test_entry_binding.py test_v15_lifecycle.py` (20 offline synthetic-fixture controls). A first test invocation failed because the test accidentally overrode unittest's `run`; this was repaired and the final suite passes. These tests do not establish a usable live job, binary-source provenance, booking, real GPU residency, native cutoff, keeper acceptance, or a scientific result. Calibration of the actual paired 400k/500k high work unit, disk/VRAM budget, approved binary-source binding, complete dependency closure, source-pinned v15 launcher, and active-stop cleanup still require work. The prior `run.py` starts a new session outside legacy qualification and tests stop in the active runner only for legacy cutoff; neither is safe to assume under v15. Its mtime-vs-commit check is not valid source provenance.
