# Q38-T7 isolated-server successor design

This is a design for a new rowflow-owned runner, not a runnable launcher or a result. The historical Q38-T7 snapshot and its guarded draft remain unchanged. The successor must never send a request-level `speculative.n_max: 0` to a drafted server. No server may be started outside an authorized compute row.

## Lifecycle and custody

1. Before allocating a port or sending any request, freeze the exact prompt set, target list, nonce-bearing phase-B prefixes, model and tokenizer identities, source commit and binary/library hashes, generation parameters, and server recipes. Record their hashes in a new run directory. Keep the historical packet and its data immutable. Acquire compute through rowflow; bind each binary to its source/build manifest and check its own ggml linkage.
2. Run one arm per separately launched server, sequentially if simultaneous residency cannot be guaranteed. The drafted server uses the approved DFlash2 recipe. The no-draft server must omit the draft model and draft-specific options, with the same main model and matching non-speculative serving shape. Capture actual argv, executable and library identity, PID plus process birth identity, chosen free port, readiness and server logs separately for each arm. Fail closed if the no-draft server advertises a draft or if identity/recipe cannot be verified. Do not infer a server's state from the port or directory name.
3. Phase A sends identical prompt bodies and generation settings per arm, keyed by prompt ID and arm. It omits request-level speculative overrides entirely. Record raw HTTP responses, token IDs, timings and identity alongside each request; an incomplete pair is unknown, not equality.
4. For each phase-B target and repeat, construct one fixed nonce-bearing prefix and identical payloads before either arm runs. Warm that prefix independently on each server with the same declared warm request; verify a server-reported cached-token count meeting the prospectively specified threshold for each measured cached request. If unavailable or too low, mark that pair invalid; do not silently substitute a prefill-inclusive result. Send the no-draft decode and needle requests only to the no-draft server; send their drafted counterparts only to the drafted server. Warming must be accounted for separately from measured calls. Preserve input hashes and the full native response including `timings.cache_n` for every arm.
5. On cancellation, failed startup or any exception, stop only captured children, drain and verify each by birth identity, record cleanup and mark the run partial. Do not reuse an exposed run directory or claim a decision from partial data. The keeper alone qualifies, arms and runs the successor.

## Implementation and validation still required

- Build a producer and rowflow launcher around this contract; add process identity and free-port handling, captured cleanup, mode-aware distinct qualification control, result/exposure custody and belief write-side enrollment. Use a new identity and predeclare no-redraw behavior before target exposure.
- Offline tests must exercise argv construction, rejection of draft args on the no-draft arm, request routing and absence of `speculative.n_max`, identical input hashes, two independent warmups, missing/insufficient cache count, process death/port reuse, partial outputs and STOP cleanup. Fakes are not evidence of actual residency, inference or cleanup.
- Through the keeper's actual qualification, prove the separate short control, process ownership and cleanup. Only an authorized target run can establish the requested performance/correctness comparison. An independently warmed cache changes the old shared-cache protocol; report it as a prospective successor and do not merge its rates with the historical run.

Phase C requires its own decision on server shape and is not repaired by this A/B design. The broader KVU-16h-runner task also covers P3 and other named runners and remains open.
