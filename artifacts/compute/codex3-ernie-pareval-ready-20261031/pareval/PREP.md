# RVP-C5-6 ParEval 120 x 20 generation prerequisite

Pinned upstream ParEval revision 9e2a9afafa2c9686fdd3310defde0f9a8c3731c1 contains 60 serial and 60 OpenMP C++ prompts; CORPUS.json retains all 120 in upstream order. The original upstream generator defaults to 20 samples per prompt, 0.2 temperature, 0.95 top-p and 1024 output tokens. This packet retains all 2400 samples as individually seeded one-choice requests; this request grouping differs from upstream's n=20 call and is explicitly recorded. Original system/user templates and postprocessing were compared byte-for-byte to the pinned source. Model is a privately launched retained 27B Q8 CPU server; production services are untouched.

HOST normal qualification used the same final launcher and a public 0.6B model for one non-cohort 16-token code request: native response and upstream postprocessing were captured, finish reason length retained, no code quality inferred. A separate native server processing-task STOP returned rc75, partial and drained. Full 27B target and all 2400 original outputs remain unrun. Gaps, failed and previously exposed samples remain UNKNOWN, never silently redrawn.

This is a generation-only prerequisite. It does not assert C5-6 completion, pass@k, efficiency@k, a local sequential baseline, 96-thread speed, or any belief tuple. Later evaluation must contain generated code, use the original native driver, prove live affinity under a real quiet whole-host grant, use the locally measured baseline and 1/2/4/8/16/32/64/96 sweep, and call the existing SC45 collect-time writer. The upstream O0 fixed-problem-size caveat follows every resulting measurement; no llama-bench comparability or historical backfill.
