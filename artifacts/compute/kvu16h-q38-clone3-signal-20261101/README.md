# Q38 clone3 pre-exec signal custody — offline analysis

The uncompiled `../kvu16h-q38-clone3-supervisor-20261101/atomic_spawn.c` does not establish signal safety. The `clone3` child inherits the calling thread's signal mask and process signal dispositions. A caught handler can run between clone and exec, while inherited ignored dispositions can remain ignored across exec; the signal mask also survives exec. A successful pidfd capture or error-pipe EOF proves none of these conditions. `SIGKILL` and `SIGSTOP` cannot be blocked or caught.

Do not invoke this primitive as currently written. A viable design should use a dedicated, separately supervised, single-threaded launcher process with a predeclared signal policy, exclusive control of its descriptor table, and exclusive child reaping. Before cloning, it should block all blockable signals in the launching thread. The child must establish the target's explicitly declared signal dispositions and mask before executing application code, with no inherited application handler able to run during that transition. Any setup error must be carried by the existing error channel and leave custody unresolved until the child is reaped and the exclusively owned cgroup is proven empty. A killed child or pipe EOF remains ambiguous, never exec-success proof. The signal policy must explicitly state which dispositions, including inherited `SIG_IGN`, are retained or reset and what mask the target receives; blindly unblocking all signals changes target semantics.

The parent must restore its own previous mask on every pre- and post-clone path, including failed setup; if restoration fails after child creation, return the captured child identity with an explicit supervisor-error state rather than claiming no child. Handle pending signals, pre-exec signal delivery, exec failure and signal restoration in the parent and child with documented async-signal-safe operations. Avoid relying on a multithreaded process-wide disposition change to be atomic. Capture the launched executable identity and readiness independently of the error pipe. A process supervisor must still own descriptor hygiene, cgroup exclusivity, descendant termination/drain, STOP, and durable cleanup receipts.

This is a design constraint, not a proof or implementation. No source fix was made: safely changing masks and dispositions changes the API and requires a target signal-policy contract, carefully reviewed implementation and host-specific authorized tests. No compiler, `clone3`, process, signal or compute was run. Future validation needs injected signal delivery at every boundary, parent-mask restoration on every return, ignored/caught disposition and target-mask assertions, pre-exec termination, error-pipe failure, exclusive reaping, and actual cgroup descendant drain. Unit fakes and static checks do not establish these properties.
