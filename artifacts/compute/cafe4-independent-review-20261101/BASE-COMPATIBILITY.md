## Behavioral gaps / checks

- Original `rs-rollback.cpp` always uses 99 GPU layers, generates one token per decode, then over-generates `rewind`, discards `rewind + 1` positions, replays the last accepted token and compares only final greedy token sequences. It is not an MTP or batched target-verification harness. It refuses zero rollback but does not validate complete reference lengths or input numerics robustly. Check model loading, tokenization, context and batch allocation, logits pointers, decoder return codes and removal results explicitly.
- The new `--verify-batch d` must actually pass a batch of d draft tokens in one decode, not loop d one-token calls. Supply positions/sequence IDs and per-position logit flags; establish positive counts for tested partial-accept cuts. Record the concrete removal interval and capacity; re-decode the necessary boundary token so the logits refer to the restored state. Compare against a separately created reference context using identical prompt/token positions and record token identity plus per-position logit differences. Batched vs single-token floating-point operations can differ even when rollback works: report token and logit evidence separately and predeclare tolerances/backend rather than silently treating any numerical drift as state corruption.
- Test at least more than one partial-accept cut including a nontrivial rejected suffix; make zero decoded batches, zero removals, absent logits, insufficient ring capacity and missing comparison hard failures. A forced corruption must cause the same independently checked oracle to fail nonzero; it is not enough merely to print a fault message or fail an unrelated setup check. Preserve independent positive and negative outcomes.
- Model choice must exercise recurrent snapshots: report actual `llama_n_rs_seq`, model architecture, backend and seq removal success. A non-recurrent model or a null/disabled snapshot ring cannot validate recurrent rollback. Check `-ngl N` input parsing and actual placement; a CPU binary or requested N does not prove GPU residency.
