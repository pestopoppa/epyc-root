## Finding: full-accept API call is omitted

The r3 comment “Full acceptance: consume sampled + all drafts and choose bonus; no rollback” is true only as **no positions need removal** in the ordinary parallel verify path. Its returned `rollback_attempted=False` and test accepting `rm_ok=False` as PASS incorrectly model **whether the server calls the removal API and handles refusal**. V10 `tools/server/server-context.cpp:4231–4240` always calls `common_context_seq_rm(slot.ctx_tgt, slot.id, slot.prompt.tokens.pos_next(), -1)` after accepting IDs, and repeats for `ctx_dft` if present. `common/common.cpp:1590–1594` invokes `llama_memory_seq_rm` and aborts if it returns false. Thus a correct abstract case must distinguish `seq_rm_called=True` (per present context) from `positions_removed=0` / `rollback_count=0`; the call's failure cannot be modeled as a successful full-accept run. The current test `check_case(5,5,snapshot_capacity=0,rm_ok=False) == PASS` should instead treat an API failure as non-success / UNKNOWN or separately encode a true return for the no-op case. Zero snapshot capacity by itself is not an API failure.

Derivation for standard nonserial, non-exact path: `handle_last_sampled_token` (`server-context.cpp:505–536`) batches sampled at P then `d` drafts P+1..P+d and appends these tokens to prompt. Accepted vector contains `a` accepted drafts plus one sampled/bonus token (`:4153–4155`, `:4229–4237`); server discards original d drafts from prompt then inserts `ids[:-1]`. Therefore removal starts at `P+1+a`. At full acceptance `a=d`, that is `P+d+1`, just beyond the last evaluated batch position `P+d`; no evaluated token lies in range. At partial acceptance `a<d`, this removes d-a draft positions. The recurrent implementation (`src/llama-memory-recurrent.cpp:161–200`) has a bounded snapshot branch only for `p0 <= cell.pos`; a beyond-tail call avoids it, but actual return must still be checked because hybrid or other implementations and API failures exist. `llama_memory_seq_rm(nullptr,...)` returns true (`src/llama-context.cpp:4184–4193`), which is no evidence for a particular real model context.

## Other scope and geometry

Its `keep=accepted` removes `d+1-a` tokens and replays the last retained-input token, while ordinary server's cleanup above removes `d-a` and leaves accepted prefix in memory. The `snapshot_capacity >= d+1-a` guard is consequently for that artificial probe and must not be described as production server's threshold (`n_rollback=d-a`, server :4155–4161). A probe that requires an extra snapshot can refuse a case the server accepts; classify separately, not v10 server parity.
