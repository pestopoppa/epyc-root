## Precise state-fault test

The matrix's state-fault criteria are sound: paired same-image unmodified positive and fault case, independent reference, exact intervention and stage, same replay tokens/positions, and an observed mismatch from that intervention. Tighten it by requiring **native proof the fault was armed once and reached the state source actually consumed**, not just a flag, nonzero exit or a mismatching token. For v10 recurrent memory, `seq_rm` selects `rs_idx` for a bounded removal (`src/llama-memory-recurrent.cpp:192–200`) and `llama_memory_recurrent_context::s_copy()` consumes and resets it before returning a selected row (`:1293–1310`). A diagnostic-only wrong-snapshot-index or bounded selected-state corruption could test sensitivity, but only after the candidate proves the expected and actual selected indices/rows are distinct, valid, represent different relevant state content and were used in the evaluated replay; preserve identifiers and synchronized state/copy evidence. Selectively compare unchanged token IDs, position, batch and ordinary same-shape positive, then independent state/logit output with a predeclared criterion. A hook that never fires, unobservably distinct state, missing raw capture, numerical drift without paired calibration, or setup failure is UNKNOWN. Avoid altering frozen production; a diagnostic candidate is not promotable as a kernel optimization.

The current native proposal's `--fault-inject` changes the replay token (`:249–253`), so its `FAULT_DETECTED` reports observable altered input, not a snapshot-state-specific failure. R3 toy's scalar state mutation (`:54–59`) does hold replay input constant and tests a logical comparator, but its synthetic score exposes state by construction (`:6–9`); it supplies no native state-consumption or sensitivity proof. Distinguish these two negative-control classes in the record.
