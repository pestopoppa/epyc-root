# Crisp Nemotron validation execution profile

The checkpoint supports R0/R3/R6/R13, run with native automatic prompt 101 and forced locale prompt; requested R1 is visible but unavailable as a trained setting. Cache-aware encoding uses the native preset mapping R0=1, R3=0, R6=2, R13=3 and full 30-second-or-shorter canonical input chunks. The 1,437 FLEURS validation inputs are partitioned by manifest index over eight independent three-CPU workers in one granted quarter with a 32 GiB correctness reservation; the minimum useful window is 7,520 s. Native cases have a 7,200 s timeout and the launcher starts no new case inside a 7,220 s window reserve, based on the observed slow cache-aware CPU engineering control. STOP drains workers, preserving exposures, and returns 75. A two-CPU R11 smoke uses two one-CPU workers, each running R13 auto on a diagnostic JFK copy; the full eight-setting campaign is unchanged. This adapter reads the exact same Q8 GGUF as the transcribe runner, uses zero-copy reshape views and consumes combined predictor biases once. `CRISPASR_FC_PW_Q8=0` disables the native optional pointwise requantization so the source weight values are retained. JFK controls matched the transcribe runner's native emitted IDs at all four supported contexts in both auto and forced modes; these are diagnostic observations, not a full-cohort parity verdict. The private adapter retains the previous convolution cache when a chunk is shorter than K−1; the original private prototype dropped it. No test-derived tuning or scoring occurs in this collection.
