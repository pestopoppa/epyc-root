# CH-30b fixed-image shim change: design fragment, not deployable

`shim-change.patch` illustrates only the leak-only export removal in a NEW isolated shim. Do not apply to the shared shim or use as a complete patch: its old comments and the launchers' gl1_guard, metadata, and predeclarations still demand graphs disabled. The HSA affinity export remains required independently.

No inventoried workaround consumer currently proves a fixed image. Old-image, comparative and frozen-v10 jobs retain their current behavior. Retargeting requires a new, explicitly identified candidate whose provenance binds all image bytes (verify SHA256SUMS and provenance, including libggml-hip.so) to source containing folded fix a9c38f8e0 or an independently proven equivalent; verify all launcher-specific features, model, driver and protocol. C4's verified image is not automatically a compatible KPF image.

For a qualified new job: update the shim comments; replace graph-off-required checks with fail-closed proof GGML_CUDA_DISABLE_GRAPHS is absent from actual server /proc/PID/environ, not merely parent environment; retain HSA_OVERRIDE_CPU_AFFINITY_DEBUG=0 and prove actual server setting; revise all run-record labels and never mix with historical graph-off baselines. Replace gl1_guard's graph-off assertion without disabling own-PID VRAM hard guard, own PID cleanup or unrelated checks. Pin library search path, verify ggml linkage and runtime HIP mapped plus during-run KFD VRAM. Apply the original predeclared leak test and its pass threshold before claiming the workaround unnecessary. Tests and inference require the appropriate CPU-region and GPU grant; no inference was run in this inventory. Retargeting is a new protocol/image decision and must not rewrite sealed historical records.
