# P3 v2 / X0 isolated-arm coordinator draft

This is a prospective dependency-injected coordination component, not a runnable benchmark, an installed guard, or a result. `run_pair` launches sequential distinct drafted and no-draft arm handles through an abstract runtime, rejects request-level speculative overrides, warms independently, requires a measured native cache hit and an adapter-verified occupancy witness, and refuses a mismatched identity or pair. It requires `runtime.stop` to return exactly `True` for every returned handle; a false, missing or exceptional cleanup result prevents the next arm and any pair. Eight fake-runtime offline tests exercise routing, matching hashes, occupancy mismatch, refusal and cleanup failure; no compute ran.

The runtime adapter does not exist. It must prove argv and live server identity (including no draft flags on no-draft), own PID/birth and child cleanup even if startup raises, independently recreate P3 neighbor occupancy, enforce equivalent occupancy across arms, freeze input and native receipts, provide STOP/deadline handling and durable no-redraw partial custody, verify binary and linkage and integrate rowflow. X0's nonce-bearing original workloads and P3 slots require different occupancy policies; this generic coordinator's fake `verified` flag is not live evidence. The draft now requires equal canonical JSON occupancy comparison witnesses across arms, but the prospective adapter must define and verify meaningful witnesses for each workload. It does not retain partial results on exceptions, implement a results writer, or qualify a real model. Those are blockers before use or publication. Historical source and scratch runners remain untouched.
