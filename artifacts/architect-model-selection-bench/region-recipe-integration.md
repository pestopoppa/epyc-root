# Region-scoped CPU benchmark recipe: implementation handoff

RECIPE-NUMA-1 in `handoffs/active/architect-model-selection-bench.md` remains open. The change belongs in `epyc-inference-research`, outside this lane. No benchmark or implementation was run here.

At research checkout `99301fa149af86a6f9743d2b0405c9234ba39586`, `scripts/lib/canonical_recipe.py` defines the fixed full-host prefix `taskset -c 0-95 numactl --interleave=all`. `apply_canonical_prefix` prepends that exact prefix, `assert_canonical_cmd` checks it, and `build_canonical_bench_command` calls the wrapper. `scripts/lib/test_canonical_recipe.py` tests the fixed prefix, its order and the `--no-mmap` requirement. A caller cannot request a smaller CPU grant through that API without violating its fixed-prefix contract.

Implement a separate explicit region-scoped recipe in the research repository, rather than silently changing the full-host default. Take the granted physical CPU list as input, validate it against the actual grant and allowed CPU set, preserve `taskset` before `numactl`, emit the intended memory policy explicitly, and make the corresponding assertion validate the same declared scope and policy. Refuse malformed, empty, out-of-grant or inconsistent scope instead of falling back to all cores. Preserve the existing full-host interface and `--no-mmap` checks; expose the new scope through the builder and CLI only where required by their callers. Add tests for full-host compatibility, quarter grants, wrong order, forbidden cores, missing or mismatched memory policy and repeat wrapping. Any launch must still observe the separate grant/admission and measurement requirements.

The intended memory policy needs its workload context declared: the architect handoff reports that `--interleave=all` beat `--membind` on the named single-region LFM/gemma runs, whereas `handoffs/active/numa-placement-defect-20260730.md` describes node-local `--membind=<node>` plus `--no-mmap` for a concurrent quarter fleet. Those observations have different workloads and scopes; do not convert either into a universal rule or relabel the historical results. The benchmark recipe should make its interleaved memory footprint explicit in admission and report actual page placement; a CPU-region grant alone does not establish memory-node exclusivity. Page-cache pressure may defeat intended interleaving even with a correct argv (canonical recipe's placement note). Validate policy during the run before making a placement claim.
