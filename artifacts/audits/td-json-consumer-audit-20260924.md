## 3. Ranked conversion list (call volume × failure cost)

**Prerequisite, ahead of everything: X1.** Fix `llama_server.py:607-616` to forward `response_format`/`json_schema` (and `grammar`, if the server accepts it there) on the chat path. `actors.py` proves llama-server honours it. Until this lands, **any TD-1 adoption on a `/v1`-lane role (`frontdoor`, `worker*`, `architect_critic`) is silently a no-op**, and several conversions below would look like they worked while changing nothing. Zero inference to verify; the DS41 measurement is the evidence.

Then, in order:

1. **R-09 — `repl_executor.py:671` REPL FINAL-schema validation.** Highest failure cost in either repo: one bad brace re-runs the entire orchestration graph from turn 0, twice, then returns the invalid answer anyway. Volume = every REPL task carrying an `output_schema`.
2. **A-01/A-02 — `controller_io.py:739,:776` autopilot action + rationale.** Highest call volume of any site here (one per autopilot iteration, overnight), and the failure path both burns a full re-prompt AND writes a `seed_batch` default action into the journal — corrupting the evidence plane, not just the run.
3. **R-02/R-03 — `chat_delegation_decision.py:107,:423` TOON delegation decision.** A closed set (direct vs investigate × role × mode) parsed by eight stacked regexes with *no failure mode at all*: unparsed architect prose becomes the user-visible answer, and recovery costs a second call to the slowest role in the stack.
4. **J-01/J-03..J-07 — `debug_scorer.py` model-side parse failures.** Volume = every eval row of every suite. The project has already measured this class twice (verbose arm A4 showed **15% false parse-failures vs A1's 0%**; canonical re-score moved gpqa **43.4% → 53.0%**) and adopted the standing rule that a cross-arm parse-failure difference is a scoring bug until proven otherwise. Constraining the judge/answer channel removes the artifact at the source; the exclusion path (J-14) already exists and is simply never reached for model-side failures.
5. **R-05/R-06 — `review_service.py:916,:1030`.** The only site with a *population-scale measured* failure rate: **4.1% parse failure over 1,366 `review_decision` events (56 null decisions)**, plus rubric axes defaulting to `True` on a parse failure. And it is the cheapest fix in the repo — `review_grammar.py` already ships both the json_schema and the GBNF (X4); only the `llm_call(...)` kwarg is missing.

Next tier (6–10), for completeness: A-07 eval_tower rubric judge (silent `heuristic_fallback` into persisted eval results) · R-19 vl_describe (fail-open `success=True`) · K-01/K-02 actor_preparation (one-shot reservation burned) · R-15 edit_transaction (max-context generation discarded) · A-15 task_synthesizer (retry-from-zero, N+1 full generations).
