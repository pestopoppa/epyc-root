# Q38FN CPU KDA exponential census

This is an offline inspection of retained evidence, not a new measurement. The JSON's six top-level keys are the handoff's requested fields. Null means unmeasured, never zero. Both phases lack a direct runtime branch/shape witness and a loop-specific timing, so no measured fraction of decode or prefill wall time is asserted.

The strongest indication is that these loops are bypassed in the profiled graph. The profiled build identity `/mnt/raid0/llm/tmp/q38fn-cpu-perop-profile-20261118-r2/out/BUILD.json` binds source to llama.cpp commit `eee3da838e3c8306a856f2c72c4b04048fded698`; `servers/d1k-L1.argv.json` identifies the Q38FN target and MTP draft, CPU placement, thread and batch settings. At that commit `src/models/qwen4exp.cpp` constructs the recurrent gate with leading dimension 1 and passes it to `build_recurrent_attn`; `src/models/delta-net-base.cpp` passes that gate into the fused op on the relevant paths. `ggml/src/ggml-cpu/ops.cpp` selects KDA when gate dimension 0 equals state width. The retained `servers/d32k-L2.prof.json` reports GATED_DELTA_NET nodes with src0 width 128; it does not report the gate input dimensions. Thus a scalar gate and width 128 would select GDA, not the KDA loop. This is a source/shape inference for the matched graph, not a per-invocation witness. C14 has one KDA exp loop in its implementation; the later retained source at `/mnt/raid0/llm/tmp/ak-q38fn-cpu-gap-census-20261122/out/src/ggml/src/ggml-cpu/ops.cpp` has two control-flow copies. Their execution counts are both unresolved here. Source availability alone does not establish which binary ran a different trace.

The r2 `out/RESULT.json` reports separate decode-window family timings (for example trunk GDN_SSM 5.286 ms/step at 1k and 5.816 ms/step at 32k); this family includes more than the KDA exponentials and cannot establish their self time or an end-to-end saving. The retained `*.prof.json` files aggregate graph evaluations, including mixed graph shapes, and omit gate dimensions. The reported perf symbol percentage is sampled aggregate CPU time, not a branch-specific wall-time bound. Prefill throughput is retained, but a phase-specific KDA branch count and compatible self-time denominator are not. No later-prompt branch witness was located in these artifacts. A directly retained phase-labelled gate dimension and state width for every relevant GDN invocation, or branch counts covering both loops and the full phase, would resolve reachability; if positive, matching loop self-time and phase wall time are required for an Amdahl bound. Even total op time is only a conservative bound under a fixed-work, no-secondary-effects assumption, not a vectorization speed prediction.
