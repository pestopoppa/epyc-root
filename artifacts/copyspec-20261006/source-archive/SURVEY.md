## 2. Stacking: ALREADY SUPPORTED, as a priority chain (not a tree)
- `--spec-type ngram-mod,draft-mtp` (or `ngram-mod,draft-dflash`) builds both impls. common_speculative_init (spec.cpp ~2943-3090) orders ALL ngram impls before ALL draft impls; common_speculative_draft (:3177-3255) runs impls in order and the first non-empty result wins for that sequence; later impls are skipped for that round. impl_last records the winner; accept() gives the winner `is_other=false`, others `true`.
- State safety: MTP accept() ignores is_other and re-seeds pending_h from the target verify rows (spec.cpp:2199), process() runs on every batch for every impl, so MTP stays in sync when ngram wins. ngram-mod accept ignores is_other. DFlash2 not audited for ngram-win rounds (its process() is also called every batch; verify before the GPU run).
- It was production once: wiki/speculative-decoding.md:602-611, 790-793: composed lane ran until 2026-07-31 (a126e43d), now draft-mtp ALONE. Cost recorded ~ -1.6% on ordinary text.
- LIKELY WHY IT NEVER HELPED (key finding, verify with LLAMA_TRACE=1): (a) ngram-mod n_min default 48: draft_one clears any draft shorter than 48 (spec.cpp ~2430), so it fires only after a >=48-token already-seen chain; (b) server-context.cpp:489 caps every draft at n_draft_max = min(.., draft.n_max) = MTP's 4 (DFlash 8), then common_speculative_draft truncates to dp.n_max (:3205). So ngram can only ever hand over 4 tokens, rarely, and when its (long, rare) match diverges it displaced MTP's draft. HyperQwen's +47-55% on copy needs 8-16 wide copy drafts + adaptive width, which this config can never produce.
- Minimal change (no tree): per-impl n_max. (1) in common_speculative_draft use impl-specific cap (ngram: params.ngram_mod.n_max, e.g. 12-16) instead of dp.n_max; (2) server-context.cpp:489 n_draft_max must be max over impls (common_speculative_n_max() :2767 already computes that: use it, then per-impl truncate); (3) set --spec-ngram-mod-n-match 8-12, n-min 4-6 via launch flags only (no code). Gate "ngram when match >= k else MTP/DFlash" is exactly n-min/n-match. Option (2)-(3) cost on CPU: 5-row verify is +42%, 3 rows ~free (REPORT s4), so cap copy width at 8 for CPU first; adaptive (widen only while last ngram round fully accepted) goes in ngram_mod::accept() (:2478, already tracks n_low) -> expose a per-seq n_cur. Edits belong on a llama.cpp-experimental branch (production frozen).
- Step 0 needs NO code: arms via flags only (n-min/n-match/n-max), run with draft cap raised only where the ngram arm needs it (requires change (2); without it the width is stuck at 4/8).
