# RPUCG prospective snapshot review — 2026-11-02

Scope: the unintegrated `rpucg-snapshot.patch`, not a live selector or an MI210 result. The validator checks structural properties and verifies supplied evaluator and recipe bytes against hashes in the same snapshot. It cannot establish that those bytes are the evaluator and recipe actually used, that the candidate list is complete, or that the caller captured the record before selection. Those facts require an authenticated producer and an independent, immutable execution receipt; a digest supplied alongside arbitrary bytes proves integrity against that digest, not provenance. Until those bindings exist, do not call an admitted snapshot a governed comparison.

A focused inspection also constructed the existing synthetic fixture with `visit_counts={"c": 1}` and `total_expansions=0`; the current validator accepted it. Whether those values are inconsistent depends on the pinned upstream policy's exact initialization and update semantics. Before imposing an arithmetic rule, derive the state transition and initialization from the pinned SimpleTES source and add controls for legitimate initial states as well as impossible states. The existing synthetic tests do not establish this invariant.

The next useful implementation step is to bind the prospective snapshot producer to the actual evaluator invocation and selection boundary, preserve the complete eligible pool and pre-selection policy state, and replay both selectors over that same sealed record. A synthetic fixture remains a software control, not the requested A/B. The existing handoff's nonpromotable and no-counterfactual-quality limits remain in force.
