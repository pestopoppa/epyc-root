## Contract

A production READY manifest is `epyc.ready.v2`, with mandatory `workload_kind=llm|speech|command`, predeclared `qualification.receipt`, source/policy/engine/job/fixture hashes, exact execution namespace tools/interpreter/root/cwd/environment fingerprint, and a declared feasibility basis. LLM keeps strict total/per-slot/parallel context and exact source-bound longest rendered prompt token count. `qualification-same-recipe` may use a two-thread fixture rate only when production also uses two threads; other LLM thread counts need pinned calibrated production token-rate evidence. Speech uses pinned audio/source/PCM identity, seconds, sample rate, decoding mode, right context, batch, and threads, with a production RTF (wall seconds/audio seconds) calibrated to matching role/batch/threads; it has no token/context fields. Command work uses declared work units and either same-two-thread or pinned production rate evidence. The keeper issues a one-use nonce only from its own process lineage. It executes the normal launcher entry with nonce-bound synthetic grant/results; model-free test receipts are `epyc.qual.fixture.v1` and never grant production.

CPU qualification uses an admitted R11 two-SMT pair, its matching family mutex, live grant/timing mask checks, OMP=1, and a mapping-only placement check. It does not claim a CPU quarter through region-lock. GPU target requests additionally run under an actual `region-lock --gpu-quiet exclusive` hold; the qualifier observes the native region-lock ancestor/tag. The canonical engine runs its normal job command for fixture normal and active cutoff, requiring a native result writer and completion predicate. Production cutoff supplies a valid logical FILLER_END/DEADLINE for reserve checks, waits for a live child’s first native event, then triggers an isolated STOP; the worker must exit75 with partial/UNKNOWN and drain the named child. A pre-work rc75 fails. The physical qualifier watchdog remains 300/600 seconds. The issuer/receipt binds source/helper/engine and raw proof hashes. At actual grant time, **both** quarter and GPU writers call the patched common `grant_ok.sh`, which rechecks the receipt, namespace, conflicts, and `free − estimated output − 2 GiB ≥ 150 GiB` before any `.grant` write. Low disk yields retryable `READY-WAIT-DISK`; the parked row is excluded from runnable READY and science counts. An ID with `.ended` cannot be reused. The v8 keeper records run-failed alerts and trips a per-owner breaker on three new failures in 24 hours; a fresh keeper qualification releases it without changing the bound manifest.

New FILED receipts use `filed_verdict.schema.json` outcome classes, phase, compute-burned, and family A–I. The v4 scoreboard credits only structured filed science/diagnostic verdicts backed by native rc0/75 and debits exact-joined structured or legacy FAILED-RUN to the same owner. Daily targets are unset unless the owner approves `science-quota.json`; old READY rate numbers are not inherited. `VALIDATOR-FAILED` retains native output for validate-only replay. This is filing/coordination classification, not a new measurement grade or amendment of the human-owned trust boundary.
