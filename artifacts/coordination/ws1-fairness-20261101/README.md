# WS-1 file-cap fairness follow-up

`red.log` reproduces the missing tail notice with three actual worker-written journals, a handled prefix, an existing notice, a cap of one, and four isolated drains. `green.log` covers the corrected drain path and existing regressions. The fairness test now additionally forces migration of an original-format notified receipt and a fresh handled disposition while the cap is one.

The scanner skips a validated resolved receipt before charging the unresolved-journal budget. A receipt distinguishes `handled` (an explicit terminal coordinator disposition observed) from `notified` (notice flushed first). Both bind to the validated source file identity; a changed source is revalidated, and malformed, stale, moving, foreign or unsafe sources remain unknown. Only explicit `done`, `declined`, `handed-off` or `superseded` dispositions establish handled state for this backstop; triage accepts a broader set of substantive replies. Original-format notices migrate only after validation. A stale migrated or cached receipt does not consume the unresolved budget, but contributes to unknown coverage. `reconcile` returns bounded coverage metadata including unknown and truncated flags, without recurring warning messages or claiming that a capped pass was complete. Directory traversal still costs O(history), and a prefix of unresolved unknown journals can exhaust a pass; no persistent sequence watermark is introduced.
