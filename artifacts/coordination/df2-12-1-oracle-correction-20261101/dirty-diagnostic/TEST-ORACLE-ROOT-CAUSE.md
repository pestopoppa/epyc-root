## Exact test oracle bug

`tests/test-recurrent-state-rollback.cpp` SHA `b200438e63d75b051782b4f2face659d1fb62c4b7da45d2266e2096abe22d3e3`, frozen source `ffc1bac82eeca6f9099e1ccd9ba49703c460a115`:

1. `ckpt` saves the target sequence after a three-token rollback, then `replay_and_compare("full")` reloads it into fresh `ctx_dst`. The lambda assigns `logits_src_replay[i]` from `ctx_src` at each replay position.
2. The test rolls back again, loads `ckpt_partial`, and calls **the same** `replay_and_compare("partial")`. The lambda unconditionally overwrites `logits_src_replay[i]` with partial-stage logits.
3. It loads the original **full** `ckpt` into `ctx_dirty` and compares dirty replay to the now overwritten **partial** reference. On the 0.8B model, full first logit is `8.13747`, partial first logit is `6.07728`, exactly the values in the frozen failure (`6.07728 != 8.13747`). Thus this assertion compares different checkpoint arms.

The `test-oracle-full.cpp` diagnostic keeps the full and partial pairwise comparisons unchanged, stores `logits_src_replay` only for the `full` stage, and prints both first-logit values. It linked the same frozen production `libllama`/ggml DSOs, used the same on-disk qwen35 Q8 model SHA `0ad885ffd4bb022fc4f0d33a3308fa108ef8613159d3b3a67e23abca056b7a6c`, and ran under standing R11 on SMT 128-129 with OMP1, 8 GiB/300 s caps, exact captured PID/birth/PGID drain. `ORACLE-FULL-RECEIPT.json` records native rc0, success marker `recurrent rollback checkpoint restored successfully`, 4.925 s, 1.53 GiB peak group RSS, full runtime library maps/hashes, and the raw log (`ORACLE-FULL-RAW.log`). Source SHA `3dab7a69a256b6c75066155a9bb3f131baab541feaed2acbdb9f2332afcdc6ea`, binary SHA `8564c0b7cd9ec5544515dc891a7bda8d22f0d386e65109ac9bdbe7fd896be06f`.

Two other diagnostics constrain the alternative: sequence 0 preclear before restoring the full checkpoint still produced the same original mismatch; a new **fresh** context loaded from the full checkpoint produced `8.13747`, and its serialized sequence state was byte-identical (20,275,964 bytes) to the dirty destination after full checkpoint load. These are test-only observations, not production-role equivalence checks. The root cause above is directly established by test source and the paired native output, independent of those extra probes.

It does not change a kernel, the rollback algorithm, tolerance, test model, or earlier pairwise comparisons.
