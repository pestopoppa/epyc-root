# AK-SHORT-ROW-CENSUS

Offline census of retained kernel dispatch windows; no inference, profiler, or GPU work was performed. The JSON is keyed by model and MMVQ `ncols` width. Each width-1 array has two records: C14 decode first, C18 speculative window second. Counts are dispatches in the entire retained window, not calls per token or a projection to the current serving graph. Widths 2–4 have unresolved cells: a complete width-specific graph and dispatch witness was not located. Null dimensions mean the kernel stream did not retain those runtime arguments. They are not zero. No model-wide zero or proposal closure is supported.

Method: read the gzip CSV records and count names beginning `void mul_mat_vec_q<` with template parameters `(ggml_type)8, 1, true, true`. In C14 source `ggml/src/ggml-cuda/mmvq.cu:1125`, those parameters are quant type, `ncols_dst`, `has_fusion`, `small_k`; type 8 is Q8_0. The remaining template arguments in every matched name are `0, false, false, true`. This counts actual launches of the fused small-K specialization, including all events in each retained window. `has_fusion` also covers bias or scale without a gate; the trace does not record the gate pointer, so these counts are upper bounds for calls that actually read gate weights and cannot alone establish hits for the split-gate optimization. A graph replay's individual kernel events are counted as recorded, without assuming a number of tokens or unique graph nodes. Kernel names do not contain runtime K or output rows, and these files lack a graph-to-dispatch mapping sufficient to recover them. The C18 27B zero is limited to that window; it does not contradict the C14 decode hits.
