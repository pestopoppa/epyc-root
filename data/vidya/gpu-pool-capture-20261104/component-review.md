# SC18 prospective GPU pool capture component

The standalone GPU-pool wiring row is declined/merged into SC18. This component advances the existing SC18 family only; it does not revive that row or close SC18.

New lane files:
- scripts/vidya/adapters/gpu_pool_native.py
- tests/vidya/test_gpu_pool_native.py

The adapter is deliberately unregistered until the owner integrates the future native writers. It captures a begin request before invocation, preserving exact candidate source/artifacts/shim identity and UNKNOWN dirty/source-recreation limits. write_capture writes a fresh, no-replace fsynced producer record. project/read_capture verifies envelope digest, request/native identity and token, immutable captured producer source hash, counts partition, op/seed versus argv, raw log hash, exact ARGV header and log-derived supported/unsupported/failed counts. It preserves raw native run (including samples), complete native context and source limitations. Native old objects and the old attention bare array emit no claims. It emits only native supported-pass counts through existing ClaimTuple and shared grade (Judged/T0, no protocol/reps claim). Scope is op/run only. It invents no model/backend/device scope and makes no independent-oracle or whole-family correctness assertion.

Three precise future native-writer patches and patched candidate files are in this directory. Source-pins.json identifies exact original scripts from research worktree vb-sl2-steps-r1-code/data/gpu-pool: matmul run-v1.py, attention run-v3.py, elementwise run-v3.py. Original writers remain untouched. Future patched writers require explicit fresh GPU_POOL_CAPTURE_ROW_ID, GPU_POOL_CAPTURE_OUT and EPYC_VIDYA_ROOT; they create a fresh output directory, bind begin before native launches, and capture each terminal result before native correctness assertions. Existing failed/unsupported cases remain explicit, raw logs and in-window KFD/VRAM/maps samples are retained. Attention's separate pre-run provenance and array result are combined at the native write side, with original argv/seed/log; no read-side history conversion exists.

Patched candidates are integration material, not ready compute rows: an owner must prepare current source/artifacts/grant/supervisor paths and fresh row IDs, retaining native family v1 contract. They still name the original pinned candidate build and source UNKNOWNs; nothing asserts it is current production or a clean champion. No GPU work, publication, grant, registry/README/handoff/index modification or commit occurred. New code was isolated to new lane files. GitNexus could not resolve the new module in the unindexed lane; no existing symbol or caller was modified.
